二、从 GPT-3 到 LLaMA-3：四个关键设计改变

在看具体计算之前，先弄清楚 LLaMA-3 和 GPT-3 的核心区别在哪里。

组件 GPT-3（旧设计） LLaMA-3 8B（新设计） 改变的动机
归一化 Pre-LayerNorm Pre-RMSNorm RMSNorm 省去均值计算，理论上更简单，实验中通常能保持相近质量（不是对所有规模、任务都成立的定律）
注意力头 MHA（96Q / 96KV） GQA（32Q / 8KV） 相比"同宽度假想 MHA 版本"（32Q/32KV），KV Cache 显存降为 1/4（不是相对 GPT-3 实际的 96 头/12288 维配置）
位置编码 绝对位置 Embedding（加法） RoPE（旋转乘法） 天然表达相对位置，长上下文外推更好

Transformer 解码器架构总览

先追踪 1 个 token，感受张量形状；最后乘以批量感受总规模。

第一步：Embedding 查表

词表矩阵的形状：

$$E \text{ 的形状} = [128256,\ 4096] \quad \text{参数量} = 128256 \times 4096 = \textbf{5.25 亿}$$

假设句子 "猫追鱼"，分词后得到 3 个 token（实际 tokenizer 可能不同，此处为示意）：

$$x_1 = \text{猫},\quad x_2 = \text{追},\quad x_3 = \text{鱼}$$

取出 "猫" 对应的行：

$$x_\text{猫} \text{ 的形状} = [1,\ 4096]$$

重要：LLaMA-3 不在 Embedding 层加位置信息。

GPT-3 会在这一步把位置 Embedding 叠加到词 Embedding 上（$x_0 = \text{Emb} + \text{PosEmb}$）。LLaMA-3 没有独立的位置 Embedding 表，位置信息通过后面的 RoPE 旋转进 Q 和 K，不改变这里的 $x_\text{猫}$。

第二步：Pre-RMSNorm

形状不变：$[1,\ 4096] \rightarrow [1,\ 4096]$

LLaMA-3 在每个 Block 的注意力和 FFN 之前各做一次 RMSNorm（Pre-Norm）。GPT-3 同样使用 Pre-Norm 顺序（Pre-LayerNorm），区别在于 LLaMA-3 把 LayerNorm 换成了计算更轻量的 RMSNorm。

小知识点：为什么用 Pre-Norm 而不是 Post-Norm？

Post-Norm 在残差连接之后才归一化：

$$y = \text{Norm}(x + F(x))$$

Pre-Norm 在进入 $F$ 之前先归一化：

$$y = x + F(\text{Norm}(x))$$

两者都有 $x+(\cdot)$ 这个残差相加的形式，区别不在于"是否直接相加两个向量"，而在于 Norm 的雅可比矩阵是否包住了恒等分支：

  • Pre-Norm 的雅可比是 $\dfrac{\partial y}{\partial x}=I+\dfrac{\partial F}{\partial\text{Norm}(x)}\dfrac{\partial\text{Norm}(x)}{\partial x}$——恒等项 $I$ 独立存在，不经过 Norm 的雅可比，残差路径提供了一条传递系数恒为 1 的直接梯度通道。
  • Post-Norm 的雅可比是 $\dfrac{\partial y}{\partial x}=J_\text{Norm}\cdot\left(I+\dfrac{\partial F}{\partial x}\right)$——$\text{Norm}$ 的雅可比 $J_\text{Norm}$ 乘在整个括号外面，恒等分支也逃不出这次归一化的缩放/耦合，深层网络里 $J_\text{Norm}$ 逐层连乘，不再有一条"绕开 Norm"的恒等路径，这是 Post-Norm 深层训练更容易不稳定（exploding/vanishing gradients）的一个主要机制——但深层训练的稳定性还受初始化方式、残差分支的数值尺度、学习率、优化器选择等多个因素共同影响，这里说的是"主要机制之一"，不是唯一原因。

需要注意：即便是 Pre-Norm，总梯度也是恒等分支和变换分支两部分之和，这条直接通道保证的是"存在一条不衰减的路径"，不是"梯度绝对无阻碍、训练必然稳定"这种数学保证——如果变换分支传回的梯度和恒等分支方向相反，两者仍可能相互抵消。Pre-Norm 的代价是归一化的正则化效果略弱一些，但工程上训练稳定性通常更重要。

一句话：Pre-Norm 让梯度有一条"高速公路"（残差路径）直达输入，深层训练不容易崩。

LLaMA-3 vs GPT-3 归一化的真正区别：两者都用 Pre-Norm 顺序（先 Norm，再做注意力/FFN），区别不在于 Pre vs Post，而在于 Norm 的类型——GPT-3 用 LayerNorm（含均值计算），LLaMA-3 用 RMSNorm（去掉均值，只保留 RMS 缩放）。

小知识点：RMSNorm 和 LayerNorm 到底差在哪里？

LayerNorm 需要：

  1. 计算均值 $\mu = \frac{1}{d}\sum_i x_i$
  2. 计算方差 $\sigma^2 = \frac{1}{d}\sum_i (x_i - \mu)^2$
  3. 标准化：$\hat{x}_i = (x_i - \mu)/\sqrt{\sigma^2 + \epsilon}$
  4. 缩放和平移：$y_i = \gamma_i \hat{x}_i + \beta_i$

RMSNorm 省掉了均值计算和平移参数 $\beta$：

$$\text{RMS}(x) = \sqrt{\frac{1}{d}\sum_{i=1}^{d} x_i^2 + \epsilon}$$

$$y_i = \frac{x_i}{\text{RMS}(x)} \cdot w_i$$

其中 $d = 4096$，$w$ 是可训练缩放参数，形状 $[4096]$。

RMSNorm 原论文（Zhang & Sennrich, 2019）等实验发现，去掉"减均值"这一步后模型质量下降极少，同时 RMSNorm 需要的统计量更少（只需要 $\sum x_i^2$，不需要先算均值再算方差），理论上计算和访存都更简单。需要说明：具体能省多少、是"一遍扫描"还是"两遍扫描"，实际取决于 kernel 实现——LayerNorm 完全可以用单遍融合 kernel（比如同时累计 $\sum x$ 和 $\sum x^2$，或用 Welford 算法）算出均值和方差，不一定要分两遍读数据；更稳妥的说法是"RMSNorm 需要的统计量更少、理论上更简单"，不是所有实现都固定是"一遍对两遍"这么绝对的差距。

一句话：RMSNorm = LayerNorm 去掉了"减均值"和"加偏置"，只保留"按均方根缩放"，理论上更简单；实验中通常能保持相近质量，但这是工程经验趋势，不是对所有规模、训练设置和任务都成立的定律。

第三步：GQA 注意力——四次权重投影（完整 attention 另外还有 $QK^\top$、$\alpha V$ 两次矩阵乘法）

GQA（Grouped Query Attention，分组查询注意力）是 LLaMA-3 相较于 GPT-3 在注意力层最大的结构差异。

生成 Q、K、V：形状不对称

Q 投影（32 个 Query head）：

$$Q = x \cdot W_Q \quad [1,\ 4096] \times [4096,\ 4096] \rightarrow [1,\ 4096]$$

切分为 32 个 Query head，每头 128 维：

$$[1,\ 4096] \rightarrow 32 \text{ 个头，每头} [1,\ 128]$$

K 投影（只有 8 个 KV head）：

$$K = x \cdot W_K \quad [1,\ 4096] \times [4096,\ 1024] \rightarrow [1,\ 1024]$$

切分为 8 个 KV head，每头 128 维：

$$[1,\ 1024] \rightarrow 8 \text{ 个头，每头} [1,\ 128]$$

V 投影（同样 8 个 KV head）：

$$V = x \cdot W_V \quad [1,\ 4096] \times [4096,\ 1024] \rightarrow [1,\ 1024]$$

$$[1,\ 1024] \rightarrow 8 \text{ 个头，每头} [1,\ 128]$$

形状一览：

矩阵 $W$ 形状 参数量 输出维度
$W_Q$ $[4096,\ 4096]$ 1677 万 $[1,\ 4096]$
$W_K$ $[4096,\ 1024]$ 419 万 $[1,\ 1024]$
$W_V$ $[4096,\ 1024]$ 419 万 $[1,\ 1024]$
$W_O$ $[4096,\ 4096]$ 1677 万 $[1,\ 4096]$

小知识点：什么是 GQA？它和 MHA、MQA 有什么区别？

注意力头数量的三种设计：

类型 Q heads K/V heads 代表模型 KV Cache
MHA（多头注意力） $h$ $h$ GPT-3、BERT 最大
MQA（多查询注意力） $h$ 1 PaLM 最小，某些设置下质量可能下降
GQA（分组查询注意力） $h$ $g$（$1 < g < h$） LLaMA-3、Gemma MHA 的 $g/h$

MHA 每个 Q head 有独立的 K 和 V，KV 表达力通常最强，但推理时 KV Cache 最大。

MQA 把所有 Q head 的 K、V 合并成 1 组，KV Cache 最小，但 K/V 表达力下降，一些实验设置下模型质量会受影响——具体影响程度依赖模型规模和任务，不是所有情况下都成立的定律。

GQA 是中间方案：把 $h$ 个 Q head 分成 $g$ 组，每组共享一对 K/V head。LLaMA-3 8B 的分组是 32Q / 8KV，每 4 个 Q head 共享 1 个 KV head：

Q head 0, 1, 2, 3    → 共用 KV head 0
Q head 4, 5, 6, 7    → 共用 KV head 1
...
Q head 28, 29, 30, 31 → 共用 KV head 7

更准确地说：模型只有一个整体的 $W_K$ 和一个整体的 $W_V$，各自一次性输出全部 8 个 KV head 的结果；每组 4 个 Query head 复用的是其中同一个 KV head 的输出，而不是"各自持有一份、又恰好共享"的投影矩阵——共享的是 KV head 生成之后的结果，不是 Q 向量或 attention 权重，同组 Q head 各自有独立的查询方向，只是从同一份 K/V 结果里"查资料"。

小知识点：4:1 的分组比例是怎么来的？

这不是数学推导的最优解，而是 Meta 针对 LLaMA-3 8B 做出的一个具体架构选择。

Ainslie 等人 2023 年的 GQA 论文表明：GQA 作为 MHA 和 MQA 之间的折中方案，可以在接近 MHA 质量的同时取得接近 MQA 的推理效率。但该论文并没有建立"4:1 是所有模型的普适最优分组比例"这样的通用规律——具体多大的分组比例效果最好，取决于模型规模、训练方式和下游任务，论文本身也是在特定实验设置下做的消融，不能直接套用到任意模型上。

LLaMA-3 8B 在 $d_\text{model} = 4096$、$n_q = 32$ 的前提下选了 $n_{kv} = 8$（分组比 4:1），这是 Meta 针对这个具体模型做出的架构选择，效果与效率上是一个合理的平衡点；但"为什么恰好是 4:1"更适合理解为"Meta 的工程选择"，而不是 GQA 论文已经证明过的通用最优比例。

一句话：LLaMA-3 8B 选择 4:1 分组是事实；"4:1 普遍是质量几乎不掉的最优比例"是一个未经普适验证的推广，不能当作定律引用。

容易犯的错误：4 个 token 和 4 个 Query head 是两个完全不同的维度

假设输入是 "猫追鱼"（3 个 token）。

  • "每 4 个 Q head 共享 1 个 KV head" 里的"4"是头的编号，描述注意力头的分组结构，和序列长度（3 个 token）没有关系。
  • 3 个 token 是序列维度：每个 KV head 在每个 token 位置都有一个独立的 K/V 向量。

展开来看，KV head 0 的数据是这样的：

KV head 0：
  位置 1（猫）：k₁,₀ = [1.0, 0.5, ...]   v₁,₀ = [0.3, -0.1, ...]   ← 128 个数
  位置 2（追）：k₂,₀ = [0.6, -0.2, ...]  v₂,₀ = [0.1,  0.8, ...]
  位置 3（鱼）：k₃,₀ = [0.2,  0.4, ...]  v₃,₀ = [0.6,  0.2, ...]

Q head 0、1、2、3 共享的是上面这整组数据，但各自用自己的 Q 向量与这些 K 做点积，得到各自独立的 attention 权重和输出。

"共享 KV"不等于"共享一个向量"——每个序列位置的 K/V 是不同的，共享的是同一个 KV head 的输出结果（这份结果由模型整体唯一的 $W_K,W_V$ 生成，不是每个 Query head 各自拥有一份再共享）。

RoPE：把位置旋转进 Q 和 K

RoPE 只作用在 Q 和 K 上，V 不旋转，形状不变：

$$Q:[1,\ 32,\ 128] \rightarrow Q_{\text{rope}}:[1,\ 32,\ 128]$$ $$K:[1,\ 8,\ 128] \rightarrow K_{\text{rope}}:[1,\ 8,\ 128]$$

具体做法：把每个 head 的 128 维向量按两两一组拆成 64 个平面：

$$(x_0,\ x_1),\ (x_2,\ x_3),\ \ldots,\ (x_{126},\ x_{127})$$

在位置 $p$，第 $i$ 个平面旋转角度 $\theta_{p,i} = p \cdot \theta_{\text{base}}^{-2i/d_\text{head}}$：

$$\begin{bmatrix} x'_{2i} \\ x'_{2i+1} \end{bmatrix} = \begin{bmatrix} \cos\theta_{p,i} & -\sin\theta_{p,i} \\ \sin\theta_{p,i} & \cos\theta_{p,i} \end{bmatrix} \begin{bmatrix} x_{2i} \\ x_{2i+1} \end{bmatrix}$$

小知识点：为什么旋转操作能表达"相对位置"？

核心数学事实：两个经过旋转的向量的点积，只与它们旋转角之差有关，与各自的绝对位置无关。

设 query 在位置 $p$，key 在位置 $s$，旋转矩阵分别是 $R_p$ 和 $R_s$：

$$(R_p q)^\top (R_s k) = q^\top R_p^\top R_s k = q^\top R_{s-p} k$$

最终只剩 $R_{s-p}$，即 $s-p$（相对距离）。注意力得分自动包含位置差信息，不依赖 $p$ 或 $s$ 本身。

直观理解：把两个 token 的位置想象成时钟表盘上的两根指针。无论把整个表盘顺时针转多少度，两根指针的夹角不变。RoPE 在 Q/K 点积这一步显式引入的是相对位移（夹角差），而不是一个独立的绝对位置向量——这不等于说整个模型完全"感知不到绝对位置"：模型仍然可能通过因果掩码边界、序列开头/结尾等上下文线索、每个位置能看到的 token 数量等其他途径，间接获得和绝对位置相关的信息。更准确的说法是"RoPE 这一步注入的是相对位移，不是绝对位置"，而不是笼统地说"整个模型感知不到绝对位置"。

传统绝对位置 Embedding（如 GPT-3）把位置向量加到 token 向量上，位置信息是"叠加"进去的；RoPE 是"旋转"进去的，两者的本质区别在这里。

小知识点：$\theta_\text{base} = 500{,}000$ 是什么意思？为什么这么大？

$\theta_\text{base}$ 控制旋转频率。对第 $i$ 个维度对，旋转速率是 $\theta_\text{base}^{-2i/d}$（这里 $i=0,1,\dots,63$）：

  • 对 $i>0$ 的维度对：$\theta_\text{base}$ 越大，旋转越慢；$\theta_\text{base}$ 越小，旋转越快
  • $i=0$ 是特例：旋转速率恒为 $\theta_\text{base}^0=1$，与 $\theta_\text{base}$ 取值无关——"base 越大旋转越慢"这条规律不适用于 $i=0$ 这个维度对

原始 RoPE 论文（Su et al., 2021）针对 512 上下文用的是 $\theta_\text{base} = 10{,}000$——这是论文的实验配置选择，不是从 512 这个数字用某种公式数学推导出来的。LLaMA-3 的上下文是 8,192——是 512 的 16 倍。

用 $\theta_\text{base}=10{,}000$ 时，第 $i$ 个维度对的周期是 $2\pi\times10{,}000^{2i/128}$；分别令周期等于 512 和 8192 可以解出：周期 $=512$ 时 $i\approx30.6$，周期 $=8192$ 时 $i\approx49.8$。也就是说，在原始 512 上下文的设计里，$i\gtrsim31$ 的维度对周期已经长于 512，训练时这些维度对不会绕完一整圈。但如果直接把同一个 $\theta_\text{base}=10{,}000$ 套用到 LLaMA-3 的 8192 上下文，$i\approx31$ 到 $i\approx49$ 之间的维度对周期短于 8192，就会在新的更长上下文里多绕一整圈以上。

把 $\theta_\text{base}$ 提升到 500,000 后，"不再绕圈"的边界会往回移，但不是所有原先绕圈的维度都能跨过这道边界：同样令周期 $=8192$，用 $\theta_\text{base}=500{,}000$ 解出的边界是 $i\approx35.0$（不是 $i\approx49.8$ 那道旧边界）。也就是说，只有 $i\approx35$ 到 $i\approx49$ 这个子区间，才真正从"在 8192 步内绕圈"变成"不绕圈"；而 $i=31,32,33,34$ 这几个维度对，即使把 base 提到 500,000，周期也只是从几百步拉长到几千步（比如 $i=31$ 从约 544 步拉长到约 3,619 步，$i=34$ 从约 838 步拉长到约 6,695 步），仍然短于 8192，依然会在 8192 步内绕完一整圈——只是绕的圈数变少了，不是彻底消除了绕圈。所以更准确的表述是："提升 base 让 $i\approx35$ 到 $i\approx49$ 这部分维度从绕圈变为不绕圈；$i\approx31$ 到 $34$ 的维度周期同样被拉长，但仍然没有跨过 8192 这道门槛"，不能笼统地说"$i\approx31$ 到 $50$ 的维度都不再绕完整圈"。

需要说明几点，避免推论过强：

  • 这里说的"绕圈""重复"，指的是单个频率分量（某一个 $i$ 对应的二维平面）自身的周期性。RoPE 的位置信息由 64 个不同频率的维度对联合编码，某一个分量绕了一整圈、单独看会重复，不代表整个 128 维的位置旋转状态发生了混叠——其他周期不同的分量仍然可能区分这两个位置（类似钟表的时针、分针、秒针，秒针每 60 秒重复一次，但三根指针联合起来长时间内基本不重复）。所以更准确的说法是"部分频率分量的周期性变得不够理想"，不能不加限定地说成"整个 RoPE 编码发生了混叠"。
  • 把 $\theta_\text{base}$ 从 10,000 提升到 500,000，效果是让中低频维度对的周期变长；但放慢倍数本身按 $50^{i/64}$ 逐维度变化，从 1 倍到约 47 倍不等，不是所有维度"等比例"放大——只能说整体频谱往更长波长的方向移动了，不是均匀缩放，具体哪些维度从"绕圈"变成"不绕圈"要看上面这道边界的移动范围。
  • 这里给出的"为什么要用 500,000"是一个在数学上自洽、合理的机理解释，不代表这就是 Meta 官方证实的选参过程——除非有第一方资料明确说明，否则这仍然是本文的推断，不是已验证的设计记录。

这里再纠正一个常见的误解：放慢≠"覆盖的角度区间变得更丰富"——对固定的 8192 步上下文而言，同一个维度放慢之后，转过的总角度反而更小了。放慢倍数依赖维度对编号 $i$：

$$\frac{\omega_i^{\text{old}}}{\omega_i^{\text{new}}} = \left(\frac{500{,}000}{10{,}000}\right)^{2i/128} = 50^{i/64}$$

  • $i=0$（最高频维度对）：放慢倍数 $=50^0=1$，完全没有变慢——旋转速率恒为 1 rad/token，与 $\theta_\text{base}$ 无关，在 8192 个位置内会转过 $8192/(2\pi)\approx1304$ 整圈。
  • $i=32$（中频）：放慢倍数 $\approx 50^{0.5}\approx7.07$ 倍。
  • $i=63$（最低频维度对）：放慢倍数 $\approx 50^{63/64}\approx47.0$ 倍，接近完整的 50 倍。以 $i=63$ 为例，8192 步内累计转过的总角度：$\theta_\text{base}=10{,}000$ 时约 0.946 rad；提升到 500,000 后反而只剩约 0.020 rad——放慢确实让这个维度在固定的 8192 步内转得更少，不是"覆盖更充分的角度区间"。这个维度真正的作用不是靠自己转出丰富角度，而是把周期拉长到明显超过 8192，保证在整个上下文范围内都不会绕完一圈，提供一个平滑变化、不重复的"慢速指针"。

一句话：$\theta_\text{base} = 500{,}000$ 的一个合理解释是把中频维度对的旋转周期拉长，使其中 $i\approx35$ 到 $i\approx49$ 这部分维度在 8192 步的新上下文里从"绕圈"变为"不绕圈"（$i\approx31$ 到 $34$ 的周期虽然也被拉长，但仍未跨过 8192 这道门槛——这是本文的机理推断，不是已证实的 Meta 官方设计记录）；不是让每个维度"等比例放慢 50 倍"，也不是让旋转角"覆盖更丰富"——对固定上下文长度而言，放慢反而意味着转过的总角度更小；而且"某个分量绕圈"也不等于"整个 RoPE 编码发生混叠"，64 个不同频率的分量是联合起作用的。

第五步：SwiGLU 前馈网络——三次矩阵乘法

GPT-3 的 FFN 是两次矩阵乘法；LLaMA-3 的 SwiGLU FFN 需要三次。

先做第二个 Pre-RMSNorm（形状不变），然后走两条并行的上投影路径：

Gate 投影：

$$[1,\ 4096] \cdot W_{\text{gate}}[4096,\ 14336] \rightarrow [1,\ 14336]$$

再过 SiLU 激活函数：

$$\text{SiLU}(G) = G \cdot \sigma(G) \quad \text{形状不变} [1,\ 14336]$$

SiLU 不是一个 0～1 有界的开关：输入趋于 $-\infty$ 时输出趋于 0（接近"关门"），但输入在中等负值（约 $-1.28$ 附近）时输出会略微为负（约 $-0.28$），输入是大正数时输出近似等于输入本身、可以远大于 1（没有上界）。更准确的说法是"连续可微、输入越大输出越接近直通、输入越负输出越接近 0（但不严格单调趋零，中间有个小负值区间）"，不是简单的"关门/全开"二值开关。

Up 投影：

$$[1,\ 4096] \cdot W_{\text{up}}[4096,\ 14336] \rightarrow [1,\ 14336]$$

逐元素相乘（门控）：

$$M = \text{SiLU}(G) \odot U \quad [1,\ 14336]$$

Down 投影（降维）：

$$[1,\ 14336] \cdot W_{\text{down}}[14336,\ 4096] \rightarrow [1,\ 4096]$$

小知识点：为什么 SwiGLU 需要两条上投影路径（gate 和 up）？

这里为了方便和 LLaMA-3 直接对比，假设一个和 LLaMA-3 同宽度（$d_\text{model}=4096$）的"GPT-3 式"GELU FFN 结构（GPT-3 175B 实际的 $d_\text{model}=12288$，真实的 GELU FFN 是 $12288\to49152\to12288$，本文四、五节的横向对比表用的就是这组真实数字；这里的 4096 版本只是同宽度示意结构，不是 GPT-3 175B 的实际维度）：

$$x \xrightarrow{W_1\ [4096 \to 16384]} [1,\ 16384] \xrightarrow{\text{GELU}} [1,\ 16384] \xrightarrow{W_2} [1,\ 4096]$$

只有一条路：升维 → 激活 → 降维。GELU 作用在所有 16384 个特征上（$4 \times d_\text{model} = 4 \times 4096$），每个特征的输出本身就是该特征自身取值的非线性函数，所以并非完全没有"选择性"——同一层内不同特征、不同输入取值，GELU 的响应也不同。需要说明：SwiGLU 的 gate（$G=xW_\text{gate}$）和 up（$U=xW_\text{up}$）其实来自同一个输入 $x$，所以 gate 并不是"独立于输入内容之外"的外部信号——这里的"独立"准确说是参数矩阵和计算分支相互独立（$W_\text{gate}$ 和 $W_\text{up}$ 是两组不同的可学习参数，各自算出一次独立的投影），不是输入信息或随机变量意义上的独立。更准确的区别是：GELU 对单一投影结果做逐元素非线性；SwiGLU 用同一个输入 $x$，经过另一组独立参数再算一次投影（$G$），把它作为门控值去调制第一个投影（$U$）的输出——多出来的是"另一条独立学习的投影分支"，而不是"内容之外的控制通道"。

SwiGLU 的 FFN：

$$x \to \underbrace{\text{SiLU}(xW_\text{gate})}_{\text{门控信号，控制"开多少"}} \odot \underbrace{xW_\text{up}}_{\text{特征内容}} \xrightarrow{W_\text{down}} \text{输出}$$

$W_\text{gate}$ 产生一个和特征维度对应的门控信号，调制每个中间特征通道的强弱；$W_\text{up}$ 提供实际的特征内容；两者逐元素相乘（$M=\text{SiLU}(G)\odot U$）后，门控值接近 0 的特征对输出贡献变小，门控值较大（可以远超 1）的特征则被放大，不是简单的"通/不通"二值控制。需要说明：最终某个通道是被放大还是缩小，不是只由门控值的绝对值单独决定，还取决于 $U$ 本身的值和符号——门控值大于 1 时相对放大 $U$ 的幅度，门控值在 0～1 之间时缩小幅度，门控值为负时可能翻转 $U$ 的符号，而如果 $U$ 本身接近 0，门控值再大最终输出也仍然很小。所以更准确的说法是"门控信号对 $U$ 做乘性调制"，而不是"门控信号单独决定最终贡献"。

类比（有简化）：可以粗略类比成给每根水管装了独立的阀门（$W_\text{gate}$），模型可以动态决定哪些中间特征该压低、哪些该放大；但和真实水阀不同的是，这个"阀门"没有 0～1 的硬性上下界——它既可能把信号放大到远超原值，也可能在中间取值区间给出小幅负值，不是一个纯粹的"开关"或"节流阀"。

小知识点：中间维度为什么是 14336，不是 4 × 4096 = 16384？

普通 GELU FFN 升维 4 倍：$4096 \times 4 = 16384$。

SwiGLU 有两个上投影矩阵（$W_\text{gate}$ 和 $W_\text{up}$），如果同样升到 16384，参数量是：

$$2 \times 4096 \times 16384 + 16384 \times 4096 = 3 \times 4096 \times 16384 \approx 2.01 \text{ 亿}$$

而普通 FFN（2 次乘法）的参数量是：

$$2 \times 4096 \times 16384 = 1.34 \text{ 亿}$$

如果想让 SwiGLU 的参数量与普通 2 矩阵 GELU FFN（升 4 倍：$d \to 4d$）严格相当，令：

$$3 \times d \times h_{\text{parity}} = 2 \times d \times 4d \implies h_{\text{parity}} = \frac{8d}{3} = \frac{8 \times 4096}{3} \approx 10923$$

如果按 128 对齐（这里只是示意性地展示"就近取整到 128 的倍数"会得到什么数字，不是 LLaMA-3 实际使用的对齐单位——见下文，真正的对齐单位是 1024）：$85 \times 128 = 10880$ 或 $86 \times 128 = 11008$。

但 LLaMA-3 实际选了 14336（$= 112 \times 128 = 3.5d$）。 这个数字可以从 Meta 公开的 Llama 3 官方实现（llama/model.py）里的真实公式精确推导出来，不需要诉诸"消融实验"这类无法验证的说法。官方公式是：

$$h_\text{base} = \frac{2}{3}(4d),\qquad h = \left\lceil \frac{h_\text{base}\times\text{ffn\_dim\_multiplier}}{\text{multiple\_of}} \right\rceil \times \text{multiple\_of}$$

代入 $d=4096$、ffn_dim_multiplier=1.3、multiple_of=1024：

$$h_\text{base} = \frac{8\times4096}{3} \approx 10922.67,\qquad h_\text{base}\times1.3 \approx 14199.47$$

$$\left\lceil\frac{14199.47}{1024}\right\rceil = 14,\qquad 14\times1024 = \textbf{14336}$$

正好对上。所以 14336 不是"128 对齐"或者神秘的消融实验最优值，而是"$\frac{8d}{3}$ 参数齐平点 × 1.3 倍放大系数，再向上取整到 1024 的倍数"这个具体配置公式算出来的——multiple_of=1024 才是真正的对齐单位，128 只是恰好也能整除 14336（$14336=112\times128$）的一个巧合，不是设计依据。

验算：$3 \times 4096 \times 14336 \approx 1.76$ 亿，比严格齐平方案（$\approx 1.34$ 亿）多约 30%。需要注意精确比例：$14336/10922.67\approx1.3125$，即实际增加约 31.25%，不是恰好 30%——ffn_dim_multiplier=1.3（30%）描述的是向上取整之前的放大系数，取整到 1024 的倍数之后，最终比例变成了 1.3125（31.25%），两者相差约 1.25 个百分点，不完全相同。

"GQA 减少 37.5%"这个说法需要说明比较对象：$1-\dfrac{41.943\text{M}}{4\times4096^2}=37.5\%$，这里的分母 $4\times4096^2$ 是"同样 32 个 Q head、同样 4096 维，但把 8 个 KV head 换成 32 个 KV head"这个假想的同宽度 MHA 版本，不是表格左边 GPT-3 实际的 6.04 亿（那是 $d_\text{model}=12288$、96 头的配置，规模完全不同）。也就是说，"37.5%"是"LLaMA-3 用 GQA vs. LLaMA-3 假想用 MHA"的对比，不是"LLaMA-3 vs. GPT-3"的对比——表格本身的两列数字（6.04 亿 vs 4194 万）已经如实反映了两个不同规模模型的差距，只是这个差距主要来自 $d_\text{model}$ 从 12288 降到 4096，GQA 本身贡献的是后面这个"同宽度下降 37.5%"的部分。

两者整体规模比：$175\text{B} / 8\text{B} \approx 21.8$ 倍；但一层参数比约 $1812\text{M} / 218\text{M} \approx 8.3$ 倍，远小于整体比。原因：GPT-3 有 96 层，LLaMA-3 只有 32 层，层数之比约 3×，$8.3 \times 3 \approx 25$，与整体比 21.8× 数量级一致（差异来自 Embedding 等非块参数占比不同）。

小知识点：Embedding 和 LM Head 为什么不共享权重？

很多早期语言模型（如 GPT-2）把 Embedding 矩阵和 LM Head 绑定为同一份参数（Weight Tying），即 $U = E^\top$，可以节省 $\lvert V \rvert \times d = 5.25$ 亿参数。

LLaMA-3 选择不共享，代价是多占 5.25 亿参数的显存。一个合理的设计动机解释是：Embedding 的职责是把离散 token id 映射到连续语义空间，LM Head 的职责是把连续表示打分回词表概率——两者的优化方向在充分训练后可能有所分歧，分开优化理论上更灵活。需要说明：这只是一种合理的动机推测，本文没有找到 Meta 公开发布的、专门针对"不共享权重带来轻微质量提升"这一结论的第一方实验数据，不能把这个解释当作 Meta 已经证实的实验结论来引用。

一句话：Embedding 是"翻译器（id→向量）"，LM Head 是"评分器（向量→概率）"，两者任务不同，让它们各自独立优化更合理。

六、KV Cache：为什么 GQA 对推理至关重要

自回归推理时，每生成一个新 token，旧 token 的 $K$ 和 $V$ 不需要重新计算——只需在第一次经过时把它们存起来，后续生成直接读取。

容易犯的错误：KV Cache 存的不是整个激活

一层前向传播有许多中间激活（Q、K、V、注意力得分、FFN 升维结果……），但只有 K 和 V 能被复用：

  • K 和 V 可以缓存，根本原因是因果模型的性质：后面追加新 token 不会改变历史位置已经算出的隐藏状态和 K/V——这一点在第一层（隐藏状态就是 token embedding 本身）看起来像是"K/V 只取决于对应位置的 token"，但在更深的层里并不准确：深层的隐藏状态是该位置及之前所有可见 token 经过多层 attention 混合后的结果，并不只取决于这一个位置自己的 token 输入。真正保证可以缓存的，是"追加未来 token 不会反过来改变过去位置已经算出的结果"这条因果性质，而不是"K/V 只依赖单个 token 输入"这个更强、但对深层不成立的说法。
  • Q 也不是数学上"不能"缓存，而是没有必要缓存：历史位置的 Q 只在算出当时那一步的输出后就不再被用到，后续的 decode 步骤用的是新 token 自己的 Q，缓存旧 Q 没有意义。
  • FFN 的中间激活同样依赖当前 token 及其对应位置的完整隐藏状态，且不会被后续步骤复用，所以不缓存。

所以 KV Cache 存的是：

$$\text{每层} \times \text{每个历史 token} \times \{K_\text{head}, V_\text{head}\} \times n_{kv} \text{ 组}$$

LLaMA-3 8B 的 KV Cache 计算：

一层、一个 token 需要存储的元素数：

$$K \text{ 部分：} n_{kv} \times d_\text{head} = 8 \times 128 = 1024 \text{ 个数}$$

$$V \text{ 部分：} n_{kv} \times d_\text{head} = 8 \times 128 = 1024 \text{ 个数}$$

BF16 每个数 2 字节（这里的 KB/MB/GB 按二进制口径计算，$1\text{KB}=1024$ 字节，严格写法是 KiB/MiB/GiB，工程语境里通常还是习惯写 KB/MB/GB）：

$$2048 \times 2 = 4096 \text{ bytes} = 4 \text{ KiB / token / 层}$$

32 层：

$$32 \times 4 \text{ KiB} = \textbf{128 KiB / token}$$

上下文长度 BF16 KV Cache（batch = 1）
1,024 128 MiB
8,192（LLaMA-3 8B 原生上下文长度） 1 GiB
32,768（超出原生上下文的外推，需要额外的长上下文扩展方法，不是原版模型原生支持） 4 GiB
128,000（同样是超出原生上下文的外推） 15.6 GiB

如果用 MHA（32 个 KV head 而不是 8 个，同样按二进制 KiB/GiB 口径）：

$$2 \times 32 \times 128 \times 2 \times 32 = 524{,}288 \text{ bytes} = 512 \text{ KiB / token}$$

8K 上下文：

$$8192 \times 512 \text{ KiB} = \textbf{4 GiB}$$

直觉：KV Cache 大小 = 层数 × KV head 数 × head 维度 × 序列长度 × 精度字节数。GQA 把 KV head 从 32 砍到 8，其余不变，Cache 直接缩小 4 倍。

七、FLOPs 计算：Prefill 与 Decode 分开看

推理分两个阶段，计算特征完全不同：

阶段 含义 计算特点
Prefill 一次性读入完整 prompt 矩阵×矩阵，算力利用高；attention 有 $S^2$ 项
Decode 每步生成 1 个新 token 矩阵×向量，受显存带宽瓶颈

Prefill（seq_len = 8192，32 层）

一层线性层 FLOPs（attention 4 次 + FFN 3 次，共 $41.9\text{M} + 176.2\text{M} = 218.1\text{M}$ 参数）：

$$2 \times 8192 \times 218{,}103{,}808 \approx 3.57 \times 10^{12}$$

一层 attention 二次项（$QK^\top$ + $AV$，按完整稠密 attention 矩阵计算 FLOPs 的口径——不一定代表优化 kernel 实际执行的计算量，见下文说明）：

$$2 \times 2 \times n_q \times S^2 \times d_\text{head} = 2 \times 2 \times 32 \times 8192^2 \times 128 \approx 1.10 \times 10^{12}$$

32 层总 FLOPs：

$$32 \times (3.57 + 1.10) \times 10^{12} \approx \textbf{1.50 \times 10^{14}}$$

即 8K prompt 的一次 prefill，32 层 Transformer 主干（线性层 + attention 二次项）约 150 TFLOPs。

这个口径需要明确几点：

  • 这里没有算 LM Head。如果要一次性算出全部 8192 个位置的 logits，还要再加 $2\times8192\times4096\times128256\approx8.61\times10^{12}\approx8.61$ TFLOPs，合计约 158 TFLOPs；但实际推理服务通常只需要 prompt 最后一个位置的 logits（用来生成第一个新 token），这种情况下 LM Head 只需要约 1.05 GFLOPs（和下面 Decode 的 LM Head 量级一样），可以忽略。所以"150 TFLOPs"要看清楚指的是哪种口径，不能笼统地叫"完整 prefill 全部计算量"。
  • attention 二次项这里按完整 $S^2$（稠密）口径计算，更精确地算是 149.53 TFLOPs；支持 causal 跳算的优化 kernel 理论上只需要算下三角部分，这一项可以减半，此时 32 层主干合计约为 131.94 TFLOPs——比稠密口径低约 11.8%，量级不变但也不算完全可以忽略。需要注意：并非所有 kernel 都严格实现"实际只算一半"，具体减少多少取决于实现方式，所以更稳妥的说法是"理论上可以减半"，而不是断言"实际只需要算下三角"。
  • Softmax、RoPE、RMSNorm 这些逐元素操作的 FLOPs 也被忽略了（量级上远小于矩阵乘法）。

所以"150 TFLOPs"是一个近似的 FLOPs 模型，不是某种精确到底的唯一实际值。

Decode（处理第 8192 个输入 token，attention 长度 8192——LLaMA-3 8B 原生上下文正好是 8192，这里刚好没有越界；如果下一步还要再送入一个 token，就已经超出原生上下文长度，需要额外的长上下文扩展方法）

这里需要先说清楚"生成"和"处理"这两个时间点的先后关系，避免差一位的误解：自回归解码的实际顺序是——(1) 已经处理完前 $t$ 个 token，得到位置 $t$ 的 logits；(2) 用这份 logits 采样出第 $t+1$ 个 token；(3) 下一次模型调用才把刚采样出的第 $t+1$ 个 token 喂进模型，它的 query 看到前面 $t$ 个位置 + 自身共 $t+1$ 个位置，算出的是用于采样第 $t+2$ 个 token 的 logits。也就是说，采样第 8192 个 token 这个动作本身（从已算好的 logits 里做一次采样）确实几乎不产生新的矩阵乘法——但这不代表生成第 8192 个 token"不需要 19.3 GFLOPs 的前向计算"：这份计算实际发生在上一轮处理第 8191 个输入 token 时（那一轮的 attention 长度是 8191，量级和这里的 19.3 GFLOPs 几乎相同），只是编号错开一位。稳态解码中，每生成一个新 token，平均仍对应一次约 19.3 GFLOPs 的单 token 前向传播，只是这次前向传播发生在处理前一个 token 输入的那一轮，而不是"采样出新 token"的那个瞬间。下面这次计算，喂入的是刚采样出的第 8192 个 token，attention 长度是 8192（8191 个历史位置 + 自身），算出的是用于采样第 8193 个 token 的 logits——严格说这是"处理第 8192 个输入 token"的计算量，但按上面的稳态关系，也可以等价地称为"生成第 8193 个 token 所需的约 19.3 GFLOPs"。两者 attention 长度只差 1（8191 vs 8192），数值上 19.3 GFLOPs 在这个精度下仍然成立；另外，"已有 8191 个位置的 KV Cache"本身不保证对应的 logits 仍然保留在内存中，只是标准的连续生成循环里，上一轮通常会同时返回这份 logits，采样才能几乎零成本地进行。

一层线性层（仅 1 个 token）：

$$2 \times 1 \times 218{,}103{,}808 \approx 4.36 \times 10^8$$

一层 attention（新输入 token 的 1 个 query，要看包括自己在内、总共 8192 个位置的 K/V：8191 个历史位置 + 自身）：

$$2 \times 2 \times 32 \times 1 \times 8192 \times 128 \approx 1.34 \times 10^8$$

32 层合计：

$$32 \times (4.36 + 1.34) \times 10^8 \approx 1.82 \times 10^{10}$$

加上 LM Head：

$$2 \times 4096 \times 128{,}256 \approx 1.05 \times 10^9$$

单 token decode 约 19.3 GFLOPs（这里只统计主要矩阵运算，不包含采样/top-k/top-p、KV Cache 写入、kernel launch 等开销——这些通常不是主要 FLOPs 来源，量级上可以忽略）。

小知识点：decode 为什么比 prefill 慢（每 token 吞吐更低）？

表面看：prefill 一次算 8192 个 token，用了 150 TFLOPs；decode 每次只算 1 个 token，只用 19 GFLOPs，似乎快很多？

但这里有个关键区别：

  • Prefill 是矩阵 × 矩阵（$X_{[S,d]} \times W_{[d,d]}$），两个大矩阵相乘，算术强度（FLOPs / 显存读写量）很高，GPU 算力核心可以被高效利用
  • Decode 退化成矩阵 × 向量（$x_{[1,d]} \times W_{[d,d]}$），每次只有 1 行，而 $W$ 矩阵需要从显存完整读出，算术强度极低

结果是：对于 batch 较小的常规单 token decode，瓶颈通常不是 GPU 算力，而是显存带宽——GPU 的算力核心大量空闲，在等待显存把权重矩阵"喂进来"。这不是所有 decode 场景下都成立的绝对结论：连续批处理（continuous batching）下 batch 较大时、上下文很长导致 attention/KV 读取占比上升时、speculative decoding 一次验证多个 token 时、张量并行通信成为瓶颈时，或权重部分驻留在更高层缓存时，算术强度可能提高、瓶颈也可能转移。更准确的说法是"小 batch 常规 decode 通常是显存带宽受限"，而不是笼统地说"decode 的瓶颈不是算力就是显存带宽"。

这就是为什么 KV Cache 的显存占用、batch size、以及 W_K/W_V 的大小（即 GQA 的意义）对推理吞吐如此关键。

一句话：小 batch 的常规 decode 通常不是算不过来，而是显存带宽跟不上 GPU 的饭量——KV Cache 越小，能同时跑的 batch 越大，整体吞吐才越高。

八、训练 FLOPs 与能耗换算

用经验公式估算训练 FLOPs

大语言模型训练常用粗略估算：

$$\text{训练 FLOPs} \approx 6 \times N \times T$$

其中 $N$ 为参数量，$T$ 为训练 token 数，系数 6 来自"前向 $\approx 2NT$，反向 $\approx 4NT$"。

小知识点：系数 6 是怎么来的？

一次前向传播：每个参数参与一次乘加，共约 $2NT$ FLOPs（乘法 + 加法各算 1 次）。这里有两处不完全精确的地方，方向相反，不能只看其中一个就下结论：

  • Token Embedding 查表被当成了矩阵乘法，导致 $6NT$ 偏高：这对参与矩阵乘法的权重（$W_Q,W_K,W_V,W_O,W_\text{gate},W_\text{up},W_\text{down}$，以及 LM Head 这类真正的稠密投影）是成立的；但 $N$ 里还包含 Token Embedding 查表矩阵（约 5.25 亿参数）——查表操作只是按 token id 取出对应的一行，几乎不产生 FLOPs。把这部分也当成参与矩阵乘法，会带来约 $525\text{M}/8.03\text{B}\approx6.5\%$ 的高估。
  • Attention 的 $QK^\top$、$\alpha V$ 这两个二次项完全没有计入 $6NT$，导致 $6NT$ 偏低：$6NT$ 只统计了参数矩阵的乘法，不包含 attention 内部这两个不带参数、但确实消耗 FLOPs 的矩阵乘法（第七节 Prefill 部分单独算过这一项）——这个遗漏量级上比 Embedding 那 6.5% 的高估更大。

用本文自己的参数重新拼一遍，同时扣掉 Embedding 查表、又补上 attention 二次项：整个模型（32 层 Transformer Block 的线性层 + LM Head，已扣掉 Embedding 查表）每个 token 的稠密矩阵乘法 FLOPs（前向+反向）约为 $6\times7.505\times10^9\approx45.03$ GFLOPs/token（这里 $7.505\times10^9=32\times218{,}103{,}808+525{,}336{,}576$，是 32 层线性层加 LM Head 的总和，不是单层的数字——单层每个 token 约为 $6\times218{,}103{,}808\approx1.31$ GFLOPs/token）；再加上 attention 二次项（前向+反向，同样是 32 层的总和），causal 减半口径下约 6.44 GFLOPs/token，完整稠密 $S^2$ 口径下约 12.88 GFLOPs/token；两种口径下、全模型每 token 合计分别约为 causal 51.47 GFLOPs/token、稠密 57.91 GFLOPs/token（两个并列结果，不是同一个量的区间）。按 15T token 代入，总训练 FLOPs 按两种口径分别是：

$$C_\text{model,\ causal}\approx7.72\times10^{23}\ \text{FLOPs}\qquad C_\text{dense-kernel}\approx8.69\times10^{23}\ \text{FLOPs}$$

这是两种不同记账口径各自算出的数字，并列展示，不是同一个量的上下界或区间——都比简化 $6NT$ 算出的 $7.23\times10^{23}$ 更大。这说明 Embedding 造成的 6.5% 高估，被 attention 二次项的遗漏抵消之后还反超了：净效应更可能是简化 $6NT$ 低估了计算量，而不是高估。

但需要指出：这两个数字不是同一类"算法 FLOPs"，不应该被笼统地并列成一个统计意义上的区间：

  • $7.72\times10^{23}$（causal 减半口径）：只统计因果注意力实际允许计算的下三角部分，这是因果模型语义上必需的有效运算量，是更贴近"模型 FLOPs"定义的数字。这里"减半"是一个近似：严格的有效位置数是 $S(S+1)/2$（含对角线自身），不是 $S^2/2$；在 $S=8192$ 时两者相对差异约为 $1/S\approx0.0122\%$，在本文的有效数字下可以忽略，但概念上应知道精确值是 $S(S+1)/2$，"恰好减半"只是 $S$ 较大时的近似说法。
  • $8.69\times10^{23}$（完整稠密 $S^2$ 口径）：额外包含了被 causal mask 丢弃的上三角部分。如果某个具体 kernel 确实先算出完整矩阵再 mask 掉一半，这部分是该 kernel 在硬件上实际执行的 FLOPs，但不是因果模型定义所必需的有效运算——换一个支持 causal 稀疏计算的 kernel，这部分就不会被执行。

所以更准确的说法是：$7.72\times10^{23}$ 是"causal 有效/模型 FLOPs"的细化估计；$8.69\times10^{23}$ 是"按完整稠密矩阵记账，或某些未做 causal 优化的 kernel 可能实际执行"的 FLOPs；梯度检查点等还可能让硬件实际执行量进一步增加。这两者是两套不同的定义，不是同一个量的置信区间上下界。这两个并列数字同样不是"真实计算量范围"，只是按 15T token、8K 序列长度、两种记账口径分别拼出来的细化 FLOPs 估计，比原来的单点估算更完整，但仍然没有计入：真实训练数据的序列长度分布和 packing 方式（不是所有样本都恰好 8K）、梯度检查点重算带来的额外硬件执行 FLOPs、被丢弃/重跑的训练步、RMSNorm/激活函数等逐元素运算，以及"15T"本身只是一个基准代入值而非精确 token 总数——这里只是用来说明"净误差方向不能只看 Embedding 这一项判断"，不是给出了一个更精确的真实 FLOPs 数字。还需要强调一点：attention 每 token 的成本随有效序列长度变化，上面 6.44/12.88 GFLOPs/token 这两个数字是按 $S=8192$ 算出来的；"净效应更可能是低估"这个方向性结论，也是在"训练序列有效长度接近 8192"这个假设下成立的，不能脱离这个假设直接推广。Meta 公开的 model card（见 Meta Llama 3 Model Card）说明预训练序列长度是 8192，但没有披露 packing 后的有效长度、padding 比例、是否存在长度课程（不同阶段用不同序列长度）等细节，所以这里的 $S=8192$ 是一个基于官方披露信息的合理近似，不是所有训练阶段、所有样本都严格适用的精确值。

反向传播需要计算两组梯度：

  1. 对输入的梯度（继续反传）：约 $2NT$
  2. 对权重的梯度（更新参数）：约 $2NT$

前向 + 反向 = $2NT + 2NT + 2NT = 6NT$。

这是数量级估算，需要区分三个不同层面，而不是笼统地说"略有偏差"：

  • 算法模型 FLOPs（前向 $2NT$ + 对输入梯度 $2NT$ + 对权重梯度 $2NT=6NT$）：这是 $6NT$ 近似的对象本身。
  • 硬件实际执行的 FLOPs：如果用了梯度检查点（gradient checkpointing），部分前向激活会在反向时重新计算一遍，这会让实际执行的 FLOPs 明显高于 $6NT$——具体取决于检查点粒度，常见方案可能让实际 FLOPs 比 $6NT$ 多出两位数的百分比，不是一个可以忽略的小修正。
  • 非"模型 FLOPs"的系统开销（注意这里不是说它们物理上零 FLOPs——Adam 的一阶/二阶矩更新（$m\leftarrow\beta_1m+(1-\beta_1)g$、$v\leftarrow\beta_2v+(1-\beta_2)g^2$）、AllReduce 通信同步里的规约求和，本身也执行浮点运算）：只是这些操作不计入标准的模型 FLOPs/MFU 分子，而且通常受限于显存带宽或网络带宽，算术强度远低于大矩阵乘法，不能简单"加到 $6NT$ 上"——更准确的说法是"$6NT$ 之外的系统开销"，它们会拉低 MFU、拉长墙钟时间，但和 FLOPs 计数是两个不同的维度，不是"不产生浮点运算"。

所以更准确的说法是：$6NT$ 只是算法层面的近似模型；硬件实际执行的 FLOPs 可能因为梯度检查点重算而明显更高（不只是"略有偏差"）；通信、优化器更新等则是独立于 FLOPs 计数之外的另一类开销，会拉低 MFU，但不应该被理解成"给 $6NT$ 加一个统一修正系数"。

LLaMA-3 8B：

$$N \approx 8.03 \times 10^9, \quad T \approx 15 \times 10^{12}$$

$$6 \times 8.03 \times 10^9 \times 15 \times 10^{12} \approx \textbf{7.23 \times 10^{23} \text{ FLOPs}}$$

这里需要说明口径：Meta 披露的训练 token 数是"15T+"，本文代入的是恰好 $15\times10^{12}$——所以 $7.23\times10^{23}$ 是按 15T 这个基准值算出来的，真实训练用的 token 数只要超过 15T，对应的理论 FLOPs 也会相应更大；同时 $6NT$ 本身也只是一个近似公式（如上所述），不是真实 FLOPs 的精确下界。

$$1.3 \times 10^6 \text{ GPU hours（H100-80GB，功耗核算口径 700W）}$$

这个 700W 是 Meta 说明里的功率核算口径（接近 GPU 峰值功率容量，并经过 PUE 调整），不是逐秒采样的实测功耗；用它乘以 GPU 小时数，得到的是一个推算值，不是电表读数：

$$1.3 \times 10^6 \times 0.7 \text{ kW} = 910{,}000 \text{ kWh} = \textbf{0.91 GWh（推算值）}$$

三者的准确定位是：1.3M GPU 小时是 Meta 直接披露的数字；910 MWh 是按 Meta 给出的功率核算口径推算出来的；390 tCO₂eq 是 Meta 自己给出的排放估算，这三者不能都笼统地叫"实际/实测用电"。

理论 FLOPs 与 GPU 小时的连接

把理论训练 FLOPs 除以总 GPU 秒数，得到每张 GPU 的端到端有效吞吐：

$$\frac{7.23 \times 10^{23}}{1.3 \times 10^6 \times 3600} \approx 1.54 \times 10^{14} \text{ FLOP/s/GPU} = \textbf{154 TFLOP/s}$$

H100 SXM5 的 BF16 Dense（无稀疏）峰值为 989 TFLOP/s（注意：494 TFLOP/s 是 TF32 Dense 的值，BF16 Dense 是其两倍），因此可以估算出一个端到端模型浮点利用率：

$$\text{MFU}_\text{估算} = \frac{154}{989} \approx \textbf{15.6\%}$$

这个 15.6% 需要理解为"基于近似输入反推出的估算值"，不是精确测量到的 MFU：15T+ token 是一个大致数字（不是精确的训练 token 总数），1.3M GPU 小时本身也是约数，$6NT$ 只是训练 FLOPs 的粗略经验模型——它忽略了 attention 二次项（这会让 $6NT$ 偏低），同时把 $N$ 里约 5.25 亿参数的 Token Embedding 查表也当成了参与矩阵乘法的参数（这会让 $6NT$ 偏高约 6.5%）。这两个误差方向相反，净效应不能只看其中一个——上面"系数 6 是怎么来的"一节用本文自己的参数重新拼过一遍，扣掉 Embedding 查表、补上 attention 二次项后，总 FLOPs 按两种口径分别是 $C_\text{model,\ causal}\approx7.72\times10^{23}$、$C_\text{dense-kernel}\approx8.69\times10^{23}$，都比简化 $6NT$ 的 $7.23\times10^{23}$ 更大，说明净效应更可能是低估而不是高估。如果用这两套更细致的 FLOPs 分别重新反推 MFU（GPU 小时数不变，仍是 1.3M）：

$$\text{MFU}_\text{model,\ causal}\approx\frac{164.97\text{ TFLOP/s}}{989\text{ TFLOP/s}}\approx16.7\%\qquad\text{利用率}_\text{dense-kernel}\approx\frac{185.62\text{ TFLOP/s}}{989\text{ TFLOP/s}}\approx18.8\%$$

这两个百分比是两种不同 FLOPs 口径分别算出的数字，并列展示，不是同一个 MFU 的置信区间上下界，不能都叫 MFU：

  • 16.7%（对应 causal 减半口径 $7.72\times10^{23}$）：分子更接近标准意义上"模型 FLOPs"的定义（因果模型语义上必需的有效运算），可以合理称为模型 FLOPs 口径下的 MFU 估计。
  • 18.8%（对应完整稠密 $S^2$ 口径 $8.69\times10^{23}$）：分子里包含了某些未做 causal 优化的 kernel 可能额外执行的 masked 区域，这部分不是模型定义所必需的运算——这个数字更准确地说不应该叫 MFU，MFU 的分子按惯例应该用事先约定好的、不随 kernel 实现变化的"模型 FLOPs"；如果换一个支持 causal 稀疏计算的 kernel，分子就应该缩小到 16.7% 对应的水平，模型本身并没有变。18.8% 更接近某种"假设 kernel 完整计算 $S^2$ 时，已统计部分硬件执行 FLOPs 除以峰值算力"的利用率，方向上更接近 HFU（Hardware FLOPs Utilization）式的口径，但也不是完整的 HFU——因为分子仍然没有计入梯度检查点重算、优化器更新、通信等其他硬件实际执行的浮点运算。更准确的三层说法是：15.6% 是传统简化 $6NT$ 定义下的 MFU 估算；16.7% 是本文细化 causal 模型 FLOPs 后的 MFU 估算；18.8% 是一种偏 HFU 方向、但仍不完整的硬件利用率参考数字，不宜继续称为"MFU"。需要纠正一点：LM Head 是真正的稠密矩阵乘法，$N=8.03\text{B}$ 里已经包含了它，不能说 $6NT$ "忽略了词表投影"——真正不够精确的地方是把 Embedding 查表也算成了矩阵乘法，不是漏算了 LM Head。

小知识点：15.6% 这个估算值为什么偏低？其余部分可能去哪了？

15.6% 这个量级在大规模分布式训练中并不罕见（理论峰值很难接近）。网上有说法称 GPT-4 训练达到约 30～38% MFU，但这不是 OpenAI 官方披露的数字，缺乏第一方技术来源，本文只把它当作非官方估计，不作为确定的对照基准。LLaMA-3 8B 这个估算值偏低，可能反映了分布式训练中常见的几类开销——但由于没有 Meta 公开的性能剖析数据，下表只能列出可能的开销来源，无法给出"剩余部分具体如何分配到各项"这样的精确归因：

  • 已知 GPU 小时数（比如 Meta 披露的 1.3M）：可以反推出隐含的 MFU 估算值（15.6%），这是本文实际做的事情。

LLaMA-3 8B 的参数量是 GPT-3 的 1/22，但训练 token 多 50 倍，总计算量反而更大。这里需要纠正一个常见的误解：这不是"Chinchilla 定律的体现"。Chinchilla 定律（Hoffmann et al., 2022）的核心结论是：在给定算力预算下，模型参数量和训练 token 数应该按相近的速率一起扩展，存在一个大致 20 token/参数 的计算最优比例（比如 Chinchilla 70B 用了约 1.4T token，约 20 token/参数）——不是"模型越小、数据越多越好"。

LLaMA-3 8B 用了 15T+ token，按 8.03B 参数算，约合 1868 token/参数，是 Chinchilla 计算最优比例（约 20 token/参数）的近 100 倍，说明 LLaMA-3 8B 的训练策略是主动大幅偏离 Chinchilla 计算最优点，而不是在实践这条定律。更准确的解释是：为了降低部署阶段的推理成本（更小的模型意味着更低的推理延迟和显存占用），Meta 在训练阶段投入远超计算最优比例的算力去训练一个相对更小的模型——这是在推理成本约束下做的工程权衡。需要说明两点：一是公开数据并不能证明训练已经"接近数据饱和"，这里不做这个断言；二是这不是"和 Chinchilla 结论相反"，而是优化目标不同——Chinchilla 研究的问题是"给定训练算力预算，如何分配模型规模和数据量以最小化训练损失"，而 LLaMA-3 8B 的选择是同时考虑训练成本和长期的推理/部署成本，因此主动偏离了单纯的训练计算最优点，两者是在回答不同的问题，不是同一个问题下的相反结论。

九、反向传播与训练机理

本章沿着前向传播的同一条链路倒着计算梯度，说明训练代码中 loss.backward() 实际完成了什么。数值例子复用配套文档《LLaMA-3-8B现代LLM架构计算规模与能耗》中的 toy GQA 模型（8 个 Query head、2 个 KV head、head_dim=2、d_model=16，token 为“机器／学习／很／有趣”），便于在同一组 Q／K／V／softmax 数值上验证反向结果。

9.0 两条贯穿全文的规则

反向传播看起来步骤很多，但本质只是链式法则加一条容易被忽略的补充规则：

  1. 链式法则：$y=f(x)$，已知 $\dfrac{\partial L}{\partial y}$，则 $\dfrac{\partial L}{\partial x} = \dfrac{\partial L}{\partial y}\cdot\dfrac{\partial y}{\partial x}$。
  2. 分支相加：如果 $x$ 在前向传播中被多个地方使用（比如同一个 $x$ 既算 $y_1=f_1(x)$ 又算 $y_2=f_2(x)$），那么反向传播时 $x$ 收到的梯度是所有分支梯度之和： $$\frac{\partial L}{\partial x} = \frac{\partial L}{\partial y_1}\frac{\partial y_1}{\partial x} + \frac{\partial L}{\partial y_2}\frac{\partial y_2}{\partial x}$$

规则 2 看起来简单，但它正是 GQA 反向传播的核心——前向时 1 个 KV head 的数据被"广播"给 4 个 Query head 使用，反向时这 4 个 Query head 传回来的梯度必须在 KV head 处加起来。以及 SwiGLU 反向（$H$ 同时喂给 gate 和 up 两条支路）、残差连接反向（$x$ 同时走了 $F(x)$ 支路和跳过 $F$ 的直连支路）——三处关键设计都是这条规则的具体应用。

9.1 一次训练 step 的完整链路

X (输入 token ids)
   │
   ▼ forward（前向文档已讲）
logits [1, seq_len, 128256]
   │
   ▼ Loss（交叉熵，与 target token 比较）
L（标量）
   │
   ▼ backward（本文要讲的部分，反向走一遍前向的每一步）
dL/dW_Q, dL/dW_K, dL/dW_V, dL/dW_O, dL/dW_gate, dL/dW_up, dL/dW_down, dL/dE, ...
   │
   ▼ optimizer.step()（如 Adam，用梯度更新每个权重）
W ← W - lr × (梯度的某种处理结果)
   │
   ▼ zero_grad()

反向传播的形状和前向是镜像的：前向从 [1,4096] 一路变成 [1,128256]，反向就是从 [1,128256] 的梯度一路变回 [1,4096]，每一步的张量形状和前向完全对应，只是数据流方向相反。

需要注意：上面图里"X (输入 token ids)"只是前向的起点标签，token id 是离散整数，没有梯度可言（$\partial L/\partial\text{token\_id}$ 没有意义）。反向传播链路真正的终点是 Embedding 查表之后那个连续向量 $x_0=E[\text{token\_id},:]$ 的梯度 [1,4096]，最终再落到 Embedding 权重矩阵 $E$ 本身（第六节）——链路在"查表"这个操作处就结束了，不会、也不需要传到离散的输入 id 上。

9.2 起点：Loss 对 logits 的梯度

LLaMA-3 训练用交叉熵损失。设 target token 的 one-hot 向量是 $y$（只有正确 token 位置是 1，其余是 0），预测概率 $p=\text{softmax}(\text{logits})$：

$$L = -\log p_{\text{target}} = -\sum_i y_i \log p_i$$

关键结果（softmax 和交叉熵放在一起求导会大幅简化）：

$$\frac{\partial L}{\partial \text{logits}_i} = p_i - y_i$$

也就是"模型预测的概率分布"减去"真实分布（one-hot）"。这是整条反向传播链路的起点信号，形状为 $[1,\ 128256]$。

小例子（词表只有 4 个词，方便手算）：假设 logits = $[2.0, 1.0, 0.1, 0.5]$，target 是第 0 个词。

$$p = \text{softmax}([2.0,1.0,0.1,0.5]) \approx [0.575,\ 0.211,\ 0.086,\ 0.128]$$

$$\frac{\partial L}{\partial \text{logits}} = p - [1,0,0,0] \approx [-0.425,\ 0.211,\ 0.086,\ 0.128]$$

校验：$p$ 四项之和应为 1（$0.575+0.211+0.086+0.128\approx1$ ✓），梯度四项之和应为 0（$-0.425+0.211+0.086+0.128\approx0$ ✓）——这两条是手算或写代码时最快发现算错的自检方式。

直觉：正确 token 的梯度是负的（说明要"调高"它的 logit 才能降低 loss），其余 token 的梯度是正的（要"调低"）。

批次、序列维度与"平均"：上面为了手算方便只看了 1 个 token，也没有除以 token 数。真实训练里 logits 形状是 $[B,\ S,\ V]$（$B$=batch size，$S$=序列长度），loss 通常是对所有有效 token（不含 padding）求平均。设有效 token 数为 $M$，则每个位置的梯度要多除一个 $M$：

$$\frac{\partial L}{\partial \text{logits}_{b,t,i}} = \frac{p_{b,t,i}-y_{b,t,i}}{M}$$

记号约定：从这里开始，为了对照前向文档的具体数值，公式都按"单个 token"（一行向量）推导，形状写成 $[1,4096]$ 之类。真实实现里 $X,H,Q,K,V,\dots$ 都还有 batch 和序列维度（如 $X:[B,S,4096]$）。对权重的梯度（如下面的 $\partial L/\partial U$、$\partial L/\partial w_i$、$\partial L/\partial W_Q$ 等）都需要在 $B,S$ 两个维度上求和——因为同一份权重被 batch 里所有 token 位置共同使用，这正是第〇节"分支相加"规则的又一次应用，只是这次分支多达 $B\times S$ 条。激活/输入的梯度不需要像共享权重那样统一压缩掉 batch/序列维度，但一个激活节点仍然要把计算图里所有用到它的分支的梯度累加起来。这里有两件不同的事需要分清楚：线性层、RMSNorm、SwiGLU 这类操作不产生跨 token 依赖——每个 token 位置的计算互不影响，可以"各自独立地往前传"；但同一个 token 内部仍然可能有多条分支需要相加（比如 SwiGLU 的 gate/up 两条支路，见 5.2，这和"跨 token"无关，是同一个 token 内的分支相加）。在本文列出的这几个模块里，只有 Attention 直接混合不同 token 位置：一个位置 $j$ 的 $K_j,V_j$ 会被多个后续 query token 共同使用，梯度要跨 query 位置累加（第五节 5.4 会具体展开）。（这里限定在本文描述的标准 decoder-only 主干内——序列级损失、跨 token 正则项、MoE 路由辅助损失这类额外设计也可能引入跨 token 依赖，但不在本文讨论范围内，LLaMA-3 8B 这条标准反向链路不受影响。）

9.3 LM Head 反向

前向：$\text{logits} = h_\text{final} \cdot U,\quad U:[4096,\ 128256]$

线性层反向的通用公式（记住这两条，后面所有 $W_Q,W_K,W_V,W_O,W_\text{gate},W_\text{up},W_\text{down}$ 的反向都是同一套）：

$$Y = XW \implies \frac{\partial L}{\partial X} = \frac{\partial L}{\partial Y}\,W^\top, \qquad \frac{\partial L}{\partial W} = X^\top \frac{\partial L}{\partial Y}$$

代入 LM Head：

$$\frac{\partial L}{\partial h_\text{final}} = \frac{\partial L}{\partial \text{logits}} \cdot U^\top \quad [1,\ 128256]\times[128256,\ 4096] \rightarrow [1,\ 4096]$$

$$\frac{\partial L}{\partial U} = h_\text{final}^\top \cdot \frac{\partial L}{\partial \text{logits}} \quad [4096,\ 1]\times[1,\ 128256] \rightarrow [4096,\ 128256]$$

两个结果形状分别对应 $h_\text{final}$（继续往前传）和 $U$（这一层要更新的权重）——这个"一个输出、两个梯度"的模式会在每一个矩阵乘法处重复出现。

上面 $\partial L/\partial U$ 是单个 token 的贡献；$U$ 是整个 batch、整个序列所有 token 共享的同一份权重，按前面的记号约定，真正要用来更新权重的梯度是对所有 $b,t$ 求和：

$$\frac{\partial L}{\partial U} = \sum_{b,t} h_{b,t}^\top \frac{\partial L}{\partial \text{logits}_{b,t}}$$

而 $\partial L/\partial h_{b,t}$ 对每个 token 位置各自独立，不需要求和，直接继续往前传即可。

9.4 Final RMSNorm 反向

前向（复习）：

$$r = \text{RMS}(x)=\sqrt{\tfrac{1}{d}\sum_i x_i^2+\epsilon},\qquad n_i=\frac{x_i}{r},\qquad y_i = n_i\, w_i$$

对权重 $w$ 的梯度（单个 token，逐元素）：

$$\frac{\partial L}{\partial w_i} = \frac{\partial L}{\partial y_i}\cdot n_i$$

同样地，$w$ 是所有 batch、所有序列位置共享的同一份权重，真正的梯度要对 $b,t$ 求和：

$$\frac{\partial L}{\partial w_i} = \sum_{b,t}\frac{\partial L}{\partial y_{b,t,i}}\cdot n_{b,t,i}$$

对输入 $x$ 的梯度（麻烦一点，因为 $r$ 依赖所有 $x_i$，不能逐元素独立求导）。记 $g_i = \dfrac{\partial L}{\partial y_i}\cdot w_i$（先把权重缩放吸收掉），结果是：

$$\frac{\partial L}{\partial x_j} = \frac{1}{r}\left[g_j - \frac{n_j}{d}\sum_i g_i n_i\right]$$

直觉：第一项 $g_j/r$ 是"当作没有归一化时"的梯度；第二项是修正项——因为 $x_j$ 变化不仅影响自己的 $n_j$，还会通过分母 $r$ 影响所有其他 $n_i$，修正项就是把这个"全局耦合"效应减掉。这个形式和 LayerNorm 反向几乎一样，只是 LayerNorm 还要多处理一个"减均值"带来的耦合项。

这个公式在整个模型里一共要用 $32\times2+1=65$ 次——每个 Block 有 2 个 RMSNorm（Attention 前 1 个、FFN 前 1 个），32 层就是 64 次，再加 1 次 Final RMSNorm，是反向传播里出现频率最高的公式之一。

9.5 32 层 Block 反向：从最后一层往前，重复 32 次

训练时反向传播是从第 32 层往第 1 层走，每层内部也是把前向的步骤倒过来。下面按前向的相反顺序展开一层。

9.5.1 残差连接反向——"梯度高速公路"到底是什么

前向：$X_\text{next} = H + Y$（$H$ 是残差分支，$Y$ 是 FFN 或 attention 的输出）

反向（加法节点的梯度直接复制给两个分支，不衰减）：

$$\frac{\partial L}{\partial H} \mathrel{+}= \frac{\partial L}{\partial X_\text{next}}, \qquad \frac{\partial L}{\partial Y} = \frac{\partial L}{\partial X_\text{next}}$$

这就是前向文档里"Pre-Norm 让梯度有一条高速公路"这句话的数学含义：$\dfrac{\partial L}{\partial X_\text{next}}$ 会原封不动（传递系数恒为 1）地加到 $\dfrac{\partial L}{\partial H}$ 上，不需要经过 $F(\cdot)$（attention 或 FFN）内部那些可能缩放、旋转甚至反号的变换。32 层累加下来，残差保证了"存在一条从第 32 层直接连到第 1 层、传递系数恒为 1 的路径"，这是深层网络不容易梯度消失的关键原因。

需要注意：这不等于"最终梯度一定不会变小"。直连路径传回来的梯度和经过 $F(\cdot)$ 分支传回来的梯度，在同一个节点上是相加的关系——如果两者方向相反，仍然可能相互抵消，导致最终梯度变小甚至接近 0。残差解决的是"是否存在一条不衰减的路径"，而不是保证"最终梯度一定不衰减"。

把两次残差合并写清楚：一个 Block 的输入是 $x$，第一次残差输出 $u=x+\text{Attention}(\text{Norm}_1(x))$，第二次残差输出 $y=u+\text{MLP}(\text{Norm}_2(u))$。记 $g_y=\partial L/\partial y$ 是从下一层（或下一个 Block）传回来的梯度，完整的合并公式是：

$$g_u = \underbrace{g_y}_{\text{直通残差}} + \underbrace{J_{\text{Norm}_2}^\top J_{\text{MLP}}^\top g_y}_{\text{MLP 分支（5.2+5.3 算出来的）}}$$

$$g_x = \underbrace{g_u}_{\text{直通残差}} + \underbrace{J_{\text{Norm}_1}^\top J_{\text{Attention}}^\top g_u}_{\text{Attention 分支（5.4+5.5 算出来的）}}$$

下面 5.2～5.3 具体展开 $J_{\text{Norm}_2}^\top J_{\text{MLP}}^\top g_y$ 这一项（SwiGLU 反向 + 第二个 RMSNorm 反向），5.4～5.5 展开 $J_{\text{Norm}_1}^\top J_{\text{Attention}}^\top g_u$ 这一项（Attention 反向 + 第一个 RMSNorm 反向）——两处推导到最后都别忘了按上面的公式加回直通残差的那一份，才是 $g_u$、$g_x$ 的完整值。

9.5.2 SwiGLU 反向

前向（$u$ 是这个 Block 第一次残差的输出，$\hat u=\text{Norm}_2(u)$ 是喂给 SwiGLU 的归一化结果）：

$$G = \hat u W_\text{gate}, \quad U = \hat u W_\text{up}, \quad M = \text{SiLU}(G)\odot U, \quad Y = M W_\text{down}$$

倒着算：

Down 投影（线性层反向公式）：

$$\frac{\partial L}{\partial M} = \frac{\partial L}{\partial Y}\, W_\text{down}^\top, \qquad \frac{\partial L}{\partial W_\text{down}} = M^\top \frac{\partial L}{\partial Y}$$

门控相乘（逐元素乘积的反向就是"交换两个因子"）：

$$\frac{\partial L}{\partial \text{SiLU}(G)} = \frac{\partial L}{\partial M}\odot U, \qquad \frac{\partial L}{\partial U} = \frac{\partial L}{\partial M}\odot \text{SiLU}(G)$$

SiLU 激活反向，需要 SiLU 的导数。$\text{SiLU}(x)=x\cdot\sigma(x)$（$\sigma$ 是 sigmoid）：

$$\text{SiLU}'(x) = \sigma(x) + x\,\sigma(x)(1-\sigma(x)) = \sigma(x)\big[1+x(1-\sigma(x))\big]$$

$$\frac{\partial L}{\partial G} = \frac{\partial L}{\partial \text{SiLU}(G)} \odot \text{SiLU}'(G)$$

Up / Gate 投影（线性层反向公式，各自独立）：

$$\frac{\partial L}{\partial \hat u}\Big|_\text{up 支路} = \frac{\partial L}{\partial U}W_\text{up}^\top, \qquad \frac{\partial L}{\partial W_\text{up}} = \hat u^\top \frac{\partial L}{\partial U}$$

$$\frac{\partial L}{\partial \hat u}\Big|_\text{gate 支路} = \frac{\partial L}{\partial G}W_\text{gate}^\top, \qquad \frac{\partial L}{\partial W_\text{gate}} = \hat u^\top \frac{\partial L}{\partial G}$$

关键一步——分支相加：$\hat u$ 同时走了 gate 和 up 两条支路（这正是第〇节讲的规则 2），所以：

$$\frac{\partial L}{\partial \hat u} = \frac{\partial L}{\partial \hat u}\Big|_\text{gate 支路} + \frac{\partial L}{\partial \hat u}\Big|_\text{up 支路}$$

漏加这一项是实现 SwiGLU 反向传播时最容易犯的错误——少加一条支路算出来的就是错误的梯度（方向和数值都不对，不能简单说成"偏小"）。

9.5.3 第二个 Pre-RMSNorm 反向

直接套用第四节的 RMSNorm 反向公式，输入是 $u$（残差流），输出是 $\hat u$，把上面算出的 $\partial L/\partial \hat u$ 转成 $g_u^{(\text{MLP})}=\partial L/\partial u$——这正是 5.1 汇总公式里 $J_{\text{Norm}_2}^\top J_{\text{MLP}}^\top g_y$ 这一整项。

按 5.1 的合并公式，把它加回直通残差的 $g_y$，得到这个 Block 第二个残差节点的完整梯度：

$$g_u = g_y + g_u^{(\text{MLP})}$$

这个 $g_u$ 就是接下来要交给 Attention 分支（5.4～5.5）的完整梯度。

9.5.4 GQA 注意力反向（含 softmax、RoPE、GQA 梯度累加）——核心难点

这是整个反向传播里最容易出错、也最值得手推一遍的部分。反向的计算顺序是前向的镜像——前向最后做的是 O 投影，所以反向第一步要处理的局部梯度也是 O 投影这一层，然后依次是 concat、每个 head 内部的 softmax/QK/V、RoPE，最后才是 Q/K/V 投影。

这里说"顺序相反"指的是计算顺序，不是说反向传播在"求逆"前向操作：对线性层 $Y=XW$，$dX=dY\,W^\top$，$W^\top$ 一般不是 $W^{-1}$；softmax、SwiGLU 也都不是可逆运算，反向只是在每个节点上算局部梯度、按链式法则往前传。RoPE 是例外——它的旋转矩阵是正交矩阵，转置恰好等于逆，所以下面 (f) 里"把梯度反向旋转回去"确实等价于"求逆"，但这是 RoPE 的特殊性质，不能推广到其他模块。

下面复用前向文档二里的 toy 模型，选一个 GQA 分组（Q0～Q3 共享的 KV head 0）完整手推；另一组 Q4～Q7/KV head 1 方法完全相同，不再重复手算。

(a) 反向的第一步：O 投影反向 + concat 拆分

这个 Block 的 Attention 分支收到的梯度，是 5.1 汇总公式里 $g_u$ 对应到 attention 输出那部分，记为 $\dfrac{\partial L}{\partial \text{attn\_out}}$：

$$\frac{\partial L}{\partial \text{attn\_concat}} = \frac{\partial L}{\partial \text{attn\_out}}\,W_O^\top, \qquad \frac{\partial L}{\partial W_O} = \text{attn\_concat}^\top \frac{\partial L}{\partial \text{attn\_out}}$$

concat 的反向就是 split——把 $[1,4096]$ 的梯度按 32 个 head 的边界切开，得到每个 head 各自的 $\dfrac{\partial L}{\partial o_h}$。

回顾 toy 模型设置：8 个 Query head，2 个 KV head（每 4 个 Q head 共享 1 个 KV head），head_dim=2。token 4"有趣"的 Q0～Q3 使用 KV head 0：

  • $q_{4,0}=[2,0],\ q_{4,1}=[0,2],\ q_{4,2}=[-2,0],\ q_{4,3}=[0,-2]$
  • KV head 0 的 $k,v$（4 个位置）：$k_1=v_1=[1,0]$（机器），$k_2=v_2=[0,1]$（学习），$k_3=v_3=[-1,0]$（很），$k_4=v_4=[0,-1]$（有趣）
  • Softmax 权重（前向文档已算出）：
    • $\alpha_{0,\cdot} = [0.647,0.157,0.038,0.157]$
    • $\alpha_{1,\cdot} = [0.157,0.647,0.157,0.038]$
    • $\alpha_{2,\cdot} = [0.038,0.157,0.647,0.157]$
    • $\alpha_{3,\cdot} = [0.157,0.038,0.157,0.647]$

为了让手算的数字干净，下面假设 split 之后 Q0～Q3 拿到的梯度都是 $\dfrac{\partial L}{\partial o_{4,h}} = [1,0]$（真实训练中这四个值就是上面这一步 split 算出来的，通常互不相同）。

这个例子只固定了 query token $t=4$（"有趣"）。完整训练里，一个 $k_j,v_j$ 不仅要对同一 GQA 组内的 4 个 Query head 求和，还要对所有能看到位置 $j$ 的 query token 求和（因果掩码下即所有 $t\ge j$ 的 token）：

$$\frac{\partial L}{\partial v_j} = \sum_{t\ge j}\ \sum_{h\in\text{group}}\alpha_{t,h,j}\cdot\frac{\partial L}{\partial o_{t,h}}$$

下面 (b)～(e) 为了手算方便，只展开了 $t=4$ 这一个 query token 对 $k_j,v_j$ 的贡献；其余 $t=1,2,3$（"机器""学习""很"各自作为 query 时）需要按同样的公式再累加一遍，真实实现里这是张量运算自动完成的，不需要手动循环。

(b) 对 V 的梯度：$o=\sum_j \alpha_j v_j$

$$\frac{\partial L}{\partial v_j}\Big|_{\text{来自 }t=4,\text{head }h} = \alpha_{h,j}\cdot\frac{\partial L}{\partial o_{4,h}}$$

这里就是 GQA 梯度累加发生的地方（先看同一 query token 内跨 head 的累加）：$v_j$ 在前向时被 Q0～Q3 这 4 个 head 同时读取（规则 2 的分支相加），所以仅考虑 $t=4$ 这一项时：

$$\frac{\partial L}{\partial v_j}\Big|_{t=4} = \sum_{h=0}^{3}\alpha_{h,j}\cdot\frac{\partial L}{\partial o_{4,h}}$$

代入数字（4 个 head 的 do 都是 $[1,0]$，所以每个位置 $j$ 只需要把 4 个 $\alpha_{h,j}$ 加起来）：

$$\sum_h \alpha_{h,1} = 0.647+0.157+0.038+0.157 = 0.999 \approx 1$$

（对"学习""很""有趣"三个位置算出来同样约等于 1——这是这个对称 toy 例子的巧合，不是一般规律，本质原因是 4 个 Q 向量恰好是同一个模式的旋转排列。）

$$\frac{\partial L}{\partial v_j}\Big|_{t=4} \approx [1,\ 0] \quad \text{对 } j=1,2,3,4 \text{ 都成立}$$

（如上所述，这只是 $t=4$ 这一项；$v_j$ 的完整梯度还要加上 $t=1,2,3$ 里能看到位置 $j$ 的那些贡献。）

直觉：一个 KV head 前向时被 4 个 Q head "共用"，反向时它收到的梯度就是这些 Q head 各自传回来的梯度叠加。更准确的口径是：$QK^\top$、softmax、$\alpha V$ 这部分反向计算量仍然按 Query head 数（32 个）来算，通常不会因为 GQA 而缩小 4 倍；真正缩小的是 $W_K,W_V$ 的前向/反向投影计算量，以及 $K,V$ 张量本身的存储和显存带宽（这也是前向文档强调 KV Cache 降为 1/4 的原因）。所以"GQA 让反向计算量变小"这句话不完全准确——它省的主要是 K/V 投影和显存/带宽开销，而不是整个 attention 部分的计算量。

(c) 对 softmax 输入（score）的梯度——以 Q0 为例完整算一遍

Softmax 反向的标准公式：若 $\alpha=\text{softmax}(s)$，已知 $\dfrac{\partial L}{\partial \alpha_j}$，则

$$\frac{\partial L}{\partial s_j} = \alpha_j\left(\frac{\partial L}{\partial \alpha_j} - \sum_l \alpha_l\frac{\partial L}{\partial \alpha_l}\right)$$

先算 $\dfrac{\partial L}{\partial \alpha_j}\Big|_{h=0} = \dfrac{\partial L}{\partial o_{4,0}}\cdot v_j = [1,0]\cdot v_j$：

$$[d\alpha_1,d\alpha_2,d\alpha_3,d\alpha_4] = [1,\ 0,\ -1,\ 0]$$

（$v_1=[1,0]\Rightarrow 1$；$v_2=[0,1]\Rightarrow 0$；$v_3=[-1,0]\Rightarrow -1$；$v_4=[0,-1]\Rightarrow 0$）

$$\sum_l \alpha_l\,d\alpha_l = 0.647(1)+0.157(0)+0.038(-1)+0.157(0) = 0.609$$

代入 softmax 反向公式：

$$ds_1 = 0.647(1-0.609)=0.253,\quad ds_2=0.157(0-0.609)=-0.096$$ $$ds_3 = 0.038(-1-0.609)=-0.061,\quad ds_4=0.157(0-0.609)=-0.096$$

校验：$\sum_j ds_j$ 应该恒等于 0（softmax 雅可比矩阵的性质），$0.253-0.096-0.061-0.096\approx 0$ ✓。这条校验在写代码时非常实用——如果反向传播实现里 $\sum ds_j \neq 0$，说明公式敲错了。

score 是 $s_j = q\cdot k_j/\sqrt{d_\text{head}} = q\cdot k_j/\sqrt2$，所以 $\dfrac{\partial L}{\partial(q\cdot k_j)} = ds_j/\sqrt2$：

$$[0.179,\ -0.068,\ -0.043,\ -0.068]$$

(d) 对 Q 的梯度（Q0 不与其他 head 共享，这里不需要累加）

$$\frac{\partial L}{\partial q_{4,0}} = \sum_j \frac{\partial L}{\partial(q\cdot k_j)}\cdot k_j = 0.179[1,0]-0.068[0,1]-0.043[-1,0]-0.068[0,-1]$$

$$= [0.179+0.043,\ -0.068+0.068] = [0.222,\ 0]$$

(e) 对 K 的梯度——同样需要 GQA 累加（这里只算 $t=4$ 这一项）

$$\frac{\partial L}{\partial k_j}\Big|_{t=4} = \sum_{h=0}^{3}\frac{\partial L}{\partial(q_h\cdot k_j)}\cdot q_h$$

以位置 1（"机器"）为例，需要 Q0～Q3 各自对 $k_1$ 的贡献（按 (c)(d) 同样步骤对 Q1、Q2、Q3 各算一遍，可得 $\dfrac{\partial L}{\partial(q_h\cdot k_1)}$ 分别为 $0.179,\ 0.111,\ 0.043,\ 0.111$）：

$$\frac{\partial L}{\partial k_1}\Big|_{t=4} = 0.179\,q_0 + 0.111\,q_1 + 0.043\,q_2 + 0.111\,q_3$$

$$= 0.179[2,0]+0.111[0,2]+0.043[-2,0]+0.111[0,-2] \approx [0.272,\ 0]$$

同样地，$k_2,k_3,k_4$ 也各自要把 Q0～Q3（这一个 query token 内）的贡献加起来——这就是"4 个 Q head 共享 1 个 KV head"在反向传播里的确切含义：$k_j$（以及上面算过的 $v_j$）在同一个 query token 下的梯度是 4 条链路梯度的和。别忘了 (a) 末尾提到的另一层累加：真实的 $k_1$ 总梯度还要再加上 $t=1,2,3$ 各自对位置 1 的贡献。

(f) RoPE 反向：旋转矩阵的转置就是逆旋转

RoPE 前向是对每两维做一次旋转：$q' = R_p\,q$，其中 $R_p$ 是正交旋转矩阵（$R_p^\top R_p = I$）。旋转矩阵的转置恰好等于它的逆，也等于"反向旋转同一个角度"：

$$R_p^\top = R_p^{-1} = R_{-p}$$

所以 RoPE 的反向传播极其简单——把梯度按相同的角度反向旋转回去：

$$\frac{\partial L}{\partial q} = R_p^\top \frac{\partial L}{\partial q'} = R_{-p}\left(\frac{\partial L}{\partial q'}\right)$$

（对 $K$ 同理，$V$ 没有 RoPE，不需要这一步）

数值例子（独立于上面的 toy 模型，只演示这个性质）：设某平面上旋转角 $\theta=30°$，$R_\theta=\begin{bmatrix}\cos30°&-\sin30°\\\sin30°&\cos30°\end{bmatrix}\approx\begin{bmatrix}0.866&-0.5\\0.5&0.866\end{bmatrix}$。若传入的梯度 $\dfrac{\partial L}{\partial q'}=[1,0]$，反向旋转（乘 $R_\theta^\top$，即用 $-30°$）：

$$R_\theta^\top[1,0]^\top = [\cos30°,\ -\sin30°]=[0.866,\ -0.5]$$

（对照：把 $[1,0]$ 按 $-30°$ 旋转得到 $[\cos(-30°),\sin(-30°)]=[0.866,-0.5]$，两种算法一致 ✓）

对上面 (d)(e) 算出的 $\dfrac{\partial L}{\partial q_{4,0}}$、$\dfrac{\partial L}{\partial k_j}$，实际训练代码里这一步就是把它们按各自 token 位置对应的旋转角转回去，得到 RoPE 之前（也就是 $W_Q,W_K$ 投影输出）的梯度。

(g) Q/K/V 投影反向

这一步有一个容易被忽略的形状不对称：$q_\text{proj}$ 只属于当前这一个 query token，reshape 拼回各 head 后是 $[1,4096]$；而当前 $t=4$ 的 query 需要读取位置 $1\sim S$ 的整段 K/V（并不是"所有位置共用同一个 $K,V$ 向量"——每个位置仍有自己的 $K_j,V_j$，只是它们都会被这一个 query 用到），所以 (e) 算出的 $\partial L/\partial k_j$ 是每个位置 $j$ 各自一份，要按序列位置拼成 $[S,1024]$（$S$ 是 K/V 覆盖的序列长度），而不是像 $q_\text{proj}$ 那样的单行 $[1,1024]$。真实的批次+序列写法是 $dq_\text{proj}:[B,S,4096]$，$dk_\text{proj},dv_\text{proj}:[B,S,1024]$（完整序列训练里 $S$ 对 Q 和 K/V 是同一个维度，本文按 (a) 的设定为了手算方便只展开了 $t=4$ 这一行）。

拿到这些之后，套用第三节的线性层反向公式。在本文这个"只展开 $t=4$"的局部例子里，$X$ 在 Q 分支和 K/V 分支里对应的形状并不相同，要分开写：

$$\frac{\partial L}{\partial W_Q} = X_{t=4}^\top \frac{\partial L}{\partial q_\text{proj}}, \qquad \frac{\partial L}{\partial X}\Big|_Q = \frac{\partial L}{\partial q_\text{proj}}\,W_Q^\top \qquad (X_{t=4}:[1,4096])$$

$$\frac{\partial L}{\partial W_K} = X_{1:S}^\top \frac{\partial L}{\partial k_\text{proj}}, \qquad \frac{\partial L}{\partial W_V} = X_{1:S}^\top \frac{\partial L}{\partial v_\text{proj}} \qquad (X_{1:S}:[S,4096])$$

同理得到 $\dfrac{\partial L}{\partial X}\big|_K,\dfrac{\partial L}{\partial X}\big|_V$（也是 $[S,4096]$）。完整序列训练时，Q 分支自然也覆盖所有 $S$ 个位置，三者会统一成 $[B,S,4096]$，不再需要区分 $X_{t=4}$ 和 $X_{1:S}$——这个区分只在本文"单 query token 演示"这个局部例子里才存在。

(h) 汇总：$X$（第一个 Pre-RMSNorm 输出）的总梯度

$X$ 同时走了 $Q,K,V$ 三条投影支路（又是第〇节的规则 2）：

$$\frac{\partial L}{\partial X} = \frac{\partial L}{\partial X}\Big|_Q + \frac{\partial L}{\partial X}\Big|_K + \frac{\partial L}{\partial X}\Big|_V$$

按 token 位置对齐后再相加：在完整序列训练里，每个位置的 $X$ 既是它自己那个 query 的输入，又是它作为 K/V 提供者的输入，所以三个分支在同一个位置上都是 $[1,4096]$（合起来 $[S,4096]$）。本文的手算例子里 Q 只展开了 $t=4$ 这一个位置，所以上面的求和严格来说只在"位置 4"这一行成立——$X$ 在其他位置（1,2,3）的总梯度，还需要各自位置的 Q 分支（本文未展开）加上它们作为 K/V 分支时收到的梯度。

9.5.5 第一个 Pre-RMSNorm 反向

5.4(h) 算出的 $\dfrac{\partial L}{\partial X}$ 是对 Norm1 输出 $X=\text{Norm}_1(x)$ 的梯度，还不是对 Block 输入 $x$ 的梯度——必须再套用一次第四节的 RMSNorm 反向公式才能转换过去（这一步很容易被漏掉：如果直接把 $\partial L/\partial X$ 当成 $\partial L/\partial x$ 使用，相当于漏做了一次 RMSNorm 的雅可比变换）。

按第四节的记号，先算 $g_i = \dfrac{\partial L}{\partial X_i}\cdot w_i$（$w$ 是 Norm1 的缩放参数），再代入

$$\Big(g_x^{(\text{attn})}\Big)_j = \frac{1}{r}\left[g_j - \frac{n_j}{d}\sum_i g_i n_i\right]$$

得到 Attention 分支对 Block 输入的贡献 $g_x^{(\text{attn})} = \partial L/\partial x\big|_{\text{Attention 分支}}$——这正是 5.1 汇总公式里 $J_{\text{Norm}_1}^\top J_{\text{Attention}}^\top g_u$ 这一整项。

按 5.1 的合并公式，把它加回直通残差的 $g_u$，得到这个 Block 完整的输入梯度：

$$g_x = g_u + g_x^{(\text{attn})}$$

$g_x$ 就是要传给上一个 Block（第 31 层，如果当前是第 32 层）的完整梯度，对应上一个 Block 里的 $g_y$。

至此一层 Block 的反向传播完整走完，32 层重复这个流程（顺序是从第 32 层往第 1 层，每层用上一层的 $g_x$ 当作自己的 $g_y$）。

9.6 Embedding 反向——数据梯度是行稀疏的，但更新方式因实现而异

前向：$x_0 = E[\text{token\_id}, :]$（查表，只取一行）。

反向：

$$\frac{\partial L}{\partial E[\text{token\_id}, :]} \mathrel{+}= \frac{\partial L}{\partial x_0}$$

关键点：$E$ 是 $[128256, 4096]$ 的大矩阵。一个 microbatch 里 token 位置数是 $B\times S$（大 batch、长序列下可能有数万甚至更多），不同的 token ID 数最多是 $\min(B\times S,\ |V|)$——多数训练场景下这个数字仍然远小于词表大小 128256。

如果还用了梯度累积（一次优化器更新前连续跑 $A$ 个 microbatch 才 zero_grad()），这是另一件独立的事：在梯度真正清零之前，Embedding 收到非零梯度的行数上限要相应放大到 $\min(A\times B\times S,\ |V|)$，不能直接套用单个 microbatch 的 $\min(B\times S,|V|)$。

上面 $\min(A\times B\times S,|V|)$ 说的是 AllReduce 之前、单个数据并行 rank 本地看到的覆盖量。如果训练还用了数据并行（并行度 $D$，各 rank 各自算本地梯度，AllReduce 汇总后再统一更新），AllReduce 之后全局的覆盖量上限要再乘上 $D$，变成 $\min(D\times A\times B\times S,\ |V|)$——这是"单 rank、汇总前"和"全局、汇总后"两个不同阶段各自的上限，不要混用。

所以大部分行的梯度是 0，但不能笼统地说"出现过的 token 最多几千个"或"绝大多数行一定为零"，这取决于 batch 大小、序列长度、是否梯度累积和词表大小的相对关系。更稳妥的说法是：数据梯度在给定的梯度累积窗口内通常具有行稀疏结构。

但这不等于"实际训练一定按稀疏方式更新"：PyTorch 的 nn.Embedding 默认产生稠密梯度（整个 $[128256,4096]$ 都会分配显存并参与更新），只有显式设置 sparse=True 才会得到稀疏梯度；大规模 LLM 训练里 Embedding 通常还会做张量/词表并行切分，AdamW 的权重衰减也可能作用到没出现过的行上。所以更准确的说法是：Embedding lookup 的数据梯度在行维度上具有稀疏结构，但实际是否使用稀疏梯度、稀疏更新，取决于具体框架、优化器和分布式实现，不能一概而论。

FLOPs 量级上，Embedding 查表本身远小于一次矩阵乘法，在"系数 6"的估算里可以忽略不计；但不能因此认为 LM Head 主导了整体计算量——LM Head 只是单独一层里最大的一次矩阵乘法（约 5.25 亿参数），而 32 层 Transformer Block 的线性层参数总量约 70 亿（LM Head 的 13 倍以上），整体训练/推理计算量仍然由 32 层 Block 主导，LM Head 只是其中"单层最大"的那一次。

9.7 用代码校验公式（推荐做法，而不是继续手算）

手推到这里已经能覆盖 RMSNorm、GQA、RoPE、SwiGLU 四个 LLaMA-3 特有模块的反向传播。继续用纸笔验证更大的例子容易出算术错误，更可靠的做法是写几行 PyTorch，用 torch.autograd 当作"标准答案"来对照自己手推的公式。

RMSNorm 反向校验（对应第四节）：

import torch

def rmsnorm(x, w, eps=1e-6):
    r = torch.sqrt((x**2).mean(-1, keepdim=True) + eps)
    return x / r * w

x = torch.tensor([1., 2., 3.], requires_grad=True)
w = torch.tensor([1., 1., 1.], requires_grad=True)
y = rmsnorm(x, w)
loss = y.sum()
loss.backward()

print("autograd dL/dx:", x.grad)   # 与第四节公式手算结果对比
print("autograd dL/dw:", w.grad)

GQA + softmax 反向校验（单个 query token）：把 toy 模型的 $q_{4,0..3}$、$k_{1..4}$、$v_{1..4}$（这些数值已经是 RoPE 之后的）搭成计算图，用 .backward() 让 k.grad、v.grad 自动算出来的只是 $t=4$ 这一个 query token 的贡献（用 torch.autograd.grad(...) 也能拿到同样的结果，区别只是它直接返回梯度、不写进 .grad；下面统一用 .backward()）——因为图里根本没有其他 query token，不会自动出现跨 query token 的累加。这正好可以拿来对照本文 (b)～(e) 手算的 [0.272, 0]（$t=4$ 这一项对 $dk_1$ 的贡献）：

import torch

k = torch.tensor([[1.,0.],[0.,1.],[-1.,0.],[0.,-1.]], requires_grad=True)   # k_1..k_4
v = k.clone().detach().requires_grad_(True)                                  # toy 里 v 和 k 数值相同
q = torch.tensor([[2.,0.],[0.,2.],[-2.,0.],[0.,-2.]], requires_grad=True)    # q_{4,0..3}

scores = q @ k.T / (2 ** 0.5)          # [4,4]，第 h 行是 Q_h 对 4 个 KV 位置的得分
alpha = torch.softmax(scores, dim=-1)
o = alpha @ v                          # [4,2]

o[:, 0].sum().backward()               # 只对第 0 维求和，对应下游梯度 dL/do_{4,h}=[1,0]（不是 o.sum()，那样会变成 [1,1]）
print("dk (仅 t=4 贡献):", k.grad)     # 与手算的 dk_1≈[0.272,0] 等数字对照
print("dv (仅 t=4 贡献):", v.grad)

跨 query token 的累加校验（对应 (a) 提到的 $\sum_{t\ge j}$）：要看到 $k_j,v_j$ 在多个 query token 之间的梯度累加，必须让计算图里同时存在多个 query token，并加上因果掩码——上面的单 token 例子做不到这一点。光打印一次联合 backward 的 K.grad 只能说明"算出了一个梯度"，还不足以严格验证 $dK_j^{\text{total}}=\sum_{t\ge j}dK_j^{(t)}$ 这条求和关系本身——下面把"联合 backward"和"逐个 query token 分别求梯度再手动累加"两种算法都跑一遍，对照它们是否一致：

import torch

seq_len, d = 4, 2
n_q, n_kv = 4, 2     # 真正的 GQA：每 2 个 Query head 共享 1 个 KV head
                     # （n_kv=1 会退化成 MQA 特例，repeat_interleave(n_q,...) 也只在 n_kv=1 时凑巧正确，这里改成通用写法）
n_rep = n_q // n_kv
Q = torch.randn(seq_len, n_q, d, requires_grad=True)
K = torch.randn(seq_len, n_kv, d, requires_grad=True)
V = torch.randn(seq_len, n_kv, d, requires_grad=True)

def attn_out():
    K_rep = K.repeat_interleave(n_rep, dim=1)   # 按 n_rep 展开；要求 n_q % n_kv == 0（真实 GQA 配置都满足，否则整数除法截断会导致展开后 head 数不等于 n_q，einsum 维度报错）
    V_rep = V.repeat_interleave(n_rep, dim=1)
    scores = torch.einsum('thd,shd->hts', Q, K_rep) / d ** 0.5
    causal_mask = torch.triu(torch.ones(seq_len, seq_len), diagonal=1).bool()
    scores = scores.masked_fill(causal_mask, float('-inf'))
    alpha = torch.softmax(scores, dim=-1)
    return torch.einsum('hts,shd->thd', alpha, V_rep)   # [seq_len, n_q, d]，第 0 维是 query token t

# 算法一：把所有 query token 的 loss 加在一起，一次性 backward
out = attn_out()
out.sum().backward()
dK_joint = K.grad.clone()

# 算法二：每个 query token t 的 loss 单独拿出来求梯度，再手动累加成 sum_t dK^(t)
K.grad = None
out2 = attn_out()
dK_per_t = torch.zeros_like(K)
for t in range(seq_len):
    dK_t, = torch.autograd.grad(out2[t].sum(), K, retain_graph=True)
    dK_per_t += dK_t

print("联合 backward:      ", dK_joint)
print("逐 t 分别求梯度再累加:", dK_per_t)
print("两者是否一致:", torch.allclose(dK_joint, dK_per_t))   # 应为 True，这才是对 sum_{t>=j} 这条累加关系的严格校验

RoPE 反向校验：前向文档给出的 $q,k$ 数值已经是 RoPE 之后的结果，直接拿它们搭图验证不了 RoPE——要验证 RoPE，必须在计算图里真正执行一次旋转：

import torch

def rope(x, theta):
    x1, x2 = x[..., 0], x[..., 1]
    c, s = torch.cos(theta), torch.sin(theta)
    return torch.stack([x1 * c - x2 * s, x1 * s + x2 * c], dim=-1)

q_pre = torch.tensor([1.3, 0.7], requires_grad=True)
theta = torch.tensor(0.5)

q_rope = rope(q_pre, theta)
(q_rope * torch.tensor([1., 0.])).sum().backward()   # 假设 dL/dq_rope = [1,0]

manual = rope(torch.tensor([1., 0.]), -theta)         # 按 -theta 反向旋转（本文 (f) 的公式）
print("autograd:", q_pre.grad)
print("manual  :", manual)   # 两者应该一致

这个"手推公式 + 代码验证"的组合，正是从"看懂训练机理"过渡到"能写训练代码"最实际的路径——公式保证你理解每一步在干什么，代码校验保证你写对了。

9.8 反向传播 FLOPs：把"系数 6"拆开看

前向文档提到训练 FLOPs 估算公式 $6NT$，并简单解释"前向 $2NT$，反向 $4NT$"。现在有了具体的反向传播步骤，可以把这三个 $2NT$ 分别对应到哪个矩阵乘法说清楚：

项 对应的计算 典型例子（以 $W_Q$ 为例）
前向 $2NT$ $Y=XW$ $q_\text{proj}=X W_Q$
反向 $2NT$（对权重的梯度） $\dfrac{\partial L}{\partial W}=X^\top\dfrac{\partial L}{\partial Y}$ $\dfrac{\partial L}{\partial W_Q}=X^\top\dfrac{\partial L}{\partial q_\text{proj}}$
反向 $2NT$（对输入的梯度） $\dfrac{\partial L}{\partial X}=\dfrac{\partial L}{\partial Y}W^\top$ $\dfrac{\partial L}{\partial X}\big|_Q=\dfrac{\partial L}{\partial q_\text{proj}}\,W_Q^\top$

三次矩阵乘法形状完全对称（都是 $[\text{token 数}, d]\times[d,d']$ 或转置形式），每次 FLOPs 都约等于 $2NT$（$N$=该矩阵参数量，$T$=token 数），加起来约为 $6NT$。这也解释了为什么"对输入的梯度"这一项不能省——即使某一层的权重已经不需要更新（比如冻结），只要它前面还有需要训练的层，$\dfrac{\partial L}{\partial X}$ 这一项梯度也必须算，否则梯度传不到更前面的层。

但要强调：$6NT$ 只在"参数矩阵的三次矩阵乘法"这个简化模型下近似成立，不是精确的 FLOPs 恒等式。它忽略或粗略处理了：attention 里和序列长度平方相关的 $S^2$ 项（前向文档七节单独算过）、softmax/RMSNorm/RoPE/激活函数这些非矩阵乘法的开销、Embedding 查表（不像普通线性层那样对每个 token 做一次完整的稠密矩阵乘法）、优化器更新本身的开销，以及梯度检查点带来的前向重算。更准确的理解是："$6NT$ 是参数量主导时的量级估算"，不是逐项精确相加的恒等式。

9.9 一次完整训练 step 的伪代码

下面是框架无关的伪代码。如果照抄成 PyTorch，要注意 torch.nn.functional.cross_entropy 默认要求类别维在第二维，不能直接传 [B,S,V] 配 [B,S]，需要先展平（有 padding 的话还要设置 ignore_index 跳过无效 token）：

for batch in dataloader:
    tokens, targets = batch                     # tokens: [B, S], targets: [B, S]（错位一位）

    # ---- 前向（对应两篇前向文档的内容）----
    logits = model(tokens)                       # [B, S, 128256]

    # ---- Loss（本文第二节）----
    # PyTorch 实际写法：cross_entropy(logits.reshape(-1, V), targets.reshape(-1), ignore_index=pad_id)
    loss = cross_entropy(logits, targets)

    # ---- 反向（本文第三～六节，框架自动完成链式法则）----
    loss.backward()
    # 框架内部做的事情，从后往前，正是本文 3→4→5→6 节的顺序：
    #   dL/dlogits → LM Head 反向 → Final RMSNorm 反向
    #   → 第32层 Block 反向 → ... → 第1层 Block 反向 → Embedding 反向（数据梯度行稀疏）

    # ---- 优化器更新 ----
    optimizer.step()      # 用每个参数的 .grad 更新参数（Adam 还会维护一阶/二阶矩）
    optimizer.zero_grad() # 清空梯度，避免和下一个 batch 的梯度叠加

框架（PyTorch/JAX）自动帮你做的，正是本文手推的这一整套公式；理解了这套公式，再看 loss.backward() 内部或者手写一个 Transformer 训练循环时，就知道每一行梯度对应的是前向的哪一步、为什么某些地方要做梯度累加（GQA、SwiGLU、残差）、为什么某些地方梯度是稀疏的（Embedding）。

9.10 简单提一句：训练显存为什么比推理大得多

推理和训练要保存的其实是两套不同的内存结构，不是"训练在推理的基础上多存一点"：

  • 推理（自回归 decode）：参数 + 当前步的临时激活 + 跨生成步骤保留的 KV Cache（每一层都要留，前向文档六、七节算过，LLaMA-3 8B 在 8K 上下文、batch=1、BF16 精度下约 1GB；batch 增大或换精度会等比例变化）。推理不需要反向传播，所以不会保留 softmax 权重、SiLU 中间值这些只有 backward 才用得到的量。
  • 训练：参数 + 梯度 + 优化器状态 + 为反向传播保存或重算的激活。标准的整段序列训练通常一次前向就算完整个序列的 Q/K/V/attention/FFN，不需要像自回归 decode 那样跨步骤缓存 KV；真正的训练显存开销是下面这几项：
  1. 反向传播要用到的中间激活（比如 RMSNorm 的 $n_i$、softmax 的 $\alpha$、SiLU 的 $\sigma(G)$——本文推导里出现过的这些中间量，前向时都要留着，反向才能用），这也是为什么"梯度检查点（gradient checkpointing）"要用算力换显存：不存这些中间激活，反向时重新算一遍。（不同实现保留的粒度不同：普通 attention 实现会显式保留完整的 softmax 矩阵 $\alpha$，完整逻辑形状是 $[B,H,S,S]$（$H=n_q=32$ 是 Query head 数——GQA 下 attention 权重仍然按 Query head 数存在，不会因为 KV head 少而变小；前面为了突出 $S^2$ 这一项只简写成 $[S,S]$，省略 $B,H$ 会明显低估这块显存的实际规模）；前向文档提到的 FlashAttention 这类融合 kernel 并不保留完整的 $\alpha$，只保留更小的统计量（如每行的最大值、归一化常数），反向时在 SRAM 里分块重新计算所需的 $\alpha$，这是它省显存的另一个来源。）
  2. 每个参数的梯度（元素数量和参数相同，但字节数不一定相同——梯度常用 FP32 存储，即使参数本身是 BF16）。
  3. 优化器状态（Adam 要存一阶矩和二阶矩，各和参数同样大小）。

以混合精度 + AdamW 为例，几种常见配置按每参数字节数拆开算（权重 / 梯度 / Adam 一阶矩 $m$ / Adam 二阶矩 $v$ / FP32 master weight）：

配置 权重 梯度 $m$ $v$ master weight 合计 相对 BF16 权重(2B)
无 master weight，梯度用 BF16 2 2 4 4 0 12 6×
无 master weight，梯度用 FP32 2 4 4 4 0 14 7×
带 FP32 master weight 的混合精度（BF16 权重+梯度 + FP32 master + Adam） 2 2 4 4 4 16 8×
梯度和 master weight 都用 FP32 2 4 4 4 4 18 9×

不同实现不会任意组合这几项，但也没有统一的"标准"配置——有的训练栈长期保存 FP32 参数、计算时临时转成 BF16；有的长期存 BF16 参数、另外维护一份 FP32 master weight；有的 BF16 训练干脆不留独立 master copy；ZeRO/FSDP 等分布式优化器还会对参数、梯度、状态分别选择精度和分片方式。16 字节/参数（表中第三行）是文献里常被引用的一个混合精度配置，但不能说它是"最常见"的统一口径。总的来说，在表格假设的"未分片、常规 FP32 AdamW 状态"这个前提下，一般落在 6～9 倍之间，比"权重+梯度+优化器各算一份"这种粗略估计的 3~4 倍要大得多；如果用了 8-bit optimizer、ZeRO/FSDP 分片、optimizer offload 或其他参数主副本策略，单卡实际比例会明显偏离这个范围，不能把 6～9 倍当成所有训练系统的统一结论。ZeRO / FSDP 等显存分片策略会把这部分状态摊到多张 GPU 上，单卡实际占用要另算。这属于显存管理范畴，超出本文"反向传播数学"的范围，值得单独写一篇。

9.11 小结

LLaMA-3 8B 的反向传播 = 交叉熵梯度 $p-y$ 从 logits 出发，经过 LM Head、Final RMSNorm、32 层 Block（每层：残差直通 + SwiGLU 反向（gate/up 分支梯度相加）+ RMSNorm 反向 + 注意力反向（O 投影 → concat 拆分 → 对 V 加权求和反向【dV 在此按 GQA 共享关系 + 跨 query token 累加】→ softmax 反向 → $QK^\top$ 反向得到 dQ、dK【dK 同样在此按 GQA + 跨 token 累加，不是放在 RoPE 之后才统一累加】→ RoPE 反向旋转回去 → Q/K/V 投影反向）+ 残差直通 + RMSNorm 反向），最终得到 Embedding 表的梯度（数据梯度按行稀疏，实际是否稀疏更新取决于框架实现）。核心是链式法则加"分支相加"这一条规则；GQA、SwiGLU、残差连接这三处设计在反向传播里都体现为"一个变量的梯度等于它在前向中各个去处传回来的梯度之和"。手推公式建立理解，torch.autograd 校验正确性，是从"看懂训练机理"走到"能写训练代码"最实际的路径。

十、总结

LLaMA-3 8B 在 GPT-3 架构基础上做了四项关键改进，以下按类别分述，避免把架构、FLOPs 口径、利用率数字、能耗数据混在一段里：

架构改进（四项）

  • Pre-RMSNorm：去掉均值计算和偏置，Pre-Norm 顺序让梯度有直通路径，深层训练更稳定。
  • GQA：把 KV Cache 从"假想的同宽度（4096 维、32 头）MHA 版本"的 4 GiB（8K 上下文）压到 1 GiB（降为 1/4——这个对比基准是同宽度的假想 MHA，不是 GPT-3 实际的 96 头/12288 维/96 层配置），有助于提高可并发的 batch 规模和推理吞吐（具体提升幅度还取决于 batch size、显存带宽、attention kernel 实现等因素）。
  • RoPE：把位置旋转进 Q/K 点积，天然表达相对距离并支持长上下文扩展。$\theta_\text{base}=500{,}000$ 的一个合理解释（本文的机理推断，不是已证实的官方设计记录）是拉长部分中频维度对的旋转周期，使其在 8K 上下文里保持不完整绕圈（放慢倍数按 $50^{i/64}$ 逐维度变化，从 1 倍到约 47 倍不等，不是所有维度统一或等比例放慢）。
  • SwiGLU：给 FFN 加了动态门控分支，用三次矩阵乘法换来更强的特征选择能力；中间维度 14336 可以由 Meta 公开代码里 $\lceil(8d/3\times1.3)/1024\rceil\times1024$（$d=4096$）这个公式精确算出来，不是无来源的"消融实验最优值"。

训练 FLOPs：三套并列口径，不是同一个量的区间

  • 传统简化 $6NT$：按 15T 这个基准值代入，约 $7.23\times10^{23}$ FLOPs（真实训练 token 数是"15T+"，超出 15T 的部分会使这个数字相应更大；$6NT$ 本身把 Embedding 查表参数当作参与矩阵乘法，带来约 6.5% 的高估，但同时完全没计入 attention 的 $QK^\top$、$\alpha V$ 二次项，这个遗漏量级更大）。
  • $C_\text{model,\ causal}\approx7.72\times10^{23}$：扣掉 Embedding 查表、补上 attention 二次项（causal 减半口径）后的细化模型 FLOPs。
  • $C_\text{dense-kernel}\approx8.69\times10^{23}$：同样扣掉 Embedding、补上 attention 二次项，但 attention 按完整稠密 $S^2$ 记账（对应某些未做 causal 优化的 kernel 可能实际执行的量）。

后两者都比 $7.23\times10^{23}$ 更大，说明 Embedding 高估和 attention 二次项遗漏这两处误差抵消后，净效应更可能是低估而非高估；后两个数字是两种不同记账口径，不是同一个量的置信区间上下界，也都不是"真实 FLOPs"——依然没有计入真实序列长度分布/打包、梯度检查点重算、被丢弃的训练步等因素，且隐含了训练序列有效长度接近 8192 这个假设。

端到端利用率：对应上面三套 FLOPs 口径的三个数字，不是同一个 MFU 的置信区间

  • 按简化 $6NT$：约 15.6%——可以合理称为 MFU。
  • 按 $C_\text{model,\ causal}$：约 16.7%——同样可以合理称为 MFU。
  • 按 $C_\text{dense-kernel}$：约 18.8%——这个数字不应该继续叫 MFU，因为分子混入了某些未做 causal 优化的 kernel 可能额外执行的 masked 区域，更接近一种偏 HFU 方向、但仍不完整（未计入梯度检查点重算、优化器更新等）的硬件利用率参考数字。

能耗与碳排放（均为 Meta 披露/推算数字，非电表读数）

Meta 披露的预训练计算是 1.3M GPU 小时（H100，700W 功耗核算口径），据此推算约 910 MWh 用电；Meta 披露碳排放约 390 tCO₂eq。
