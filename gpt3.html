二、batch_size × 维度：这个乘积意味着什么？

$$3,200,000 \text{ (tokens)} \times 12,288 \text{ (dims)} \approx 3.93 \times 10^{10} \text{ (elements)}$$

这个乘积体现在三个方面：

1. 显存压力

使用 FP16（每个数占 2 字节），仅存储一个 $[T,d]$ 形状的激活张量（比如某一层输出的隐藏状态）就需要：

$$3.2 \times 10^6 \times 12288 \times 2 \text{ 字节} \approx \textbf{78.6 GB}$$

这只是一份 $[T,d]$ 张量的大小，不是"一层"要保存的全部激活——一层实际还有 Q/K/V、注意力中间量、FFN 里 $4d$ 维的中间激活、每次归一化的输入等，真正训练时全部加起来远不止 78.6GB（用梯度检查点可以少存一些，代价是反向时要重算）。即便只看这一份 78.6GB，一张 H100（80GB 显存）也几乎被撑满，这也是为什么大模型训练要靠数据并行（把 320 万个 token 按 batch 维切开、分给不同 GPU）、序列并行、流水线并行等多种并行方式配合，把总激活量摊到多张显卡上——张量并行切分的主要是权重矩阵和隐藏维度，不是直接把 token 这一维切开分配，不能笼统地说"用张量并行分散 320 万个 token"。

2. 矩阵乘法的规模（等价总运算量口径，不是真实执行时的单次 GEMM 形状）

每一层的核心运算 $Y = XW$，把全部 320 万个 token 展平成一个等价的整体运算量来看：

  • 输入 $X$：$[3,200,000,\ 12,288]$（极其"高瘦"的矩阵，每行代表一个 token）
  • 权重 $W$：$[12,288,\ 12,288]$（方阵）
  • 输出 $Y$：$[3,200,000,\ 12,288]$

需要说明：真实训练里不会有哪张 GPU 真的执行一次输入 320 万行的单次 GEMM——3.2M 是全局/有效 batch size，实际会被拆到多个数据并行副本、每张 GPU 的局部 batch、多个 microbatch（可能还叠加梯度累积），张量并行下权重矩阵和隐藏维度还会被切分到不同 GPU，流水线并行则把不同层分配到不同 GPU（GPT-3 论文本身也提到模型是沿深度和宽度分布到多张 GPU 上的）。上面这个 $[3.2\text{M},12288]$ 只是"把所有 token 展平后的等价总运算量"表示，用来算 $2Tmn$ 这个总 FLOPs 是没问题的，但不能理解成"训练时真的有一次矩阵乘法的实际输入形状就是这样"。

3. 梯度下降的平滑度

320 万个 token 的梯度平均，统计信息更丰富、梯度噪声更小；对于固定模型规模，这确实是大 batch 有时能配合更大学习率的原因之一。但这里不适合把"3.2M 大 batch"和"6e-05"直接当成这条一般规律在 GPT-3 上的体现：GPT-3 论文 Table 2.1 列出了从 1.25 亿到 1,750 亿参数的 8 个模型，趋势是模型越大，batch size 越大、但学习率反而越小——175B 这个模型在 8 个模型里 batch size 最大（3.2M），学习率却是这组里最小的（6e-05），不是"较大学习率"。更准确的理解是：大模型通常需要更大的 batch（配合更小的学习率）来维持训练稳定，两者是模型规模增大后同时出现的变化，不是"batch 变大→学习率也跟着变大"这样的因果关系；训练稳不稳定也不只由 batch size 决定，还依赖优化器选择（比如 Adam 的自适应缩放）、learning rate warmup、梯度裁剪，以及训练所处的阶段。

三、完整前向传播：用具体数值走一遍

先追踪 1 个 token，感受形状；最后乘以 batch size 感受总规模。

第一步：Embedding 查表

$$E \text{ 的形状} = [50257,\ 12288] \quad \text{参数量} = 50257 \times 12288 = \textbf{6.176 亿}$$

取出第 42 行，得到初始向量：

$$x_0 \text{ 的形状} = [1,\ 12288]$$

加位置编码（形状不变）：

$$x_0 = \text{Embedding} + \text{Learned Positional Embedding（学习式位置嵌入）} \quad [1,\ 12288]$$

（GPT-3 用的是学习式位置嵌入——一张 $[\text{上下文长度}, 12288]$ 的可训练表，按位置索引查表，不是 Transformer 原论文里固定的正余弦位置编码。）

第二步：一层 Transformer Block 的完整计算

Layer Norm

形状不变：$[1,\ 12288] \rightarrow [1,\ 12288]$

这里的 Layer Norm 不是矩阵乘法，而是对当前 token 的 12288 维隐藏向量做归一化。

假设当前 token 的向量是：

$$x = [x_1, x_2, \dots, x_{12288}]$$

先计算这 12288 个数的平均值：

$$ \mu = \frac{1}{d}\sum_{i=1}^{d} x_i $$

再计算方差：

$$ \sigma^2 = \frac{1}{d}\sum_{i=1}^{d}(x_i-\mu)^2 $$

然后把每一维标准化：

$$ \hat{x}_i = \frac{x_i-\mu}{\sqrt{\sigma^2+\epsilon}} $$

最后再乘上可训练的缩放参数 $\gamma_i$，加上可训练的平移参数 $\beta_i$：

$$ y_i = \gamma_i \hat{x}_i + \beta_i $$

其中 $d=12288$，$\epsilon$ 是一个很小的数，用来防止除以 0。$\gamma$ 和 $\beta$ 的形状都是 $[12288]$。

直观理解：Layer Norm 先把一个 token 的 12288 个特征值 $\hat x$ 拉到大致均值为 0、方差为 1 的稳定范围；严格说这个"均值0方差1"说的是标准化后的 $\hat x$，不是加上可训练的 $\gamma,\beta$ 之后的最终输出 $y$——训练中 $\gamma,\beta$ 可以让 $y$ 的均值和方差偏离 0 和 1，这是模型学习到的缩放/平移，不影响标准化这一步本身的作用。$y$ 才是真正交给 Attention 或 FFN 继续计算的量。

Multi-Head Attention：4 次带参数的投影矩阵乘法，外加注意力内部的 $QK^\top$ 和 $AV$

这里说的"4 次"专指 $XW_Q,XW_K,XW_V,HW_O$ 这四个带参数的线性投影；除此之外，Attention 内部还有 $QK^\top$（算得分）和 $AV$（加权求和）两类矩阵乘法——它们不涉及可训练参数，但同样消耗 FLOPs（第四节会把这部分单独算出来）。

生成 Q、K、V（各一次）：

$$Q = x \cdot W_Q \quad [1,\ 12288] \times [12288,\ 12288] \rightarrow [1,\ 12288]$$

$W_Q,\ W_K,\ W_V$ 各有参数量：$12288^2 = \textbf{1.51 亿}$

切分为 96 个头，每头 128 维：

$$[1,\ 12288] \rightarrow \text{96 个头，每头} [1,\ 128]$$

小知识点：为什么是 96 个头？

GPT-3 175B 的隐藏维度是 $d_{\text{model}}=12288$，注意力头数是 $n_{\text{heads}}=96$，所以每个头的维度是：

$$ d_{\text{head}}=\frac{d_{\text{model}}}{n_{\text{heads}}}=\frac{12288}{96}=128 $$

这里的 96 不是严格数学推导出来的最优值，更像是经验、实验和硬件效率共同作用后的设计选择。实际设计大模型时，常见做法是让每个 head 保持一个比较合适的维度，例如 64 或 128，然后根据总隐藏维度反推头数。

如果只分成 1 个头：

$$ n_{\text{heads}}=1,\quad d_{\text{head}}=12288 $$

模型就只有一套注意力分布。它仍然可以计算 $QK^T$，但所有关系都要挤进同一个 attention map 里，表达模式会比较单一。

如果分成 12288 个头：

$$ n_{\text{heads}}=12288,\quad d_{\text{head}}=1 $$

每个头只有 1 维，单个头的 query/key 只是一个数字，能表达的相似度太弱。同时会产生大量很小的 softmax 和调度开销，工程效率也会很差。

所以头数的选择一般是在两边之间找平衡：

  • 头太少：注意力模式太单一。
  • 头太多：每个头维度太小，表达力下降，kernel 调度和 softmax 开销变大。
  • 常见分析方法：固定模型规模做 ablation，对比不同头数的训练 loss、下游任务效果、显存占用、KV cache 成本和 GPU kernel 效率。

一句话：GPT-3 的 96 个头不是公式证明出的最优解，而是在 $12288$ hidden size 下选择 $128$ head dimension 后得到的工程经验平衡点。

每头计算注意力得分：

$$\text{score} = Q_{head}K_{head}^T = [1,128] \times [128,1] = \text{一个标量（对某一个 key 而言）}$$

这只是 query 和某一个 key 的得分；实际上位置 $i$ 要对它能看到的所有历史位置（$j\le i$，长度为 $i$）各算一次，得到的是一个长度为 $i$ 的得分向量，再整体做 softmax，不是只算一个标量就结束。Softmax 后加权求和，每头输出 $[1,\ 128]$，96 头拼接回 $[1,\ 12288]$。

多头注意力完整计算（以"黑猫睡"为例，计算"睡"的输出）

小注解：$q_3$ 里的 3 是什么？

在例子“黑猫睡”里：

$$ x_1=\text{黑},\quad x_2=\text{猫},\quad x_3=\text{睡} $$

所以 $q_3$ 表示第 3 个 token，也就是“睡”这个位置生成的 query 向量。这里的下标 3 是位置序号，不是第 3 维，也不是第 3 个 attention head。

同理，$k_1,v_1$ 来自“黑”，$k_2,v_2$ 来自“猫”，$k_3,v_3$ 来自“睡”。计算“睡”的注意力输出时，会用 $q_3$ 分别和 $k_1,k_2,k_3$ 做相似度计算：

$$ q_3k_1^T,\quad q_3k_2^T,\quad q_3k_3^T $$

这表示“睡”这个 token 分别看“黑”“猫”和它自己。因为 GPT 是因果模型，所以第 3 个 token 只能看位置 1、2、3，不能看未来的位置 4、5、...。

教科书公式 8.10～8.14：

$$q_i = x_i W^Q \quad k_j = x_j W^K \quad v_j = x_j W^V \tag{8.10}$$

$$\text{score}(x_i, x_j) = \frac{q_i k_j^T}{\sqrt{d_k}} \tag{8.11}$$

小知识点：为什么原书写 $q_i \cdot k_j$，工程里常写 $q_i k_j^T$？

原书里的 $q_i \cdot k_j$ 是向量点积写法，数学上没有问题。点积符号 $\cdot$ 本身就表示两个向量逐维相乘后求和：

$$ q_i \cdot k_j = \sum_{m=1}^{d_k} q_{i,m} k_{j,m} $$

如果从矩阵形状看，把 $q_i$ 和 $k_j$ 都看成行向量：

$$ q_i:[1,d_k] \quad k_j:[1,d_k] $$

那么要得到一个注意力分数标量，就需要把 $k_j$ 转置：

$$ q_i k_j^T:[1,d_k]\times[d_k,1]\rightarrow[1,1] $$

所以：

$$ q_i \cdot k_j \equiv q_i k_j^T $$

区别只是视角不同：$q_i \cdot k_j$ 是数学向量内积写法，$q_i k_j^T$ 是矩阵乘法/工程实现写法，更容易和代码里的 $QK^T$ 对上。真正不严谨的是写成没有点积符号、也没有转置的 $q_i k_j$。

$$\alpha_{ij} = \text{softmax}(\text{score}(x_i, x_j)) \quad \forall j \leq i \tag{8.12}$$

$$\text{head}_i = \sum_{j \leq i} \alpha_{ij} v_j \tag{8.13}$$

$$a_i = \text{head}_i W^O \tag{8.14}$$

正确理解 8.10～8.14：这是一套完整的单头注意力公式

首先澄清一个容易犯的错误：8.10～8.14 本身量纲是自洽的（各步骤的张量形状都能对上）。严格来说，(8.12) 的 $\text{softmax}$ 没有像后面 8.12′ 那样显式写出归一化用的分母求和集合，要靠旁边 $\forall j\le i$ 这个条件才能推断出"对哪些位置归一化"；这一点在 8.12′ 里补齐了。所以准确的说法是"量纲没有问题，但归一化范围需要读者从上下文推断，不是公式本身写得完全显式"。

单头注意力的含义是：用 token 的全部 $d_{\text{model}}$ 维度跑一套 QKV 计算，整个 $d_{\text{model}}$ 就是唯一的一个头在处理。此时：

$$W^Q, W^K, W^V \in \mathbb{R}^{d_{\text{model}} \times d_{\text{model}}}$$

$$q_i,\ k_j,\ v_j \in \mathbb{R}^{1 \times d_{\text{model}}}$$

$$\text{head}_i = \sum_{j \le i} \alpha_{ij} v_j \in \mathbb{R}^{1 \times d_{\text{model}}}$$

$$a_i = \text{head}_i \cdot W^O : [1,\ d_{\text{model}}] \times [d_{\text{model}},\ d_{\text{model}}] \rightarrow [1,\ d_{\text{model}}] \quad \checkmark$$

量纲完全闭合，不需要任何额外步骤。

$\text{head}_i$ 里的 $i$ 是 token 位置（$j \le i$ 这个因果掩码就是证据），"head" 只是这个单头输出的名字——作者用 head 命名，是为了和多头场景的语义保持一致（多头里每个头也叫 head）。

单头 vs 多头的直觉区别：

单头注意力 多头注意力（GPT-3）
头数 1 96
每个头处理的维度 全部 $d_{\text{model}}=12288$ 维 切分后每头 $d_{\text{head}}=128$ 维
W^Q 形状 $[12288, 12288]$ 每头 $[12288, 128]$
head_i 维度 $12288$ 每头 $128$，拼接后 $12288$

$128 \ne 12288$ 的冲突从哪里来？ 只在把这套公式套用到多头场景（每头 $W^Q$ 已切成 $[12288, 128]$）却不加拼接步时才会出现。这是应用时遗漏了拼接步骤的问题，不是公式 8.10～8.14 本身的错误。

为什么还要补一套修正公式（8.10′～8.15′）？ 原版 8.10～8.14 是自洽的单头模板，但它没有显式体现多头——头编号不出现在任何符号里，读者无法直接看出如何扩展到多头。修正版的目的是把头编号 $(c)$ 和位置下标 $i,j$ 彻底分开写清楚，同时把缺失的拼接步骤（8.14′）和输出投影（8.15′）显式列出，让多头计算流程在符号层面完整可见。

修正版：显式多头注意力公式系列（8.10′～8.15′）

约定：头数 $h=96$，$d_{\text{model}}=12288$，每头维度 $d_{\text{head}}=d_{\text{model}}/h=128$。上标 $(c)\in\{1,\dots,h\}$ 表示第 $c$ 个头；下标 $i$ 为 query 位置、$j$ 为 key/value 位置。两个维度各占一个符号位，全篇不复用。

说明：头编号用上标 $(c)$ 是为了和位置下标 $i,j$ 在视觉上分到上/下两层而做的消歧选择，并非业界标准记号。最经典的 Vaswani(2017) 反而用下标 $\text{head}_i$ 表示第 $i$ 个头——这也正是原文 $\text{head}_i$ 把「头」和「位置」记号撞车的根源。字母可随意，关键是「头维度与位置维度永不复用」并在开头声明。

三条简化前提（GPT-3 特例 / 教学抽象，需显式标明）：

声明 内容 影响
维度合一 一般注意力允许 $d_k\ne d_v$、缩放只用 key 维 $d_k$；本文代入 GPT-3 恰有 $d_k=d_v=d_{\text{head}}=128$，故统一写 128。 缩放因子、value 维、单头输出维
缩放用 key 维 (8.11′) 的缩放是 $\sqrt{d_k}=\sqrt{128}$，不是 $\sqrt{d_{\text{model}}}$。 (8.11′)、矩阵形式
省略 bias 投影写成 $xW$ 是教学抽象（bias 为 $O(d)$ 量级，参数量统计中可忽略）；GPT-3 实际实现为 $xW+b$。 全部投影、$W^O$

(8.10′) 每头各自投影（输出 128 维；完整实现为 $x_iW^{Q,(c)}+b^{Q,(c)}$，此处略去 bias）：

$$q_i^{(c)} = x_i\,W^{Q,(c)},\quad k_j^{(c)} = x_j\,W^{K,(c)},\quad v_j^{(c)} = x_j\,W^{V,(c)} \tag{8.10'}$$

$$W^{Q,(c)},W^{K,(c)},W^{V,(c)}\in\mathbb{R}^{12288\times128} \;\Rightarrow\; q_i^{(c)},k_j^{(c)},v_j^{(c)}\in\mathbb{R}^{1\times 128}$$

(8.11′) 该头内得分（缩放因子为 key 维 $\sqrt{d_k}=\sqrt{128}$）：

$$\text{score}^{(c)}(x_i,x_j)=\frac{q_i^{(c)}\,\big(k_j^{(c)}\big)^{\!\top}}{\sqrt{d_k}} \qquad [1,128]\times[128,1]\to[1,1] \tag{8.11'}$$

(8.12′) 因果 softmax（分母显式对 $j'\le i$ 求和，故无歧义）：

$$\alpha_{ij}^{(c)}=\frac{\exp\!\big(\text{score}^{(c)}(x_i,x_j)\big)}{\displaystyle\sum_{j'\le i}\exp\!\big(\text{score}^{(c)}(x_i,x_{j'})\big)},\quad \forall\,j\le i;\qquad \alpha_{ij}^{(c)}=0\ (j>i) \tag{8.12'}$$

(8.13′) 单头输出（128 维，下标 $i$=位置，上标 $(c)$=头）：

$$\text{head}_i^{(c)}=\sum_{j\le i}\alpha_{ij}^{(c)}\,v_j^{(c)}\;\in\mathbb{R}^{1\times 128} \tag{8.13'}$$

(8.14′) 跨头拼接（原文缺失、修正核心：头上标在此被收掉，结果只剩位置下标）：

$$o_i=\operatorname{Concat}\!\big(\text{head}_i^{(1)},\dots,\text{head}_i^{(h)}\big)\in\mathbb{R}^{1\times 12288} \tag{8.14'}$$

(8.15′) 输出投影（$W^O$ 作用在拼接后的 12288 维上，量纲自洽；完整实现含 $+b^O$）：

$$a_i = o_i\,W^O,\qquad W^O\in\mathbb{R}^{12288\times12288}\;\Rightarrow\; a_i\in\mathbb{R}^{1\times 12288} \tag{8.15'}$$

对照原文：原文单头公式里的 $\text{head}_i$ 本身是 12288 维、量纲没有问题（见上面第 230～244 行）。如果读者把这个符号直接套用到多头场景，又误以为它指的是"每个头各自的 128 维输出"，就会觉得 $a_i=\text{head}_i W^O$ "算不通"——但这是同一个符号在两种场景下被赋予了不同含义导致的误读，不是原公式本身的缺陷（呼应第 257 行的说明）。修正版用 $\text{head}_i^{(c)}$ 专指"第 $c$ 个头在位置 $i$ 的 128 维输出"，用 $o_i$ 专指"拼接后的 12288 维"，拆出 (8.14′) 这一步拼接后，两个符号各司其职，就不会再产生这种混淆。

矩阵 · 整序列形式（$X\in\mathbb{R}^{n\times d_{\text{model}}}$，$n$ 个 token 一起算）：

$$Q^{(c)}=XW^{Q,(c)},\quad K^{(c)}=XW^{K,(c)},\quad V^{(c)}=XW^{V,(c)}\;\in\mathbb{R}^{n\times 128}$$

$$A^{(c)}=\operatorname{softmax}_{\text{row}}\!\left(\frac{Q^{(c)}\big(K^{(c)}\big)^{\!\top}}{\sqrt{d_k}}+M\right)\in\mathbb{R}^{n\times n},\qquad M_{ij}=\begin{cases}0,& j\le i\\[2pt]-\infty,& j>i\end{cases}$$

其中 $\operatorname{softmax}_{\text{row}}$ 表示逐行归一化：对 $[n,n]$ 分数矩阵的每一行（固定 query 位置 $i$、沿所有 key 位置 $j$）做 softmax，每行之和为 1。这与 (8.12′) 分母 $\sum_{j'\le i}$ 是同一件事的矩阵写法。

$$H^{(c)}=A^{(c)}V^{(c)}\in\mathbb{R}^{n\times 128},\qquad \operatorname{MultiHead}(X)=\operatorname{Concat}\!\big(H^{(1)},\dots,H^{(h)}\big)\,W^O\in\mathbb{R}^{n\times 12288}$$

逐位置形式的 $a_i$ 即 $\operatorname{MultiHead}(X)$ 的第 $i$ 行；掩码 $M$ 是 (8.12′) 中 $\forall j\le i$ 的矩阵写法。

与「大矩阵切块」视角对接：原文说的 $W^Q[12288,12288]$ 切成每头 $[12288,128]$，就是把 $h$ 个头的投影矩阵横向拼接——

$$W^Q=\big[\,W^{Q,(1)}\ \big|\ \cdots\ \big|\ W^{Q,(h)}\,\big]\in\mathbb{R}^{12288\times12288}$$

「一次大乘法 $XW^Q$ 再切 96 段」与「跑 96 次 $XW^{Q,(c)}$」数值完全等价：前者是工程并行写法，后者是 (8.10′) 的数学定义。

Step 2：计算得分（除以 $\sqrt{128} \approx 11.3$）

除以 $\sqrt{d_k}$ 的直接作用是控制 $QK^\top$ 点积的方差：如果 Q、K 各分量方差是 1，未缩放的点积方差会随维度 $d_k$ 线性增长，维度越高点积越容易偏大；偏大的数值送进 softmax 会让分布迅速饱和（趋近 one-hot），饱和区域的梯度非常小。"防止梯度消失"只是这个饱和效应的下游结果，缩放本身直接解决的是"点积方差随维度增长、导致 softmax 饱和"这个问题。

$$\text{score}(x_3, x_3) = \frac{0.71}{11.3} \approx 0.063$$

四、乘上 Batch Size：真实训练规模

训练时一个完整 batch 覆盖 320 万个 token（不是物理上同时驻留或单次执行，而是一个 step 里累计处理的 token 总数——具体怎么拆到多张 GPU、多个 microbatch 上是第二节已经说明过的工程细节），把这些 token 展平后等价的总矩阵乘法规模是：

矩阵乘法 等价形状（总运算量口径）
$X \cdot W_Q$ $[3200000,\ 12288] \times [12288,\ 12288]$
$X \cdot W_1$ $[3200000,\ 12288] \times [12288,\ 49152]$
$X \cdot W_2$ $[3200000,\ 49152] \times [49152,\ 12288]$

这里再次强调：这是把 320 万个 token 展平后的等价总运算量表示，不是训练时某一次真实执行的单个 GEMM 形状——实际会拆到多个数据并行副本、每张 GPU 的局部 batch/microbatch，以及张量并行、流水线并行等切分方式上，用总 FLOPs（$2Tmn$）来理解这张表是准确的，用"这就是一次真实矩阵乘法的输入规模"来理解则不准确。

一次 $W_Q$ 乘法的 FLOPs：

$$2 \times 3,200,000 \times 12,288 \times 12,288 \approx \textbf{966 万亿次}$$

一层 Block 的线性层 FLOPs：

$Q,K,V,O$ 四个矩阵都是 $[12288,12288]$ 规模（各算一次 966 万亿）；但 $W_1,W_2$ 分别是 $[12288,49152]$ 和 $[49152,12288]$，比 $W_Q$ 大 4 倍，各自的 FLOPs 也是 966 万亿的 4 倍，不能按同样大小直接相加。按等价 $d\times d$ 规模换算，一层一共是：

$$\underbrace{4}_{W_Q,W_K,W_V,W_O\text{（各 1 倍）}} + \underbrace{2\times4}_{W_1,W_2\text{（各 4 倍）}} = 12 \text{ 个等价规模}$$

$$12 \times 966\text{万亿} \approx \mathbf{1.160\times10^{16}}\ \text{次}$$

注意力本身的 $QK^\top$ 和加权求和（$AV$）也有 FLOPs，容易被漏算：对稠密注意力，这两步合计约为每层 $4TSd$（$S$ 是序列长度，这里取 GPT-3 常见的 2048）：

$$4 \times 3.2\times10^6 \times 2048 \times 12288 \approx 3.22\times10^{14}\text{ 次/层，} 96\text{ 层约} 3.09\times10^{16}\text{ 次}$$

这一项比线性层小得多，但不是 0。另外需要说明：GPT-3 并不是全部 96 层都用完整的稠密因果注意力，论文里提到是稠密注意力和局部带状稀疏注意力交替使用的，所以这里按"全部稠密"算出的注意力 FLOPs 是一个偏高的上界，不是精确值。

96 层线性层 + 注意力 FLOPs 合计（前向传播）：

$$96 \times 1.160\times10^{16} + 3.09\times10^{16} \approx 1.113\times10^{18} + 0.031\times10^{18} \approx 1.14\times10^{18} \text{ 次}$$

加上反向传播（约为前向的 2 倍），一个 step 总计：

$$\approx 3.4 \times 10^{18} \text{ 次浮点运算}$$

（这个数量级和常用的经验估算 $6NT$ 基本吻合：用全模型参数量 $N\approx175\times10^9$、$T=3.2\times10^6$，$6NT\approx3.36\times10^{18}$，两种算法结果一致，说明这不是巧合，而是同一套"参数量主导 FLOPs"的逻辑。）

需要说明：$3.4\times10^{18}$ 是主导项的近似值，不是把每个算子都逐项精确相加的结果——还没单独算 Unembedding、LayerNorm、GELU、bias 加法、softmax/交叉熵、以及 Embedding 查表反向这些开销。以 Unembedding 为例，$2TdV=2\times3.2\times10^6\times12288\times50257\approx3.95\times10^{15}$，前向+反向约 $1.19\times10^{16}$，占 $3.4\times10^{18}$ 的约 0.35%——量级上完全不影响这里的结论，但"一个 step 总计"更准确的理解是"由参数矩阵和注意力 $S^2$ 项主导的近似"，不是所有算子逐一相加的精确总和。）

五、FLOPs 与电能消耗的关系

连接 FLOPs 和电能的桥梁

核心指标是能效比：

$$\text{能效} = \frac{\text{FLOP/s}}{\text{Watt}}$$

根据 Epoch AI 研究，GPU/TPU 能效历史上每两年翻一倍。以 FP16 格式，NVIDIA H100 达到每瓦 $1.4 \times 10^{12}$ FLOP/s，Meta MTIA 达到 $2.1 \times 10^{12}$ FLOP/s。

换算公式

$$\text{电能（焦耳）} = \frac{\text{总 FLOPs}}{\text{FLOP/s per Watt}}$$

$$\text{电度数（kWh）} = \frac{\text{电能（焦耳）}}{3,600,000}$$

用 GPT-3 真实数字推算

训练用 V100 GPU，NVIDIA 官方规格里 Tensor Core FP16 峰值约为 125 TFLOP/s（一些资料里出现的 140 并不是官方峰值，这里改用官方数字），能效约为：

$$\frac{125\times10^{12}\text{ FLOP/s}}{300\text{W}} \approx 4.17 \times 10^{11} \text{ FLOP/s per Watt}$$

按完整 batch size 折算的等效 step 数：

$$\text{等效 steps} = \frac{3 \times 10^{11} \text{ tokens}}{3.2 \times 10^6 \text{ tokens/step}} \approx 93,750 \text{ steps}$$

需要说明：这里的 $93{,}750$ 是"假设从头到尾都用完整 3.2M batch size"折算出来的等效 step 数，不是 GPT-3 实际训练的优化器更新总次数。论文提到训练早期会把 batch size 从 32K token 线性爬升到完整的 3.2M token，爬升过程持续最初的 40 亿～120 亿 token；按这个爬升过程做连续近似，实际的优化器更新次数会比 93,750 略多（大致落在 9.8 万～10.7 万这个量级，具体数字取决于 175B 模型实际采用的爬升长度和离散调度方式，论文没有披露到这个精度）。但这不影响后面的总 FLOPs 和能耗估算：

$$\sum_{\text{step}}6N\,T_{\text{step}}=6N\sum_{\text{step}}T_{\text{step}}\approx6N\times3\times10^{11}$$

只要每个 step 处理的 token 数加总仍是 3,000 亿，主干模型 FLOPs 总量（$6NT$ 这套近似）就与具体怎么拆分成多少个 step、每个 step 多大无关。但"总电能也同样无关"这个结论只在下面这套理想化假设下成立：真实电能 $E=\sum_s P_s\,t_s$，如果 batch 较小的早期 step 里 GPU 利用率更低、通信占比更高、kernel 效率更差，或者每个 step 存在不随 batch 大小变化的固定开销（比如优化器更新这类按 step 发生、不完全随 token 数线性缩放的计算），真实总电能未必和"总 FLOPs 不变"一样保持不变。下面 213 MWh 这个数字用的是"始终按固定峰值 $\text{FLOP/s per Watt}$、忽略每 step 固定开销"这个理想化模型，在这个模型内部 $E_\text{ideal}=\dfrac{\text{总FLOPs}}{\text{固定峰值 FLOP/s per Watt}}$ 确实只取决于总 FLOPs、与怎么拆分 step 无关；但这不代表真实训练的电能也对 batch 调度方式不敏感——213 MWh 这个数字本身就是"理想化设备侧估算"，不受这里讨论的 batch 爬升影响，只是这个"不受影响"是理想化模型的性质，不能推广成"真实电能也与 batch 拆分无关"这个更强的结论。

"完整 batch 等效 step"耗时（假设 1024 张 V100，用第四节修正后的、按完整 3.2M-token batch 算出的单 step FLOPs $\approx 3.4\times10^{18}$——这个耗时只对应"完整 batch、1024 张 V100、每张都跑在 125 TFLOP/s 峰值"这组假设，训练早期 batch 从 32K 逐渐爬升到 3.2M 时，实际每个 step 的 FLOPs 更小，耗时也会相应更短）：

$$\frac{3.4 \times 10^{18}}{1024 \times 125 \times 10^{12}} \approx 26.6 \text{ 秒}$$

"完整 batch 等效 step"电能（同样只对应完整 batch 这组假设，不是训练早期较小 batch 下的单 step 电能）：

$$1024 \times 300W \times 26.6s \div 3{,}600{,}000 \approx 2.27 \text{ kWh}$$

训练总电能（理想化设备侧估算：假设 GPU 持续跑在峰值算力，且只按 GPU 芯片 300W TDP 这个功率边界计算，不含服务器其他部件）：

$$93,750\ (\text{等效 steps}) \times 2.27 \approx \textbf{213 MWh}$$

（交叉验证：$93,750$ 个等效 step $\times 3.4\times10^{18}$ FLOPs/步 $\approx3.19\times10^{23}$ FLOPs，这和 Patterson 等人论文报告的 GPT-3 训练总量 $3.14\times10^{23}$ FLOPs 量级和主导项口径基本吻合——但这只能排除数量级错误，不能说"证明了架构推导本身是自洽的"：两边的估算都主要由参数量 $N$、token 数 $T$ 以及"训练约为 $6NT$"这套关系决定，本身不是两个完全独立的验证；而且本文这里全用稠密注意力（正文已说明这是偏高的上界）、用"反向约为前向 2 倍"的近似、也没有逐项加入 Unembedding、LayerNorm、GELU、交叉熵等运算，这些简化造成的高估和遗漏造成的低估完全可能相互抵消，让总数"凑巧"接近 Patterson 的数字。这里用两位有效数字的 $3.4\times10^{18}$ 算出的差距约 1.5%，如果代入前面运算链条里未经四舍五入的单 step 结果（约 $3.4325\times10^{18}$），差距约 2.5%——但需要说明：$3.4325\times10^{18}$ 本身也不是更接近真实 GPT-3 FLOPs 的精确值，只是"在本文这套简化模型内部不做四舍五入"的结果，真正更大的不确定性来自上面说的架构简化和算子遗漏，不是要不要四舍五入这么小的差别。所以 1.5%～2.5% 这个区间不必看作精确统计量，更适合理解成"量级和主导项口径相互吻合，差距在估算误差范围内"。）

这里"213 MWh"最好不要叫"理论下限"：$125$ TFLOP/s 和 $300$W 都是规格表上的数字（分别是峰值算力和芯片额定最大功耗），两者不保证在同一个真实工作点上同时成立——GPU 跑到峰值算力时实际功耗不一定恰好是 300W。所以 213 MWh 更准确的定位是"基于规格表峰值算力和 TDP 算出的理想化估算"，不是一个经过测量证明的严格数学下限。

  1. 达成吞吐与峰值吞吐的差距：Patterson 论文给出的 GPT-3 实际训练吞吐约为 24.6 TFLOP/s（论文原文称其为 measured performance，不一定严格等同于后来文献里对 MFU 的正式定义），只有 125 TFLOP/s 峰值的约 20%，可以作为一个近似的利用率指标。这背后是显存带宽瓶颈、kernel 调度效率、GPU 间通信等待、梯度检查点重算、负载不均衡等因素共同造成的，没有性能剖析（profiling）数据无法精确拆分各自占比。达成/峰值吞吐比：$125/24.6\approx5.08$ 倍。

需要提醒：24.6 TFLOP/s 和 330W 都是 Patterson 论文针对同一个 GPT-3 训练配置给出的数字——论文并没有明确说明这两个数字是否来自严格同步采样的测量，"同时测得"这个说法比论文实际能支持的证据更强，更准确的说法是"论文针对同一训练场景分别给出的吞吐和功率输入参数"。但可以确定的是，功耗本身会随利用率、频率和负载变化而变化，这两个数字不是各自独立、可以任意搭配的常数；125 TFLOP/s 和 300W 则来自规格表，属于另一种性质的数字。上面的三项分解适合用来"解释 1,287 MWh 这个数字是怎么拼出来的"，但不代表这三个乘数在物理上彼此独立、可以脱离具体工作负载单独存在。另外，训练失败重启、超参数搜索试验、数据预处理等额外能耗，未必完整体现在"一次成功训练"的 24.6 TFLOP/s 里，这部分的不确定性本文没有进一步展开。

具体验算（用论文给出的真实吞吐和系统功率）：

$$\frac{3.14\times10^{23}}{24.6\times10^{12}/330\text{W}} \div 3.6\times10^6 \approx 1{,}170\text{ MWh}$$

再乘上论文给出的 PUE（约 1.10）：

$$1{,}170\times1.10\approx\textbf{1,287 MWh}$$

这几乎精确地还原出了 1,287 MWh 这个数字——说明它不是电表读数意义上的"实测总能耗"，而是论文基于已发布的实际训练吞吐、系统功率和 PUE 反推得到的公开估算值。

大规模长期部署下，累计推理能耗可能超过一次训练

"推理占模型生命周期能源 90%"不是针对 GPT-3 或 GPT-4o 单独测得的结论，而是 Patterson 论文里引用的行业总体口径（NVIDIA 对机器学习工作负载的估计约 80%～90%，AWS 对云端机器学习需求的估计约 90%），不保证适用于每一个具体模型。是否超过训练能耗，实际取决于"调用次数 × 每次推理能耗 × 服务年限"这三者的乘积——只有当一个模型被大规模、长期地持续调用时，累计推理能耗才可能超过一次训练，不是任何模型都必然如此。

  • 每次 GPT-4o 查询约消耗 0.3 Wh（这个数字高度依赖输入/输出长度、批处理效率和具体硬件，是一个粗略的参考估算，不是每次查询的固定值）
  • ChatGPT 每天约 1 亿次查询（同样是一个粗略的规模假设，且已经落后于最新披露的规模——OpenAI 2025 年公开信息显示其平台每天的消息量已超过 25 亿条；这里仍用 1 亿次只是为了演示"调用次数 × 单次能耗 × 服务年限"这个计算框架，不代表当前 ChatGPT 的真实调用规模，也不能直接把 25 亿乘以 0.3Wh 当作现实用电量——真实模型、请求长度和服务类型都不同）：$1\text{亿} \times 0.3\text{Wh} = \textbf{30,000 kWh/天}$
  • 一年：$30{,}000 \times 365 = 10{,}950{,}000\text{ kWh} \approx \textbf{10.95 GWh}$（这是"每次 0.3Wh、每天 1 亿次"这两个假设条件下的情景推算，不是任何厂商公布或实测的 ChatGPT 年度实际用电量），是 GPT-3 训练估算用电量（1,287 MWh $=$ 1.287 GWh）的约 8.5 倍

硬件能效在快速提升

硬件能效的提升速度，即使是同一家机构（Epoch AI）不同口径的研究，给出的数字也不一样：一项针对领先硬件、Tensor FP16 口径的统计给出"每两年翻一倍"，对应年化增长率 $2^{1/2}-1\approx41\%$；另一项按 FP32 FLOP/s ÷ TDP、覆盖更宽硬件样本（含普通 GPU 与 ML GPU）的研究给出翻倍周期约 2.7～3 年，对应年化增长率 $2^{1/2.7}-1\approx29\%$ 到 $2^{1/3}-1\approx26\%$，即约 26%～29%。可以确认的差异包括：是否只取领先设备、精度口径（Tensor FP16 vs FP32）、样本范围和时间窗口；至于两项研究的 TDP 估算方式是否也不同，本文没有找到足够的方法细节来确认，不做这个归因。本文之前提到的"年化约 28%"这个数字，数值上落在 26%～29% 这个区间内，但完整来源本文仍无法核实——仅凭数值接近不能判断它具体出自哪项研究，也可能来自其他数据集、置信区间近似，或连续/复合增长率的混用，这里不做进一步推测。另外，不管用哪个增长率，历史上的效率提升速度都不能直接当作对未来硬件效率的可靠预测，只是机械外推。

（如果只是想看"假设年化 28% 延续会怎样"这个数学示例：6 年约提升 $1.28^6\approx4.4$ 倍，14 年约提升 $1.28^{14}\approx31.7$ 倍——两者差一个数量级，说明"提升 4 倍"这类结论对时间窗口非常敏感，本文不再展开，也不建议把这类未经核实的外推当作硬件趋势的结论来引用。）

六、反向传播与训练机理

本章沿着前向传播的同一条链路倒着计算梯度，说明训练代码中 loss.backward() 实际完成了什么，并展开前文“反向传播约为前向两倍”的来源。数值演示使用一个独立的 toy 模型（3 个 token“黑猫睡”、单头、head_dim=2），因为前向章节中的 128 维向量使用省略号表示，不能直接用于精确手算。本文统一采用 GPT-3 的词表大小 $|V|=50{,}257$。

6.0 两条贯穿全文的规则（外加一条容易和它们搞混的操作）

  1. 链式法则：$y=f(x)$，已知 $\dfrac{\partial L}{\partial y}$，则 $\dfrac{\partial L}{\partial x} = \dfrac{\partial L}{\partial y}\cdot\dfrac{\partial y}{\partial x}$。
  2. 分支相加：如果同一个变量 $x$ 在前向传播中被多个地方使用（比如同一个 $x$ 既算 $y_1=f_1(x)$ 又算 $y_2=f_2(x)$），反向传播时 $x$ 收到的梯度是所有分支梯度之和。

这条规则在 GPT-3 里会在三个地方出现：残差连接（$x$ 同时走了 $F(x)$ 支路和跳过 $F$ 的直连支路）、因果注意力（一个位置 $j$ 的 $K_j,V_j$ 会被它自己以及后面被 attention mask 允许连接的 query 共同读取，梯度要跨这些 query 累加——在稠密因果注意力下这是"后面所有位置"，但 GPT-3 实际用到的局部带状稀疏层里通常只是后面一部分被掩码允许的 query，不是全部；这一点即使不用 GQA、只是标准 MHA 也一样成立；严格说具体范围取决于 attention mask 集合 $\mathcal M$ 怎么定，6.5.4 小节会展开确切条件，不是"因果"这个词本身逻辑上保证"后面所有位置"这么强的结论）；再加上 6.3 节会讲到的权重共享（$E$ 同时被输入查表和 Unembedding 两处使用）。

容易混淆的第三种情况——加法节点反向：如果 $y=a+b$，其中 $a,b$ 是两个不同的变量（不是同一个变量被用了两次），反向只是把上游梯度原样复制给两边：$da=dy,\ db=dy$，不涉及"多个分支求和到同一个变量"。6.6 节的 $x_0=E[\text{token\_id},:]+P[\text{pos},:]$ 就是这种情况——$E$ 的这一行和 $P$ 的这一行是两个不同的变量，各自拿到一份相同的梯度副本，这是加法节点的性质，和"分支相加"规则不是一回事（两者都涉及"一个节点收到梯度"，但加法节点是复制，分支相加是求和）。

6.1 一次训练 step 的完整链路

X (输入 token ids)
   │
   ▼ forward（本文第三节已讲）
logits [1, seq_len, 50257]
   │
   ▼ Loss（交叉熵，与 target token 比较）
L（标量）
   │
   ▼ backward（本文要讲的部分）
dL/dW_Q, dL/dW_K, dL/dW_V, dL/dW_O, dL/dW_1, dL/dW_2, dL/dE, dL/dPosEmb, ...
   │
   ▼ optimizer.step()

需要注意：token id 是离散整数，没有梯度可言。反向传播链路真正的终点是 Embedding 查表之后那个连续向量的梯度，最终落到 Token Embedding 矩阵 $E$ 和 Position Embedding 矩阵 $P$ 本身（6.6 节）——链路在"查表 + 相加"这个操作处就结束了。

6.2 起点：Loss 对 logits 的梯度

和本文第三节一致，交叉熵 + softmax 组合求导：

$$\frac{\partial L}{\partial \text{logits}_i} = p_i - y_i, \qquad p=\text{softmax}(\text{logits})$$

小例子（词表只有 4 个词，方便手算）：logits $=[1.5, 0.2, -0.3, 0.8]$，target 是第 0 个词。

$$p=\text{softmax}([1.5,0.2,-0.3,0.8]) \approx [0.5170,\ 0.1409,\ 0.0855,\ 0.2567]$$

$$\frac{\partial L}{\partial \text{logits}} = p-[1,0,0,0] \approx [-0.4830,\ 0.1409,\ 0.0855,\ 0.2567]$$

校验：$p$ 之和 $=1$（$0.5170+0.1409+0.0855+0.2567=1.0001\approx1$ ✓，末位是舍入误差），梯度之和 $=0$（$-0.4830+0.1409+0.0855+0.2567=0.0001\approx0$ ✓）。

平均因子：上面的 $p-y$ 是单 token、未做平均时的梯度。PyTorch 的 cross_entropy 默认 reduction="mean"，如果一个 batch 里有效 token 数是 $M$，实际梯度要多除一个 $M$：$\dfrac{\partial L}{\partial\text{logits}_{b,t}}=\dfrac{p_{b,t}-y_{b,t}}{M}$。这里第一次出现 $b,t$ 两个下标，先定义清楚：真实训练里 logits 是 $[B,S,V]$，$B$=batch size，即一个 batch 里的序列条数；$S$=序列长度，即每条序列的 token 位置数。下标 $b=1,\dots,B$ 指第几条序列，$t=1,\dots,S$ 指序列内第几个 token 位置（$t$ 沿用时间步的习惯记法）；一对 $(b,t)$ 唯一确定一个 token 位置，整个 batch 共 $B\times S$ 个，因为 padding 的存在 $M\le B\times S$。用 reduction="sum" 时才不用除。这不改变梯度方向，只改变数值尺度，但下面各节的公式默认都按不除以 $M$ 的口径推导，实现时要留意。

记号约定：从这里开始，公式按"单个 token"（一行向量）推导，形状写成 $[1,12288]$ 之类，方便对照本文第三节。真实实现里所有量都还有 batch 和序列维度（$[B,S,\cdot]$），本文公式里这些量一律省略 $(b,t)$ 下标。

loss 分三层写，不能都叫 $L$：交叉熵是可加的，本文约定

$$L_{b,t}\ (\text{单个 token 位置}) \quad\longrightarrow\quad L_b=\sum_t L_{b,t}\ (\text{单条序列}) \quad\longrightarrow\quad L=\sum_b L_b=\sum_{b,t}L_{b,t}\ (\text{整个 batch})$$

（用 reduction="mean" 时 $1/M$ 已吸收在 $L_{b,t}$ 里，不影响这个分解。）相应地，权重梯度也分三层：$\dfrac{\partial L_{b,t}}{\partial W}$ 是单个位置的贡献，$\dfrac{\partial L_b}{\partial W}=\sum_t\dfrac{\partial L_{b,t}}{\partial W}$ 是单条序列的贡献，只有 $\dfrac{\partial L}{\partial W}=\sum_{b,t}\dfrac{\partial L_{b,t}}{\partial W}$ 才是真正拿去更新权重的梯度。

为什么必须用不同记号：$L$ 是整个 batch 上的一个标量，$W$ 在计算图里只有一份，所以 $\partial L/\partial W$ 在数学上唯一地指求和之后的那个量。若单 token 那一步也写成 $\partial L/\partial W$，两行并排就得到 $\partial L/\partial W=\sum_{b,t}\partial L/\partial W$——这个等式只在 $B\times S=1$ 或梯度恒为零时成立。麻烦的是三层的形状完全相同（都和 $W$ 一样），维度检查救不了这个错，只能靠记号区分。本文 6.5 节的 toy 例子把整条序列的 3 个 query 都算全了，所以那里的矩阵式子天然处在 $\partial L_b/\partial W$ 这一层，而不是 $\partial L_{b,t}/\partial W$——读的时候要留意是哪一层。

求和的来源就是"同一份权重被所有 token 位置共用"：等价于设想每个位置各用一份副本 $W^{(b,t)}$、最后令所有副本相等，多元链式法则要求把这 $B\times S$ 条分支的梯度加起来。

对激活/输入的梯度不需要这样求和——但 Attention 是例外：一个位置的 $K,V$ 会被多个后续 query token 共同使用，梯度要跨 query 位置累加（具体取决于 attention mask，6.5.4 小节会具体展开确切条件）；此外 GELU、LayerNorm 这类逐 token 操作没有跨 token 依赖，但和 LLaMA-3 的 SwiGLU 不同，GPT-3 的 FFN 只有一条路径（$W_1\to\text{GELU}\to W_2$），不需要处理"分支相加"。

6.3 Unembedding（$U$）反向

GPT-3 沿用 GPT-2 架构，Embedding 和 Unembedding 权重是共享的（weight tying，$U=E^\top$）：这个结论的依据是 OpenAI 官方 GPT-2 实现直接用输入词嵌入矩阵 wte 的转置去算 logits，且 GPT-3 论文明确说明除了稀疏注意力这一处改动外沿用 GPT-2 架构——这是架构和代码层面的证据，是判断权重共享与否的主要依据。

参数量并不能独立证明这一点：把 bias、LayerNorm 的 $\gamma,\beta$、Position Embedding 都按本文采用的架构配置算进去估算（GPT-3 论文没有公开完整的实现细节，部分配置是按 GPT-2 架构推断的），共享权重时总参数量约 174.6B，不共享时约 175.2B——两者四舍五入到十亿这个精度都是"175B"，不能靠总参数量是否对上标称值来反推是否共享，本文第三节"合计约 1746 亿参数"这句话对两种情况都成立，只能当作一个大致的相容性检查，不是证据。所以下面的推导按 GPT-2/GPT-3 的真实架构，默认 $U=E^\top$。

前向：$\text{logits}_{b,t}=h_{b,t}\cdot E^\top,\quad E:[50257,\ 12288]$

本小节把 $(b,t)$ 下标全部写出，不用 6.2 的省略约定——下面两个梯度的性质根本不同，下标忽有忽无正是最容易读错的地方。记 $h_{b,t}$ 为第 $(b,t)$ 个 token 位置的 $h_\text{final}$（$b=1..B$ 标是哪条序列，$t=1..S$ 标该序列内的第几个 token 位置）：

$$\frac{\partial L}{\partial h_{b,t}} = \frac{\partial L}{\partial\text{logits}_{b,t}}\cdot E \quad [1,50257]\times[50257,12288]\to[1,12288]$$

$$\frac{\partial L_{b,t}}{\partial E}\Big|_\text{Unembedding 分支} = \left(h_{b,t}^\top\cdot\frac{\partial L}{\partial\text{logits}_{b,t}}\right)^{\!\top} \quad [50257,12288]$$

（因为 $\text{logits}_{b,t}=h_{b,t}E^\top$，对 $E$ 求导要多转置一次，形状上和"$U$ 独立存在"时的 $\partial L_{b,t}/\partial U:[12288,50257]$ 正好是转置关系。）

为什么上式分子是 $L$、下式却必须是 $L_{b,t}$——两者是不同类的对象：

  • 上式对激活 $h_{b,t}$ 求导。每个位置有自己的一份 $h$，而位置 $(b,t)$ 的 $h$ 只参与生成它自己那一份 loss，所以 $\dfrac{\partial L}{\partial h_{b,t}}=\dfrac{\partial L_{b,t}}{\partial h_{b,t}}$，两种写法数值相同，写 $L$ 不会有歧义。
  • 下式对权重 $E$ 求导。$E$ 在计算图里只有一份，被全部 $B\times S$ 个位置共用（还要再被下面的输入查表分支用一次），所以 $\dfrac{\partial L}{\partial E}$ 在数学上唯一地指求和之后那个量。单个位置的那一份不是 $L$ 对 $E$ 的导数，只是求和式里的一项，只能写成 $\dfrac{\partial L_{b,t}}{\partial E}$。两者形状都是 $[50257,12288]$，维度检查发现不了，只能靠记号区分。

Unembedding 分支真正的梯度，是把所有 token 位置的贡献加起来：

$$\frac{\partial L}{\partial E}\Big|_\text{Unembedding 分支}=\sum_{b=1}^{B}\sum_{t=1}^{S}\frac{\partial L_{b,t}}{\partial E}\Big|_\text{Unembedding 分支}=\sum_{b,t}\left(h_{b,t}^\top\frac{\partial L}{\partial\text{logits}_{b,t}}\right)^{\!\top}$$

关键点——分支相加：因为 $E$ 被用了两次（一次是这里的 Unembedding，一次是 6.6 节的输入查表），$E$ 最终收到的梯度是两份之和：

$$\frac{\partial L}{\partial E} = \frac{\partial L}{\partial E}\Big|_\text{Unembedding 分支} + \frac{\partial L}{\partial E}\Big|_\text{查表分支（6.6 节）}$$

如果某个实现选择不共享权重（$U$ 是独立参数），上面的推导会退化成"对 $U$ 单独求梯度、不需要和查表分支相加"这个更简单的情况——如上所述，这种情况下的总参数量（约 175.2B）同样能四舍五入成"175B"，参数量本身不能用来排除这种可能；本文按 GPT-2/GPT-3 论文和官方代码给出的真实架构，以共享权重为主线。

6.4 LayerNorm 反向

前向（复习）：

$$\mu=\frac1d\sum_i x_i,\quad \sigma^2=\frac1d\sum_i(x_i-\mu)^2,\quad \text{std}=\sqrt{\sigma^2+\epsilon}$$

$$\hat x_i=\frac{x_i-\mu}{\text{std}},\qquad y_i=\gamma_i\hat x_i+\beta_i$$

对 $\gamma,\beta$ 的梯度（单个 token 位置，逐元素）：

$$\frac{\partial L_{b,t}}{\partial\beta_i}=\frac{\partial L}{\partial y_i}, \qquad \frac{\partial L_{b,t}}{\partial\gamma_i}=\frac{\partial L}{\partial y_i}\cdot\hat x_i$$

真正用于更新的是对所有 $b,t$ 求和后的版本：

$$\frac{\partial L}{\partial\beta_i}=\sum_{b,t}\frac{\partial L}{\partial y_{b,t,i}}, \qquad \frac{\partial L}{\partial\gamma_i}=\sum_{b,t}\frac{\partial L}{\partial y_{b,t,i}}\cdot\hat x_{b,t,i}$$

对输入 $x$ 的梯度：这是 LayerNorm 比 RMSNorm 麻烦的地方——$\mu$ 和 $\sigma^2$ 都依赖全部 $x_i$，所以 $x_j$ 的变化会通过两条路径影响所有 $\hat x_i$。记 $g_i=\dfrac{\partial L}{\partial y_i}\cdot\gamma_i$（先把缩放吸收掉），结果是：

$$\frac{\partial L}{\partial x_j} = \frac{1}{\text{std}}\left[g_j - \frac1d\sum_i g_i - \frac{\hat x_j}{d}\sum_i g_i\hat x_i\right]$$

直觉：第一项 $g_j/\text{std}$ 是"当作没有归一化"的梯度；第二项 $-\frac1d\sum_i g_i$ 来自"减均值"这一步的耦合（所有维度共享同一个 $\mu$）；第三项 $-\frac{\hat x_j}{d}\sum_i g_i\hat x_i$ 来自"除以标准差"这一步的耦合，结构上和 RMSNorm 里的修正项同源。作为记忆方式：可以说"LayerNorm 反向比 RMSNorm 多出中间这一项'减均值'的耦合"——RMSNorm 去掉了减均值这一步，反向公式也就少了这一项。但严格来说这不是一个精确的算式恒等关系：LayerNorm 的 $\hat x_i=(x_i-\mu)/\sigma$ 是中心化变量，方差 $\sigma^2$ 也是围绕均值算的；RMSNorm 用的是未中心化的 $x_i/\text{RMS}(x)$，分母也不是围绕均值的标准差。也就是说第一项和第三项虽然形式相似，但两者依赖的标准化变量和统计量本身不同——不能理解成"从 LayerNorm 公式里直接删掉中间那一项就精确等于 RMSNorm 公式"，这里说的"多出一项"只是一个方便记忆的近似类比。

这个公式在 96 层模型里一共要用 $96\times2+1=193$ 次（每个 Block 2 次，加 1 次 Final LayerNorm）。

6.5 96 层 Block 反向：从最后一层往前，重复 96 次

GPT-3 用 Pre-LN（LayerNorm 在 Attention/FFN 之前），和 LLaMA-3 的 Pre-RMSNorm 结构完全一样，只是把 RMSNorm 换成 LayerNorm、把 SwiGLU 换成 GELU、没有 RoPE（位置信息是在输入端相加的，见 6.6 节）、没有 GQA（K/V head 数等于 Q head 数，不需要处理"一个 KV head 被多个 Q head 共享"）。

6.5.1 残差连接反向——两次合并写清楚

一个 Block 的输入是 $x$，第一次残差输出 $u=x+\text{Attention}(\text{LN}_1(x))$，第二次残差输出 $y=u+\text{FFN}(\text{LN}_2(u))$。记 $g_y=\partial L/\partial y$ 是从下一层传回来的梯度：

$$g_u = \underbrace{g_y}_{\text{直通残差}} + \underbrace{J_{\text{LN}_2}^\top J_{\text{FFN}}^\top g_y}_{\text{FFN 分支（5.2+5.3）}}$$

$$g_x = \underbrace{g_u}_{\text{直通残差}} + \underbrace{J_{\text{LN}_1}^\top J_{\text{Attention}}^\top g_u}_{\text{Attention 分支（5.4+5.5）}}$$

和 LLaMA-3 那份文档一样要提醒一句：残差保证"存在一条传递系数恒为 1 的直通路径"，但不保证最终梯度一定不衰减——直通梯度和分支梯度是相加关系，方向相反时仍可能相互抵消。

6.5.2 FFN（GELU）反向——比 SwiGLU 简单，只有一条路径

前向（$u$ 是残差流，$\hat u=\text{LN}_2(u)$）：

$$z=\hat u W_1,\qquad a=\text{GELU}(z),\qquad Y=aW_2$$

倒着算：

$$\frac{\partial L}{\partial a}=\frac{\partial L}{\partial Y}W_2^\top,\qquad \frac{\partial L}{\partial W_2}=a^\top\frac{\partial L}{\partial Y}$$

GELU 反向，需要 GELU 的导数。精确形式 $\text{GELU}(x)=x\cdot\Phi(x)$（$\Phi$ 是标准正态分布的累积分布函数，$\varphi$ 是对应的密度函数）：

$$\text{GELU}'(x)=\Phi(x)+x\cdot\varphi(x)$$

$$\frac{\partial L}{\partial z}=\frac{\partial L}{\partial a}\odot\text{GELU}'(z)$$

$$\frac{\partial L}{\partial \hat u}=\frac{\partial L}{\partial z}W_1^\top,\qquad \frac{\partial L}{\partial W_1}=\hat u^\top\frac{\partial L}{\partial z}$$

GPT-2 官方开源实现确认使用的是 tanh 近似版 GELU（$0.5x(1+\tanh(\sqrt{2/\pi}(x+0.044715x^3)))$）；GPT-3 的训练代码没有公开，论文只说"沿用 GPT-2 的架构"，这里假设 GPT-3 同样用 tanh 近似版是一个基于这句话的合理推断，不是已经证实的 GPT-3 官方实现细节。导数形式更复杂，但框架的自动微分会自动处理，不需要手推——这里给出精确版的导数是为了说明原理，两者数值上非常接近。

因为 FFN 只有一条路径（不像 SwiGLU 有 gate/up 两条支路），这里不需要"分支相加"这一步。

省略 bias 的说明：本文第三节明确指出 GPT-3 的投影实际是 $xW+b$，本章和第三节一样，为了简化只推导 $W$ 的梯度，没有单独写 $b$ 的梯度——这里补一句：bias 的反向极其简单，对任意一个线性层 $Z=XW+b$，都是把该层自己的上游梯度按所有 token 位置直接求和。这里有个记号陷阱要绕开：本文的 batch 下标也是 $b$，如果照写成 $\sum_{b,t}$，求和指标 $b$ 就会把被求导的 bias $b$ 遮蔽掉，同一个式子里一个字母指两样东西。改用下面 6.5.4 (f) 小节那个 reshape 后的一维 token 指标 $n=1,\dots,BS$（$\bar Z=\text{reshape}(Z,[BS,\cdot])$）就没有这个问题：$\dfrac{\partial L}{\partial b}=\sum_{n=1}^{BS}\dfrac{\partial L}{\partial \bar Z_{n}}$（这里的 $Z$ 泛指"这一层自己的输出"，不是特指上面 FFN 小节里的 $Y$——比如 $W_2$ 的 bias 对 $dY$ 求和，$W_1$ 的 bias 对 $dz$ 求和，$W_Q$ 的 bias 对 $dq_\text{proj}$ 求和，$W_K,W_V$ 同理对各自的投影输出求和，$W_O$ 的 bias 对 $d\text{attn\_out}$ 求和），对 $W_Q,W_K,W_V,W_O,W_1,W_2$ 每一个都适用同样的原理，只是代入各自层的输出梯度，不需要额外推导。本文后续所有小节都沿用这个简化，不再逐处重复声明。

6.5.3 第二个 LayerNorm 反向

套用 6.4 节公式，把 $\partial L/\partial\hat u$ 转成 $g_u^{(\text{FFN})}=\partial L/\partial u$——这是 6.5.1 里 $J_{\text{LN}_2}^\top J_{\text{FFN}}^\top g_y$ 这一整项。

$$g_u = g_y + g_u^{(\text{FFN})}$$

这个 $g_u$ 交给 Attention 分支（5.4～5.5）。

6.5.4 多头注意力反向——toy 数值演示

GPT-3 是标准 MHA（96 个 Q head，96 个 K/V head，一一对应），比 LLaMA-3 的 GQA 简单：不需要处理"一个 KV head 被多个 Q head 共享"的梯度累加，但跨 query token 的累加依然存在（对稠密因果注意力、或存在重叠连接的稀疏注意力都成立，见下面的范围说明）——这一层累加和用不用 GQA 无关。

范围说明：下面的推导都按稠密因果注意力（每个 query 能看到它之前的所有位置）展开。GPT-3 论文 2.1 节提到，真实的 96 层里是稠密注意力和局部带状稀疏注意力（locally banded sparse attention，类似 Sparse Transformer）交替出现的，不是每一层都是完整的稠密因果注意力。对于稀疏层，(b)(e) 里的求和范围 $\sum_{i\ge j}$ 要收紧成"只对允许连接的 query 集合 $\mathcal M$ 求和"：$dV_j=\sum_{i:(i,j)\in\mathcal M}\alpha_{ij}\,do_i$，$dK_j$ 同理。公式形式一样，只是求和范围更窄——下面的推导对稠密层完全适用，但不能不加说明地代表 GPT-3 全部 96 层。

toy 模型设置：3 个 token"黑猫睡"，单头，head_dim=2（为了手算干净，只用 1 个头；真实 GPT-3 是 96 个头各自独立重复这一套计算，最后拼接）。

  • $q_1=[1,0],\ q_2=[0,1],\ q_3=[1,1]$
  • $k_1=v_1=[1,0]$（黑），$k_2=v_2=[0,1]$（猫），$k_3=v_3=[1,1]$（睡）
  • 因果掩码：位置 1 只能看 1；位置 2 能看 1,2；位置 3 能看 1,2,3。

前向数值（$\sqrt{d_\text{head}}=\sqrt2\approx1.414$）：

query scores（除以 $\sqrt2$） softmax 输出 $=\sum\alpha_j v_j$

$q_2$ $[0,\ 0.707]$ $[0.330,\ 0.670]$ $[0.330,\ 0.670]$
$q_3$ $[0.707,\ 0.707,\ 1.414]$ $[0.248,\ 0.248,\ 0.503]$ $[0.752,\ 0.752]$

假设下游梯度 $\partial L/\partial o_i=[1,0]$，对 $i=1,2,3$ 都一样（简化假设，真实值来自 O 投影反向）。

(a) O 投影反向 + concat 拆分

$$\frac{\partial L}{\partial\text{attn\_concat}}=\frac{\partial L}{\partial\text{attn\_out}}W_O^\top,\qquad \frac{\partial L_b}{\partial W_O}=\text{attn\_concat}^\top\frac{\partial L}{\partial\text{attn\_out}}$$

concat 反向就是按 96 个 head 的边界 split，得到每个 head、每个 token 位置的 $\partial L/\partial o_i$。

(b) 对 V 的梯度——跨 query token 累加（无需 GQA，标准因果注意力就有）

$$\frac{\partial L}{\partial v_j}=\sum_{i\ge j}\alpha_{i,j}\cdot\frac{\partial L}{\partial o_i}$$

代入数字：

$$dV_1=\alpha_{11}do_1+\alpha_{21}do_2+\alpha_{31}do_3=(1+0.330+0.248)\,[1,0]=[1.578,\ 0]$$

$$dV_2=\alpha_{22}do_2+\alpha_{32}do_3=(0.670+0.248)\,[1,0]=[0.918,\ 0]$$

直觉：位置 1（"黑"）被 3 个 query 读取，梯度是 3 项之和；位置 3（"睡"）只被自己读取，梯度只有 1 项——越靠前的位置被越多后续 token 依赖，反向梯度的累加项也越多，这是稠密因果注意力的结构性质（存在重叠连接的稀疏掩码下也成立，见下面的范围说明），标准 MHA 和 GQA 都一样。

(c) 对 softmax 输入的梯度——一个容易被忽略的边界情况

标准公式：$\dfrac{\partial L}{\partial s_j}=\alpha_j\left(\dfrac{\partial L}{\partial\alpha_j}-\sum_l\alpha_l\dfrac{\partial L}{\partial\alpha_l}\right)$

query 1 的特殊情况：位置 1 因果掩码下只能看自己，softmax 退化成对单个元素做归一化，$\alpha_{11}\equiv1$ 恒成立、与 score 数值无关。代入公式：$ds_{11}=1\times(d\alpha_{11}-1\times d\alpha_{11})=0$，恒等于 0——也就是说 $q_1$ 对自己的 score 反向梯度永远是 0，$dQ_1=0$，$K_1$ 也不会从这一条路径收到梯度。这不是算错了，而是"只能看见一个元素的 softmax 的导数恒为 0"这个数学性质本身。

query 2（$d\alpha_{21}=do_2\cdot v_1=1,\ d\alpha_{22}=do_2\cdot v_2=0$）：

$$\textstyle\sum_l\alpha_ld\alpha_l=0.330\times1=0.330$$ $$ds_{21}=0.330(1-0.330)=0.221,\qquad ds_{22}=0.670(0-0.330)=-0.221$$

校验：$ds_{21}+ds_{22}\approx0$ ✓

query 3（$d\alpha_{31}=1,\ d\alpha_{32}=0,\ d\alpha_{33}=do_3\cdot v_3=1$）：

$$\textstyle\sum_l\alpha_ld\alpha_l=0.248+0.503=0.751$$ $$ds_{31}=0.248(1-0.751)=0.0616,\quad ds_{32}=0.248(0-0.751)=-0.1866,\quad ds_{33}=0.503(1-0.751)=0.1250$$

校验：$0.0616-0.1866+0.1250\approx0$ ✓

除以 $\sqrt2$ 换算成对 $(q_i\cdot k_j)$ 的梯度：$d(q_2k_1)=0.1564,\ d(q_2k_2)=-0.1564$；$d(q_3k_1)=0.0436,\ d(q_3k_2)=-0.1320,\ d(q_3k_3)=0.0884$。

(d) 对 Q 的梯度（对该 query 能看到的所有 key 求和，但不需要跨多个 query 累加）

这里需要先说明标题的准确含义，避免和下面的求和公式看起来矛盾：$dQ_i$ 确实需要对 query $i$ 能看到的所有 key 求和（下面 $dQ_3$ 就是三项 $k_1,k_2,k_3$ 的和），这一点和 $dK_j,dV_j$ 没有本质区别；"不需要累加"指的是另一件事——$Q_i$ 只在它自己这一个 query 位置被用来算 score，不会像 $K_j,V_j$ 那样被后面其他 query 位置重复读取，所以不需要像 (b)(e) 那样跨多个 query token 累加。简言之：$dQ_i$ 要对"key 维度"求和，但不需要对"query 维度"累加。

$$dQ_1=[0,0]\quad(\text{见 (c) 的边界情况})$$

$$dQ_2=d(q_2k_1)\,k_1+d(q_2k_2)\,k_2=0.1564[1,0]-0.1564[0,1]=[0.1564,\ -0.1564]$$

$$dQ_3=d(q_3k_1)\,k_1+d(q_3k_2)\,k_2+d(q_3k_3)\,k_3=[0.0436+0.0884,\ -0.1320+0.0884]=[0.1320,\ -0.0436]$$

(e) 对 K 的梯度——同样跨 query token 累加

$$dK_j=\sum_{i\ge j}d(q_ik_j)\,q_i$$

$$dK_1=\underbrace{0}_{\text{来自 }q_1}+d(q_2k_1)q_2+d(q_3k_1)q_3=0.1564[0,1]+0.0436[1,1]=[0.0436,\ 0.2000]$$

$$dK_2=d(q_2k_2)q_2+d(q_3k_2)q_3=-0.1564[0,1]-0.1320[1,1]=[-0.1320,\ -0.2884]$$

$$dK_3=d(q_3k_3)q_3=0.0884[1,1]=[0.0884,\ 0.0884]$$

这就是标准 MHA 里"跨 query token 累加"的完整体现：$K_1$ 收到来自 $q_1,q_2,q_3$ 三条路径的梯度（$q_1$ 那条恰好是 0），$K_3$ 只收到来自 $q_3$ 自己的梯度。GPT-3 没有 GQA，所以不存在"同一 KV 还要在多个 head 之间累加"这一层，但跨 token 这一层累加在稠密因果注意力下始终都在。

严格来说，"因果"本身只规定"不能看未来"，并不保证一个 $K_j,V_j$ 一定会被多个 query 读取——比如一个极端的稀疏掩码可以让每个 query 只看自己，这种情况下就没有跨 query 的累加。求和范围终究是由 attention mask $\mathcal M$ 决定的：稠密因果注意力下 $\mathcal M$ 让几乎每个 $K_j,V_j$ 都被多个 query 覆盖，累加自然发生；GPT-3 论文里的局部带状稀疏层通常也会在局部窗口内产生同样的重叠，所以本文的核心结论不受影响，只是不能把"只要是因果注意力就一定累加"说成是逻辑上必然的。

(f) Q/K/V 投影反向

和 LLaMA-3 那份文档不同，这里的 toy 例子从一开始就同时算了 $q_1,q_2,q_3$ 三个 query token（不是只固定一个），所以不需要区分"单 query token"和"完整序列"两种粒度——(d)(e) 算出的 $dQ,dK,dV$ 本来就都是按序列位置 $[S,d]$ 排列的。

但这里需要先说清楚一个容易混淆的形状层级问题：(d)(e) 算出来的 $dQ,dK,dV$（toy 里每个 $[S,2]$）只是单个 head 的梯度——toy 模型为了手算干净只用了 1 个头，真实 GPT-3 有 96 个头，各自独立重复 (a)~(e) 这一整套计算。要还原出完整的 $W_Q$ 梯度，需要先把 96 个头的 $dQ_h$ 沿最后一维拼接起来：

  • 单个玩具头：$dQ_h\in\mathbb R^{S\times2}$（本节数值例子算的就是这个）
  • GPT-3 单个真实头：$dQ_h\in\mathbb R^{S\times128}$（$\text{head\_dim}=128$）
  • 拼接全部 96 个头之后：$dQ=\text{concat}(dQ_1,\dots,dQ_{96})\in\mathbb R^{S\times12288}$
  • 完整投影权重：$W_Q\in\mathbb R^{12288\times12288}$（96 个头共用同一个大矩阵，各自对应其中一段列切片）
  • 单头对应的权重切片：$W_Q^{(h)}\in\mathbb R^{12288\times128}$，$dW_Q^{(h)}=X^\top dQ_h$

只有在拼接完全部 96 个头的 $dQ$之后，$X:[S,12288]$ 和 $dQ:[S,12288]$ 才对得上、可以直接写出完整 $W_Q$ 的梯度：

$$\frac{\partial L_b}{\partial W_Q}=X^\top\frac{\partial L}{\partial q_\text{proj}},\qquad \frac{\partial L_b}{\partial W_K}=X^\top\frac{\partial L}{\partial k_\text{proj}},\qquad \frac{\partial L_b}{\partial W_V}=X^\top\frac{\partial L}{\partial v_\text{proj}}\qquad (X:[S,12288],\ q_\text{proj}\text{ 已拼接 96 头}:[S,12288])$$

（本节 toy 例子只手算了 1 个头 2 维的数字，上面这组"拼接后"的形状公式是把 96 个头都补齐之后才成立的，不能直接把本节算出的 $[S,2]$ 数字代进 $X:[S,12288]$ 这个式子。）

注意分子写的是 $L_b$ 不是 $L$：$X:[S,12288]$ 覆盖的是一条序列的所有位置，所以 $X^\top(\cdot)$ 已经把 $\sum_t$ 做掉了，但还差对 $b$ 的求和——这正是记号约定里的中间那一层。但真实训练里 $X$ 是三维张量 $[B,S,12288]$，"$X^\top$"这个记号对三维张量没有标准含义，不能直接照抄上面的写法。严谨的做法是先把 batch 和序列维合并成一维：$\bar X=\text{reshape}(X,[BS,12288])$，$\overline{dQ}=\text{reshape}(dQ,[BS,12288])$，再套用二维公式 $dW_Q=\bar X^\top\overline{dQ}$；或者直接写成指标求和形式 $(dW_Q)_{mn}=\sum_{b,t}X_{b,t,m}\,(dQ)_{b,t,n}$，两种写法等价，都比直接写"$X^\top dQ$"更准确。这两种写法给出的都是完整的 $\dfrac{\partial L}{\partial W_Q}=\sum_{b,t}\dfrac{\partial L_{b,t}}{\partial W_Q}$——换句话说，记号约定里那个 $\sum_{b,t}$ 不是额外套上去的一层循环，它就是 $\bar X^\top\overline{dQ}$ 这次矩阵乘法的收缩维（长度 $BS$）。$W_K,W_V,W_O,W_1,W_2$ 以及 $E$ 的 Unembedding 分支全都同理。

（LLaMA-3 那份文档的 toy 例子只手算了一个固定 query 位置，所以需要专门区分 $q_\text{proj}$ 的 $[1,d]$ 和 $k_\text{proj},v_\text{proj}$ 的 $[S,d]$；这里的 toy 例子把 3 个 query 都算全了，就不存在这个不对称。）

(g) 汇总：$X$（第一个 LayerNorm 输出）的总梯度

$$\frac{\partial L}{\partial X}=\frac{\partial L}{\partial X}\Big|_Q+\frac{\partial L}{\partial X}\Big|_K+\frac{\partial L}{\partial X}\Big|_V$$

（按 token 位置对齐后相加，理由同 LLaMA-3 文档：每个位置的 $X$ 既是它自己 query 的输入，又是它作为 K/V 提供者的输入。）

6.5.5 第一个 LayerNorm 反向

套用 6.4 节公式，把 $\partial L/\partial X$ 转成 $g_x^{(\text{attn})}=\partial L/\partial x\big|_\text{Attention 分支}$，再按 6.5.1 的公式加回 $g_u$：

$$g_x=g_u+g_x^{(\text{attn})}$$

$g_x$ 就是要传给上一个 Block 的完整梯度。至此一层 Block 的反向传播完整走完，96 层重复这个流程。

6.6 Embedding + 位置编码反向

前向：$x_0=E[\text{token\_id},:]+P[\text{pos},:]$，$E$ 的这一行和 $P$ 的这一行是两个不同的变量，这是一个加法节点（不是 6.0 节的"分支相加"规则，两者的区别见 6.0 节末尾）：

$$\frac{\partial L}{\partial E[\text{token\_id},:]}\mathrel{+}=\frac{\partial L}{\partial x_0},\qquad \frac{\partial L}{\partial P[\text{pos},:]}\mathrel{+}=\frac{\partial L}{\partial x_0}$$

两个表各自拿到一份相同的梯度副本，不是各分一半。式子里的 $\mathrel{+}=$ 正是记号约定里 $\sum_{b,t}$ 的实现形态——同一个 token id（或同一个位置 id）在 batch 里可能出现在多个 $(b,t)$ 上，这些位置的梯度都要累加到同一行。写成求和式就是：

$$\frac{\partial L}{\partial E[v,:]}=\sum_{(b,t)\,:\,\text{token\_id}_{b,t}=v}\frac{\partial L}{\partial x_0^{(b,t)}},\qquad \frac{\partial L}{\partial P[t,:]}=\sum_{b=1}^{B}\frac{\partial L}{\partial x_0^{(b,t)}}$$

（注意两者的求和范围不同：$E$ 的某一行按 token id 相同的位置聚合，$P$ 的第 $t$ 行则是对所有序列在同一位置 $t$ 上求和——位置 $t$ 在每条序列里都恰好出现一次，所以 $P$ 的前 $S$ 行必定全部非零，不像 $E$ 那样行稀疏。）

Token Embedding $E$ 的完整梯度：由于 6.3 节说明的权重共享（$U=E^\top$），$E$ 实际上收到两份梯度之和，两份的"稀疏程度"完全不同：

$$\frac{\partial L}{\partial E} = \underbrace{\frac{\partial L}{\partial E}\Big|_\text{Unembedding 分支}}_{\text{完整的 }[V,d]\text{ 稠密矩阵，几乎每一行都非零}} + \underbrace{\text{scatter\_add}\left(\frac{\partial L}{\partial x_0}\ \text{到对应 token id 那一行}\right)}_{\text{查表分支，只有 batch 里出现过的 token id 对应的行非零}}$$

Unembedding 分支是 6.3 节那个矩阵乘法 $\sum_{b,t}\left(h_{b,t}^\top\,\partial L/\partial\text{logits}_{b,t}\right)^\top$ 直接算出来的完整矩阵，不是"按 token id 取一行"——那是查表分支才有的操作。两者相加后，$E$ 的总梯度通常不再是稀疏的（稠密的 Unembedding 分支已经覆盖了几乎所有行）。这里要注意：即使给查表分支单独设置 sparse=True，也不能让 $E$ 的总梯度变稀疏——Unembedding 分支产生的稠密梯度仍然要和查表分支的梯度合并，而且 PyTorch 里能处理稀疏梯度的优化器本来就不多（比如 SparseAdam），"一部分稀疏、一部分稠密"混合处理并不是默认就能做到的事。所以更准确的结论是：查表分支单独拿出来看，数据梯度在行维度上确实是稀疏的；但只要 $E$ 和 Unembedding 权重共享，$E$ 的完整梯度通常就得按稠密处理，"稀疏更新"这个说法在权重共享的场景下基本不成立。

Position Embedding $P$ 的梯度和 $E$ 的查表分支相比谁更"稀疏"，需要看具体数字，不能一概而论（这里比较的是 $E$ 的查表分支，不是上一段刚说过的、已经因为权重共享而变稠密的 $E$ 总梯度）：决定 $E$ 查表分支非零行数的不是"batch 大小"本身，而是这个 batch 里不同 token ID 的数量 $D$，非零行数最多是 $\min(D,|V|)$。GPT-3 达到完整 batch size 阶段后一个训练 batch 约 320 万 token（训练早期存在 batch 逐渐爬升的过程，并非从头到尾都是这个数字），是词表大小 50257 的 60 多倍——即便真实 token 分布是长尾的（常见词远比生僻词出现得多），这么大的 batch 也完全可能覆盖词表中的很大一部分甚至接近全部 token，具体覆盖率取决于真实的 token 频率分布，不能不看数据就断言"远小于词表"。$P$ 在固定 2048 长度的预训练 batch 下通常会覆盖全部 2048 个位置；但既然 $E$ 查表分支在这种大 batch 下覆盖率也可能很高，不能简单地说"$P$ 的覆盖率一定远高于 $E$ 的查表分支"——两者都可能接近满覆盖，只是分母不同（词表 50257 行 vs 位置表 2048 行）。这个"$P$ 通常覆盖率很高"的结论本身，也要限定在固定长度、或接近最大上下文长度的预训练 batch下：如果训练用了大量短序列、动态长度 batch，超出实际使用范围的那些位置行同样不会有梯度。

不管这两个查表分支各自谁的覆盖率更高，真正重要的结论没有变：$E$ 的总梯度早就因为 Unembedding 分支是稠密的而变成稠密梯度了——上面这一段只是对"两个查表操作各自产生的局部梯度"做数学上的严谨说明，不影响 $E$ 总梯度稀疏与否的结论。

6.7 用代码校验公式

LayerNorm 反向校验（下面这个 layernorm_backward_manual 只校验 6.4 节"单个 token"版本的公式——代码里 x=torch.randn(4) 是一维的，dgamma=dy*xhat、dbeta=dy.clone() 也是按单 token 逐元素写的；如果要直接用在真实的 [B,S,d] 训练张量上，$\gamma,\beta$ 的梯度还需要按 6.4 节说过的那样再对 $b,t$ 求和 $\big(d\gamma=\sum_{b,t}dy_{b,t}\odot\hat x_{b,t}\big)$，这个函数本身不会自动做这一步）：

import torch

def layernorm(x, gamma, beta, eps=1e-5):
    mu = x.mean(-1, keepdim=True)
    var = ((x - mu) ** 2).mean(-1, keepdim=True)
    xhat = (x - mu) / torch.sqrt(var + eps)
    return gamma * xhat + beta

# 直接实现 6.4 节的闭式公式，而不是只打印 autograd 的结果——这样才能真正校验公式本身
def layernorm_backward_manual(dy, x, gamma, eps=1e-5):
    d = x.shape[-1]
    mu = x.mean(-1, keepdim=True)
    var = ((x - mu) ** 2).mean(-1, keepdim=True)
    std = torch.sqrt(var + eps)
    xhat = (x - mu) / std
    g = dy * gamma
    dx = (g - g.mean(-1, keepdim=True) - xhat * (g * xhat).mean(-1, keepdim=True)) / std
    dgamma = dy * xhat
    dbeta = dy.clone()
    return dx, dgamma, dbeta

torch.manual_seed(0)
x = torch.randn(4, requires_grad=True)
gamma = torch.randn(4, requires_grad=True)   # 不能用全 1，见下方说明
beta = torch.randn(4, requires_grad=True)
w = torch.randn(4)                            # 随机下游权重，loss 不能用 y.sum()

y = layernorm(x, gamma, beta)
loss = (y * w).sum()
loss.backward()   # loss=(y*w).sum() 时 dL/dy 就是 w

dx_manual, dgamma_manual, dbeta_manual = layernorm_backward_manual(w, x.detach(), gamma.detach())

print("dx     autograd vs 手推公式一致:", torch.allclose(x.grad, dx_manual, atol=1e-5))
print("dgamma autograd vs 手推公式一致:", torch.allclose(gamma.grad, dgamma_manual, atol=1e-5))
print("dbeta  autograd vs 手推公式一致:", torch.allclose(beta.grad, dbeta_manual, atol=1e-5))

为什么不能用 gamma=[1,1,1,1] 配 y.sum()：$\hat x$ 是减去均值后的结果，任何输入下 $\sum_i\hat x_i$ 恒等于 0。如果 $\gamma$ 全为 1、$\beta$ 全为 0，y.sum() 就是 $\sum_i\hat x_i\equiv0$——这是一个恒为常数 0 的函数，所以这种设置下 $\partial L/\partial x$ 必然恒为 0，测试不出 $x$ 的梯度公式对不对；但 $\partial L/\partial\gamma_i=\hat x_i$、$\partial L/\partial\beta_i=1$ 这两个并不会自动变成 0（$\hat x$ 本身不是常数 0，只是求和为 0），所以旧版本的问题准确说是"测不出 $dL/dx$ 公式"，不是"所有梯度都测不出"。换成随机 $\gamma$、随机下游权重 $w$，并且直接实现闭式公式做 allclose 比较之后，三个梯度公式才都得到了真正校验，而不只是打印一个数字给人工比对。

跨 query token 累加校验（对应本文 (b)(e)）：用"联合 backward"和"逐个 query token 拆开求梯度再手动累加"两种算法对照，这是能真正验证求和关系本身、而不只是"看到一个数字"的做法：

import torch

seq_len, d = 3, 2
Q = torch.tensor([[1.,0.],[0.,1.],[1.,1.]], requires_grad=True)
K = torch.tensor([[1.,0.],[0.,1.],[1.,1.]], requires_grad=True)
V = K.clone().detach().requires_grad_(True)

def attn_out():
    scores = Q @ K.T / d ** 0.5
    mask = torch.triu(torch.ones(seq_len, seq_len), diagonal=1).bool()
    scores = scores.masked_fill(mask, float('-inf'))
    alpha = torch.softmax(scores, dim=-1)
    return alpha @ V   # [seq_len, d]，第 0 维是 query token

# 联合 backward
out = attn_out()
out[:, 0].sum().backward()   # 对应 dL/do_i = [1,0]
dK_joint = K.grad.clone()

# 逐 query token 拆开求梯度，再手动累加
K.grad = None
out2 = attn_out()
dK_per_t = torch.zeros_like(K)
for t in range(seq_len):
    dK_t, = torch.autograd.grad(out2[t, 0], K, retain_graph=True)
    dK_per_t += dK_t

print("联合 backward:", dK_joint)
print("逐 t 累加     :", dK_per_t)
print("是否一致:", torch.allclose(dK_joint, dK_per_t))   # 应为 True

# query 1 的边界情况：ds_11 恒为 0
print("dQ[0]（应为 [0,0]）:", torch.autograd.grad(out2[:, 0].sum(), Q, retain_graph=True)[0][0])

6.8 反向传播 FLOPs："×2"这句话背后的原理

本文第四节"乘上 Batch Size"提到"加上反向传播（约为前向的 2 倍）"。"反向约为前向 2 倍"这句话背后的逻辑，和"系数 6"的经验估算是同一套：

$$\text{训练 FLOPs}\approx 6NT = \underbrace{2NT}_{\text{前向}}+\underbrace{2NT}_{\text{反向：对权重的梯度}}+\underbrace{2NT}_{\text{反向：对输入的梯度}}$$

前向占 $2NT$（"1 份"），反向的两项加起来占 $4NT$（"2 份"）——这就是"×2"的来源。这里的 $N$ 是全模型参数量；如果只看某一个矩阵（比如 $W_Q$，参数量记为 $N_{W_Q}$，避免和全模型的 $N$ 混用），对应的三次矩阵乘法各自的 FLOPs 是：

项 计算 FLOPs
前向 $q_\text{proj}=XW_Q$ $2TN_{W_Q}$
反向·对权重 $\dfrac{\partial L}{\partial W_Q}=X^\top\dfrac{\partial L}{\partial q_\text{proj}}$ $2TN_{W_Q}$
反向·对输入 $\dfrac{\partial L}{\partial X}=\dfrac{\partial L}{\partial q_\text{proj}}W_Q^\top$ $2TN_{W_Q}$

表中的 $X$ 是整个 batch 展平后的 $[T,12288]$（$T$ 就是 token 总数 $B\times S$），所以 $\partial L/\partial W_Q=X^\top\partial L/\partial q_\text{proj}$ 这一式已经包含了记号约定里的 $\sum_{b,t}$，写的就是真正用于更新的权重梯度，不是 $\partial L_{b,t}/\partial W_Q$ 也不是 $\partial L_b/\partial W_Q$。

单看 $W_Q$ 这一个矩阵，三项合计是 $6TN_{W_Q}$——"×2"这个原理本身没问题。把这套逻辑对 $W_Q,W_K,W_V,W_O,W_1,W_2$ 等所有参数矩阵各自算一遍再加总，还需要单独加上共享的 Embedding/Unembedding 矩阵 $E$——$E$ 虽然在输入端只是按 token id 查表（几乎不产生 FLOPs），但在输出端的 Unembedding 步骤（$\text{logits}=h_\text{final}E^\top$）里，它确确实实参与了一次和 $W_Q$ 等同量级的大规模稠密矩阵乘法，同样要按 $6TN_E$ 计入。把 $W_Q,\dots,W_1,W_2$ 这些矩阵和 $E$ 加总，$\sum N_{W_\cdot}+N_E\approx N$（全模型参数量；是约等于不是恒等——$N$ 还包含 LayerNorm 的 $\gamma,\beta$、各线性层 bias、Position Embedding 这些不经过大矩阵乘法的参数，它们相对 175B 小到可以忽略；但 $E$ 不属于这一类可忽略项，只是它本身占全模型参数量的比例也不大——约 6.18 亿，占 175B 的 0.35%左右——量级上同样可以忽略，但道理和"不参与大矩阵乘法"不一样，是"参与了但占比小"），才回到开头那个全模型的 $6NT$：$N$ 在"单个矩阵的 $6TN_{W_Q}$"和"全模型的 $6NT$"这两处指的不是同一个数字，只是背后的原理相同，容易在核对数字时混淆，这里特意拆开说明一下。

直接用参数量算前向 FLOPs（$2NT$，$N=175\times10^9$，$T=3.2\times10^6$ token/step——这里需要说明：$3.2\text{M}$ token/step 是 GPT-3 论文里完整 batch size 阶段的口径；论文提到训练早期会把 batch size 从较小规模逐渐爬升到完整值，所以并非所有训练 step 都固定是这个 token 数，这里用的是达到完整 batch 之后的稳态值，不影响下面 $6NT$ 这套框架本身）：

$$2NT = 2\times175\times10^9\times3.2\times10^6\approx1.12\times10^{18}$$

更新：本文早期版本在这里核对时发现，本文第四节当时的"一层 Block 共 6 次大矩阵乘法"算法把 $W_1,W_2$（形状 $[12288,49152]$ 和 $[49152,12288]$，比 $W_Q$ 大 4 倍）当成和 $W_Q,W_K,W_V,W_O$ 同样大小来计算，导致前向 FLOPs 少算了约 2 倍；一层的等价规模应该是：

$$\underbrace{4}_{W_Q,W_K,W_V,W_O（各 1 倍）} + \underbrace{2\times4}_{W_1,W_2（各 4 倍）} = 12 \text{ 个 } W_Q\text{ 等价规模，而不是 6 个}$$

这一处已经在本文第四节中修正（目前第四节给出的前向 FLOPs 约 $1.14\times10^{18}$、完整训练 step 约 $3.4\times10^{18}$，和这里 $2NT\approx1.12\times10^{18}$、$6NT\approx3.36\times10^{18}$ 的结果一致），本文这里保留这段推导过程，是为了说清楚"×2"背后 $6NT=2NT+2NT+2NT$ 这套逻辑是怎么来的，不再是"待核对的分歧"。

"$6NT\approx2NT_\text{前向}+4NT_\text{反向}$"这个近似框架本身是成立的；它同样忽略了 attention 的 $S^2$ 项、softmax/LayerNorm/GELU 等非矩阵乘法开销、Embedding 查表、优化器更新和梯度检查点重算，不是精确恒等式。

6.9 一次完整训练 step 的伪代码

这里需要说明适用范围：下面是一段现代自回归语言模型训练的通用伪代码，用来展示"loss.backward() 背后对应哪些反向步骤"，不是 GPT-3 论文披露的原始训练实现细节。GPT-3 论文描述的做法是把多篇文档打包（packing）成完整的 2048-token 序列，而不是以 padding + ignore_index 为核心机制来处理变长样本；ignore_index=pad_id 这一行是通用做法的示意，不代表 GPT-3 实际训练就是这样处理边界的。

for batch in dataloader:
    tokens, targets = batch                      # tokens: [B, S]

    logits = model(tokens)                        # [B, S, 50257]
    # 注意：PyTorch 的 cross_entropy 把第 1 维当类别维，不能直接传 [B,S,V] 配 [B,S]，必须先展平：
    loss = cross_entropy(logits.reshape(-1, logits.size(-1)), targets.reshape(-1), ignore_index=pad_id)

    loss.backward()
    # 从后往前：dL/dlogits → Unembedding 反向 → Final LayerNorm 反向
    #   → 第96层 Block 反向 → ... → 第1层 Block 反向 → Embedding+PosEmb 反向

    optimizer.step()
    optimizer.zero_grad()

6.10 训练显存 vs 推理缓存

本文前五节（前向部分）没有涉及 KV Cache，这里按 GPT-3 的参数自己估算一下（标准 MHA，96 head、每头 128 维、96 层，FP16）：

$$\text{每 token 每层：}\ 2\times96\times128\times2\text{ 字节}=49{,}152\text{ 字节}=48\text{ KiB}\ (1\text{KiB}=1024\text{ 字节})$$

$$96\text{ 层：}\ 96\times48\text{ KiB}=4{,}608\text{ KiB}=4.5\text{ MiB/token}$$

如果上下文长度按 2048 算（GPT-3 常见上下文长度）：$2048\times4.5\text{ MiB}=9{,}216\text{ MiB}=\textbf{9 GiB}$（二进制口径，恰好整除）；换算成十进制的 GB（$1\text{GB}=10^9$ 字节）约为 9.66 GB（batch=1，FP16）。GPT-3 没有 GQA，K/V head 数等于 Q head 数，所以这个数字比 LLaMA-3 同规模模型的 KV Cache 大得多；另外这是假设全部 96 层都用完整稠密因果注意力算出的上界——如果按 GPT-3 论文实际的稠密/稀疏交替架构，稀疏层的 KV Cache 未必需要保留全部历史位置，实际占用可能更低。

推理和训练要保存的是两套不同的内存结构：

  • 推理：参数 + 当前步临时激活 + 跨生成步骤保留的 KV Cache（上面估算的量）。
  • 训练：参数 + 梯度 + 优化器状态 + 为反向传播保存或重算的激活（LayerNorm 的 $\hat x$、softmax 的 $\alpha$、GELU 的中间值等）。混合精度 + AdamW 大约每参数 12～18 字节（取决于是否保留 FP32 master weight、梯度精度等具体配置），是纯 FP16/BF16 权重的 6～9 倍，不含激活；具体倍数没有统一标准，取决于训练栈的实现。

6.11 小结

GPT-3 的反向传播 = 交叉熵梯度 $p-y$ 从 logits 出发，经过 Unembedding、Final LayerNorm、96 层 Block（每层：残差直通 + GELU FFN 反向（单路径，无需分支相加）+ LayerNorm 反向（作为记忆类比可以说"比 RMSNorm 多一项'减均值'耦合"，但严格说两者用的标准化统计量本身不同，不是从 LayerNorm 公式里删掉一项就精确等于 RMSNorm，6.4 节有展开）+ 多头注意力反向（O 投影 → concat 拆分 → 对 V 加权求和反向【跨 query token 累加】→ softmax 反向【第一个 token 的边界情况：单元素 softmax 导数恒为 0】→ 对 Q、K 的梯度【K 同样跨 query token 累加，无需 GQA 也一样】→ Q/K/V 投影反向）+ 残差直通 + LayerNorm 反向），最终把梯度分别加回 Token Embedding 和 Position Embedding 两张表。核心仍是链式法则 + "分支相加"这条规则；GPT-3 没有 GQA、RoPE、SwiGLU 这些 LLaMA-3 特有的复杂度，"跨 query token 的梯度累加"这一条在稠密因果注意力、以及 GPT-3 实际使用的局部带状稀疏层里都会发生，和用不用 GQA 无关；但严格来说这不是"因果"这个词本身逻辑上保证的，而是取决于 attention mask 具体让哪些位置重叠（6.5.4 小节的范围说明有展开）。本文第四节里"反向约为前向 2 倍"这句话，来源正是 $6NT\approx2NT_\text{前向}+4NT_\text{反向}$ 这套近似估算。

七、总结

GPT-3 拥有约 1750 亿参数（忽略若干小项、并假设 Embedding/Unembedding 权重共享后的近似核对），按完整 3.2M-token batch 折算，一个"完整 batch 等效 step"约需 $3.4 \times 10^{18}$ 次浮点运算（主导项近似，含线性层与注意力的 $S^2$ 项，前向+反向；训练早期 batch 从 32K 逐步爬升到 3.2M 时，实际 step 的 FLOPs 会明显更小），仅一份 $[T,d]$ 形状的激活张量（$T$ 取完整 global batch 的 320 万 token，是聚合/等价规模，不是单张 GPU 上实际同时保存的一整块张量）就需要 78.6GB 显存（一层完整的激活远不止这一份）——这是为什么它需要大规模 GPU 集群、数周到一个多月才能训练完成的根本原因（本文按 1024 张 V100 推算约 29 天，Patterson 论文按约 10,000 张 V100 估算约 15 天，两者都是估算配置，不是 OpenAI 公开的确切训练规模）。FLOPs 和电能之间的桥梁是硬件能效（FLOP/s per Watt）。按 V100 的官方峰值 125 TFLOP/s、300W 芯片 TDP 计算，得到一个理想化设备侧估算约 213 MWh（这不是严格数学下限——峰值算力和 TDP 都是规格表数字，不保证在同一工作点同时成立）；Patterson 等人论文给出的估算值是 1,287 MWh，约为这个估算的 6 倍——这个差距可以拆解成三项来解释：达成/峰值吞吐比（24.6 vs 125 TFLOP/s，约 5.08 倍，背后是显存带宽、通信、重算等因素共同造成、无法精确拆分占比）、功率统计边界不同（300W 芯片 TDP vs 论文 330W 系统平均功率，约 1.10 倍）、以及 PUE（约 1.10 倍）——三者相乘约 6.15 倍，和观察到的"约 6 倍"吻合，但其中 24.6 TFLOP/s（第一项的达成吞吐）和 330W（第二项的系统功率）都是 Patterson 论文针对同一个 GPT-3 训练配置给出的数字，不是可以脱离具体工作负载、各自独立存在的常数。1,287 MWh 本身是论文反推出的估算值，不是电表实测读数。推理虽然单次用电少，但只有在大规模、长期部署时，累计推理能耗才可能超过一次训练用电量，不是所有模型都必然如此。
